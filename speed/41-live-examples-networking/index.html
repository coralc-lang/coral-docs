Live Examples: Networking

Talking to Other Programs Over a Socket

Appendix G lists the networking surface: tcpListen, tcpAccept, tcpConnect, tcpSend, tcpRecv, tcpClose, the UDP equivalents, and sockaddr_in. std::io::net wraps the operating-system calls every socket program uses; it hides nothing else.

The API is IPv4 only, with no DNS, so connect to a dotted-quad literal. There is no TLS or HTTP library, and no timeouts: tcpConnect, tcpRecv, and tcpSend block until done or failed. There is no non-blocking mode, select, or poll, and no 'read whatever is available' primitive.

Two properties shape every example. tcpSend(sock, buf, len) sends exactly len bytes, looping until all are accepted or an error occurs; a short count means the peer closed. tcpRecv(sock, buf, len) reads until buf is full or the peer closes, so Ok(n) with n < len means end of stream, never 'nothing right now.' TCP has no message boundaries, so you impose framing (41.3); UDP keeps them but is unordered and unretried.

Imports are std::io::net for sockets and functions, IoError from std::io::fs, buffers from std::mman, and text from String; thread examples add std::concurrent::thread and std::concurrent::mutex.

A TCP Echo Server

The problem

Two programs must exchange bytes reliably, in order, over a connection either side can end. A TCP echo server is the smallest case: listen, accept one client, and echo every byte.

The idea

tcpListen(port) creates a listening socket on every IPv4 interface; ports below 1024 need privileges. tcpAccept(listener) blocks until a client connects and returns a socket for that conversation. tcpRecv reads, tcpSend writes, tcpClose closes. Because tcpRecv is read-exactly, a prompt reply reads one byte and echoes it.

The implementation.

// Socket calls, the handle type, and the shared error variant.
import(lib) std::io::net {
    tcpListen, tcpAccept, tcpRecv, tcpSend, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };

// Echo one connection to completion, one byte at a time.
void echoLoop(TcpSocket client)
{
    u8 b = 0;
    // tcpRecv is read-exactly, so ask for a single byte: that is the
    // only request that returns as soon as one byte has arrived.
    while (true)
    {
        Result<isize, IoError> r = tcpRecv(client, &b, 1);
        if (r.isErr()) break;                  // the connection broke
        if (r.unwrap() == 0) break;            // the peer closed cleanly

        // Send the byte straight back; a send failure also ends the loop.
        Result<isize, IoError> w = tcpSend(client, &b, 1);
        if (w.isErr()) break;
    }
}

i32 main()
{
    // Create the listening socket on port 8080 for every IPv4 interface.
    Result<TcpSocket, IoError> server = tcpListen((u16)8080);
    if (server.isErr()) { println("could not listen on port 8080"); return 1; }

    TcpSocket listener = server.unwrap();
    println("echo server listening on port 8080");

    // Accept connections forever; each one is a separate conversation.
    while (true)
    {
        Result<TcpSocket, IoError> conn = tcpAccept(listener);
        if (conn.isErr()) break;

        // Service this client, then close only its socket, not the listener.
        TcpSocket client = conn.unwrap();
        echoLoop(client);
        tcpClose(client);
    }

    tcpClose(listener);
    return 0;
}

echoLoop reads a byte, sends it back, and repeats until a receive fails or returns zero, meaning the peer is done. Closing the connection leaves the listener free.

Cost and notes

Each tcpRecv and tcpSend is a system call, so a byte-at-a-time echo costs two per byte, the price of promptness without a 'read available' call. tcpListen sets SO_REUSEADDR; tcpSend loops internally, so partial writes need no handling.

Edge cases and variations

tcpRecv returns Ok(0) at end of stream, and Ok(n) below the request means the same, not 'try later'; an Err means a reset or bad descriptor. The accept loop exits successfully on failure even though the listener died. A silent client holds the single-threaded server in echoLoop forever; 41.7 fixes that with threads. Variation: echo lines by reading to a newline (41.3).

A TCP Client That Connects and Sends a Line

The problem

Reach out to a server, send a line, and print the reply. This is the other half of every client-server pair, and it must cope with an absent server.

The idea

tcpConnect(ip, port) takes a dotted-quad string and a port, opens a socket, and performs the handshake. Failure is ordinary: nothing listening, wrong address, or no route. This client sends a line to 41.1's echo server and reads the reply a byte at a time, for the same read-exactly reason.

The implementation.

import(lib) std::io::net {
    tcpConnect, tcpRecv, tcpSend, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::text::string { String };

i32 main()
{
    // Connect to the echo server of 40.1 on the loopback address.
    Result<TcpSocket, IoError> opened = tcpConnect("127.0.0.1", (u16)8080);
    if (opened.isErr())
    {
        println("connect failed, is the echo server from 40.1 running?");
        return 1;
    }
    TcpSocket sock = opened.unwrap();

    // The request is a str; ptr and len give tcpSend its bytes and count.
    str line = "hello from the client\n";
    Result<isize, IoError> sent = tcpSend(sock, line.ptr, line.len);
    if (sent.isErr()) { tcpClose(sock); return 1; }

    // The reply length is unknown, so grow an owned String as bytes land.
    String reply = String::new();
    u8 b = 0;
    // Read one byte at a time until newline or close, capping the result.
    while (reply.len < 256)
    {
        Result<isize, IoError> r = tcpRecv(sock, &b, 1);
        if (r.isErr()) break;
        if (r.unwrap() == 0) break;
        // Accumulate the byte, then stop once the terminator is seen.
        reply.pushByte(b);
        if (b == (u8)'\n') break;              // the line is complete
    }

    // asView() prints exactly the bytes received, NUL and all.
    println("client received: {}", reply.asView());
    tcpClose(sock);
    return 0;
}

The request is a str, so line.ptr and line.len give tcpSend the bytes and count directly. The reply accumulates in an owned String because its length is unknown; reply.asView() carries the length, safe even if the server echoed a NUL.

Cost and notes

tcpConnect can take real wall-clock time, since the handshake involves both machines and every router between them. The send loops inside the library; the receive is one system call per byte, because the API will not return a partial buffer.

Edge cases and variations

Connections are refused immediately when the host is reachable and nothing listens; they hang for the kernel's default timeout, possibly minutes, when packets are dropped. This client hard-codes the address and port; a real one reads them from a Uri. 127.0.0.1 is loopback, so it only talks to a local server. Variation: send several lines in one tcpSend; framing is yours.

Reading Until a Newline or Close

The problem

TCP gives a byte stream, but protocols are built from units: a line, a header, a message. Reading one unit requires more than the obvious call.

The idea

Because tcpRecv(sock, buf, n) blocks until it has n bytes or the stream ends, tcpRecv(sock, buf, 256) waits for 256 bytes even when the line is five and the sender waits for a reply. The correct primitive reads one byte at a time and stops at the delimiter: slow but correct, and the only framing tool without a timeout or non-blocking mode. The helper returns bytes read, treating newline and clean close as the end.

The implementation.

import(lib) std::io::net {
    tcpListen, tcpAccept, tcpConnect, tcpSend, tcpRecv, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::text::string { String };

// Reads bytes into `out` until '\n' arrives, the peer closes, or `max`
// bytes have been read. Returns the number of bytes appended.
Result<isize, IoError> readLine(TcpSocket sock, String* out, usize max)
{
    // Reset the accumulator so callers can reuse the same String.
    out.clear();
    while (out.len < max)
    {
        u8 b = 0;
        // One-byte reads are the only framing tool this blocking API offers.
        Result<isize, IoError> r = tcpRecv(sock, &b, 1);
        if (r.isErr()) return r;
        if (r.unwrap() == 0) break;            // peer closed: end of unit

        // Keep the delimiter in the result; the caller may strip it.
        out.pushByte(b);
        if (b == (u8)'\n') break;              // delimiter reached
    }
    return Result<isize, IoError>::Ok { .value = (isize)out.len };
}

i32 main()
{
    // Listen first; the connection below queues in the backlog, needing no thread.
    Result<TcpSocket, IoError> server = tcpListen((u16)8090);
    if (server.isErr()) return 1;
    TcpSocket listener = server.unwrap();

    // A connection made to our own listener is queued by the kernel as
    // soon as listen() has run, so accept() below returns at once and the
    // whole exchange can run in one thread.
    Result<TcpSocket, IoError> opened = tcpConnect("127.0.0.1", (u16)8090);
    if (opened.isErr()) { tcpClose(listener); return 1; }
    TcpSocket client = opened.unwrap();

    Result<TcpSocket, IoError> accepted = tcpAccept(listener);
    if (accepted.isErr()) { tcpClose(client); tcpClose(listener); return 1; }
    TcpSocket peer = accepted.unwrap();

    // Two sends become one stream; readLine slices it back into units.
    str first = "first line\n";
    str second = "second line\n";
    tcpSend(client, first.ptr, first.len);
    tcpSend(client, second.ptr, second.len);

    // One accumulator reused for both lines; readLine clears it each call.
    String line = String::new();
    readLine(peer, &line, 256);
    println("server got: {}", line.asView());
    readLine(peer, &line, 256);
    println("server got: {}", line.asView());

    // Close all three descriptors: the accepted peer, the client, and the listener.
    tcpClose(peer);
    tcpClose(client);
    tcpClose(listener);
    return 0;
}

The program is its own client and server: listen enters accept mode immediately, so tcpConnect completes the handshake and waits in the backlog until tcpAccept collects it; no second thread is needed. Two sends land as one stream, and readLine slices it back at each \n.

Cost and notes

readLine makes one receive system call per byte and copies each byte twice, once into the local and once into the String. That suits a small maximum unit, not bulk transfer. The max bound stops a peer from forcing unlimited allocation; a line that never ends is a denial-of-service attempt, so a real server caps the unit and rejects the connection.

Edge cases and variations

An empty line is a single '\n', returned with length one. A line longer than max is truncated and the rest stays in the stream, desynchronising the parser, so treat reaching max without a delimiter as an error. The delimiter remains in the result and must be stripped before comparing fields. Ok does not mean a delimiter was seen; a partial line at close is also Ok. Variation: parameterise the delimiter, or read until \r\n, as HTTP does.

A Minimal HTTP/1.0 GET Client

The problem

Fetch a web page with no HTTP library, understanding every byte. It is the smallest thing a browser does, and it shows HTTP is a text protocol on a TCP socket.

The idea

An HTTP/1.0 request is a request line, headers, and a blank line, separated by CRLF. With Connection: close, the server sends the response and closes; since tcpRecv reports close as Ok(0), reading until close needs no Content-Length parsing. The response prints as it arrives. With no DNS, the target must be an IPv4 literal, so the example points at 41.5.

The implementation.

import(lib) std::io::net {
    tcpConnect, tcpSend, tcpRecv, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::text::string { String };
import(lib) std::mman { alloc, dealloc };

i32 main()
{
    // Speak HTTP/1.0 by hand over one plain TCP connection.
    Result<TcpSocket, IoError> opened = tcpConnect("127.0.0.1", (u16)8080);
    if (opened.isErr()) { println("connect failed"); return 1; }
    TcpSocket sock = opened.unwrap();

    // Assemble the exact request bytes; HTTP requires CRLF line endings.
    String request = String::from("GET / HTTP/1.0\r\n");
    request.appendView("Host: 127.0.0.1\r\n");
    request.appendView("Connection: close\r\n");
    request.appendView("\r\n");

    // Send the whole request head in one call; short writes are handled.
    str head = request.asView();
    Result<isize, IoError> sent = tcpSend(sock, head.ptr, head.len);
    if (sent.isErr()) { tcpClose(sock); return 1; }

    // A single reusable buffer: the response streams out, not stored.
    u8* buf = alloc<u8>(4096);
    if (buf == null) { tcpClose(sock); return 1; }

    // Read until tcpRecv returns zero, the server's close after the body.
    while (true)
    {
        Result<isize, IoError> r = tcpRecv(sock, buf, 4096);
        if (r.isErr()) { println("recv failed"); break; }
        isize n = r.unwrap();
        if (n == 0) break;                     // server closed: response done
        // Emit exactly the bytes just received, whatever they encode.
        print("{}", str::fromParts(buf, (usize)n));
    }

    // Release the buffer and the socket; the program owns both.
    dealloc<u8>(buf);
    tcpClose(sock);
    return 0;
}

The request is assembled in a String so the exact CRLF bytes are controlled; \r\n, not \n, is the HTTP line ending. str::fromParts(buf, n) wraps the received bytes in a length-carrying view, so print writes exactly n, including non-text bytes. The loop ends on tcpRecv returning zero.

Cost and notes

The loop asks for 4096 bytes and gets all 4096 until the final partial buffer, because that is what tcpRecv promises; a smaller response arrives in one partial call then a zero. The response streams out, so memory stays at one buffer. Building the request allocates once.

Edge cases and variations

No DNS: tcpConnect accepts only dotted quads, so example.com needs a resolver the library does not provide. No TLS, so https is out of reach and the port is plain 80. No redirects or status-line parsing; this prints the response and leaves interpretation to the reader. A lying Content-Length or a server that never closes leaves the loop waiting. Variation: scan the first \r\n for the status code, or stop at the blank line to show only the body.

A Tiny HTTP Server That Returns a Fixed Page

The problem

Answer an HTTP GET with a fixed HTML page, speaking the protocol by hand so you see exactly what a server sends. This is the counterpart to 41.4.

The idea

Read request headers until the blank line that ends them; method and path do not matter because every request gets the same page. Build a response with a status line, Content-Length, and the body, send it, and close. HTTP/1.0 closes after each response, so a single-threaded accept loop suffices at low traffic.

The implementation.

import(lib) std::io::net {
    tcpListen, tcpAccept, tcpSend, tcpRecv, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::text::string { String };
import(lib) std::fmt::fmt { formatInt };
import(lib) std::mman { alloc, dealloc };

// Read request headers until CRLFCRLF, or the peer closes, or the cap.
void readHeaders(TcpSocket client, u8* hdr, usize cap)
{
    // Track how many head bytes have been collected so far.
    usize used = 0;
    while (used < cap)
    {
        u8 b = 0;
        // One byte at a time so the CRLFCRLF boundary cannot be overshot.
        Result<isize, IoError> r = tcpRecv(client, &b, 1);
        if (r.isErr()) break;
        if (r.unwrap() == 0) break;
        // Store the byte, then test the last four for the blank line.
        hdr[used] = b;
        used += 1;
        if (used >= 4 &&
            hdr[used - 4] == (u8)'\r' && hdr[used - 3] == (u8)'\n' &&
            hdr[used - 2] == (u8)'\r' && hdr[used - 1] == (u8)'\n')
            break;
    }
}

// Answer one request with a fixed page and close the connection.
void serveOnce(TcpSocket client)
{
    // The page never changes; the request path is ignored.
    str body = "<!doctype html><title>hi</title><p>Hello from Coral.</p>\n";
    // Read and discard the request head; only its ending blank line matters.
    u8* hdr = alloc<u8>(4096);
    if (hdr == null) { tcpClose(client); return; }
    readHeaders(client, hdr, 4096);
    dealloc<u8>(hdr);

    // Derive Content-Length from the body so the two can never disagree.
    String response = String::from("HTTP/1.0 200 OK\r\n");
    response.appendView("Content-Type: text/html; charset=utf-8\r\n");
    response.appendView("Content-Length: ");
    String length = formatInt((i64)body.len, 10u, false);
    response.appendView(length.asView());
    response.appendView("\r\nConnection: close\r\n\r\n");
    response.appendView(body);

    // One send for status line, headers, and body; the library loops.
    str out = response.asView();
    tcpSend(client, out.ptr, out.len);
    tcpClose(client);
}

i32 main()
{
    Result<TcpSocket, IoError> server = tcpListen((u16)8080);
    if (server.isErr()) { println("could not listen on port 8080"); return 1; }
    TcpSocket listener = server.unwrap();
    println("serving a fixed page on http://127.0.0.1:8080/");

    // HTTP/1.0 sends one request per connection, so a serial loop suffices.
    while (true)
    {
        Result<TcpSocket, IoError> conn = tcpAccept(listener);
        if (conn.isErr()) break;
        serveOnce(conn.unwrap());
    }
    tcpClose(listener);
    return 0;
}

The header reader is a rolling four-byte test for the \r\n\r\n that ends the request head. Content-Length is computed from the body with formatInt, so the number always matches the bytes that follow, the most common way a hand-written server breaks. The response is one tcpSend.

Cost and notes

This server handles one client at a time and blocks in readHeaders; a slow or silent client stalls everyone behind it. A request body is not read, fine for GET and wrong for POST. formatInt allocates a small String for the length.

Edge cases and variations

A client that connects and sends nothing holds the server in readHeaders until it times out or hits the cap, and there is no API timeout. A request over 4096 bytes has its head truncated and should be rejected. Only one request per connection is served, matching HTTP/1.0's default close; keep-alive needs a loop and Content-Length parsing. Variation: route on the request line and choose a body per path. The listener binds all interfaces, so this is reachable from the network.

A UDP Send and Receive Pair

The problem

Datagram sockets have no connection and no handshake; each message is independent. Two UDP sockets exchanging one message show the whole idea.

The idea

udpSocket() creates an unbound datagram socket, and udpBind(&sock, port) gives it a local port. udpSendTo(&sock, buf, len, ip, port) sends one datagram; udpRecvFrom(&sock, buf, len) receives one. Unlike TCP, a datagram is a unit: the receiver gets exactly the bytes sent in one call, and a short read is normal. Order and delivery are not guaranteed.

The implementation.

import(lib) std::io::net {
    udpSocket, udpBind, udpSendTo, udpRecvFrom, udpClose, UdpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::mman { alloc, dealloc };

i32 main()
{
    // Receiver: a datagram socket bound to a known local port.
    Result<UdpSocket, IoError> receiverRes = udpSocket();
    if (receiverRes.isErr()) return 1;
    UdpSocket receiver = receiverRes.unwrap();
    if (udpBind(&receiver, (u16)9999).isErr())
    {
        udpClose(&receiver);
        return 1;
    }

    // Sender: unbound; the OS assigns a source port on the first send.
    Result<UdpSocket, IoError> senderRes = udpSocket();
    if (senderRes.isErr()) { udpClose(&receiver); return 1; }
    UdpSocket sender = senderRes.unwrap();

    // A datagram keeps its boundary; the bytes travel as one unit.
    str message = "ping over udp\n";
    // A UDP send reports only local errors; loss on the wire is silent.
    Result<isize, IoError> sent =
        udpSendTo(&sender, message.ptr, message.len, "127.0.0.1", (u16)9999);
    if (sent.isErr())
    {
        println("send failed");
        udpClose(&sender);
        udpClose(&receiver);
        return 1;
    }

    // A datagram larger than this buffer is truncated with no error.
    u8* buf = alloc<u8>(512);
    if (buf == null)
    {
        udpClose(&sender);
        udpClose(&receiver);
        return 1;
    }

    // Exactly one datagram is received per call, or the call blocks.
    Result<isize, IoError> got = udpRecvFrom(&receiver, buf, 512);
    if (got.isErr())
    {
        println("receive failed");
    }
    else
    {
        isize n = got.unwrap();
        println("received {} bytes: {}", n, str::fromParts(buf, (usize)n));
    }

    // Release the buffer and both socket handles.
    dealloc<u8>(buf);
    udpClose(&sender);
    udpClose(&receiver);
    return 0;
}

The sender is never bound; the operating system assigns an ephemeral source port on first send. The datagram travels over loopback into the receiver's queue, where udpRecvFrom collects exactly one message. Both sockets are in one process, so the kernel holds the datagram until asked.

Cost and notes

udpSendTo and udpRecvFrom are each one system call per datagram. There is no retry or buffering: if the network drops the datagram, no error is reported. That is UDP's performance advantage and reliability disadvantage in one sentence.

Edge cases and variations

udpRecvFrom passes null for the source address, so a server built on it cannot reply, only observe the payload; that is a genuine gap. Datagrams larger than the receive buffer are truncated by the kernel, the excess silently lost. The example relies on both sockets being in one process; across machines, a dropped packet makes udpRecvFrom block forever. A zero-length datagram is legal and delivered. Variation: echo the payload to the sender's known address, which works only because it is known in advance.

Handling Several Clients with Threads

The problem

The echo server of 41.1 serves one client at a time; a second waits. You want each connection handled independently.

The idea

Accept a connection, hand its socket to a new thread, and go back to accepting. The worker needs only the socket, so it travels in a small allocated struct the worker owns and frees when the conversation ends. This is thread per connection, the oldest scalable-server pattern. The API cannot detach a thread, so this accepts a bounded number of clients and joins them at the end.

The implementation.

import(lib) std::io::net {
    tcpListen, tcpAccept, tcpRecv, tcpSend, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::concurrent::thread {
    threadCreate, threadJoin, Thread, ThreadError
};
import(lib) std::mman { alloc, dealloc };

// Bound the number of concurrent clients; each gets one thread.
const u32 MAX_CLIENTS = 4;

// Hand a heap-owned socket to a worker across the thread boundary.
struct ClientJob { TcpSocket sock; }

// Worker entry point: own the job, echo its socket, then close it.
rawptr handleClient(rawptr arg)
{
    // Recover the job, copy the socket out, and free the job at once.
    ClientJob* job = (ClientJob*)arg;
    TcpSocket sock = job->sock;
    dealloc<ClientJob>(job);                   // the worker owns the job

    u8 b = 0;
    // Same byte-at-a-time echo as 40.1, but on this worker's own socket.
    while (true)
    {
        // A recv error, a clean close, or a failed send all end the worker.
        Result<isize, IoError> r = tcpRecv(sock, &b, 1);
        if (r.isErr()) break;
        if (r.unwrap() == 0) break;
        if (tcpSend(sock, &b, 1).isErr()) break;
    }
    tcpClose(sock);
    return null;
}

i32 main()
{
    Result<TcpSocket, IoError> server = tcpListen((u16)8080);
    if (server.isErr()) return 1;
    TcpSocket listener = server.unwrap();

    // Keep one join handle per client so the stacks can be reclaimed.
    Thread* workers = alloc<Thread>((usize)MAX_CLIENTS);
    if (workers == null) { tcpClose(listener); return 1; }

    // Accept a bounded batch; the server drains it before exiting.
    u32 accepted = 0;
    while (accepted < MAX_CLIENTS)
    {
        Result<TcpSocket, IoError> conn = tcpAccept(listener);
        if (conn.isErr()) break;

        // Package the accepted socket so the worker can take ownership.
        ClientJob* job = alloc<ClientJob>(1);
        if (job == null) { tcpClose(conn.unwrap()); break; }
        job->sock = conn.unwrap();

        // Spawn the worker; on failure reclaim both socket and job here.
        Result<Thread, ThreadError> t = threadCreate(handleClient, (rawptr)job);
        if (t.isErr()) { tcpClose(job->sock); dealloc<ClientJob>(job); continue; }
        workers[accepted] = t.unwrap();
        accepted += 1;
    }

    // Join every worker so no thread outlives the buffers it used.
    for (u32 i = 0; i < accepted; i += 1) threadJoin(workers[i], null);
    dealloc<Thread>(workers);
    tcpClose(listener);
    return 0;
}

The worker copies the socket out of the job and frees the job before working, so ownership is unambiguous. If threadCreate fails, the accept loop closes the socket and frees the job. Joining each worker makes completion observable.

Cost and notes

One thread per connection means one stack and one kernel object per client, growing with connections; the pool in Chapter 35 replaces that with a queue push. The threads run in parallel, so the server uses every core. The join loop drains every accepted conversation before exit.

Edge cases and variations

A silent client blocks its worker in tcpRecv forever, and the final join blocks with it; a timeout would help, and the API has none. If MAX_CLIENTS connections are accepted and none closes, the server stops accepting long before its workers finish, bad for production but fine for a demonstration. Workers share nothing, so no mutex is needed; the next section changes that. Variation: accept forever and submit each job to a ThreadPool from Chapter 35, bounding threads.

A Line-Based Chat Broadcast Server

The problem

Several clients connect, each types lines, and every line reaches all the others. This is the first protocol where connections must know about each other, which is where shared mutable state appears.

The idea

A Room holds the list of connected sockets behind a mutex. A client joins on connect, leaves on disconnect, and a line is broadcast to every socket except the sender. The mutex protects the list, not the sockets, so a send cannot race a join or leave.

The implementation.

import(lib) std::io::net {
    tcpListen, tcpAccept, tcpRecv, tcpSend, tcpClose, TcpSocket
};
import(lib) std::io::fs { IoError };
import(lib) std::concurrent::thread { threadCreate, Thread, ThreadError };
import(lib) std::concurrent::mutex { Mutex };
import(lib) std::text::string { String };
import(lib) std::mman { alloc, dealloc };

// Cap the room; a joining client beyond this is refused.
const u32 ROOM_CAPACITY = 8;

// The shared state: the set of connected sockets behind one mutex.
struct Room
{
    // Guards the client list; only list operations happen under it.
    Mutex mutex;
    // Fixed-size array of live sockets; their order does not matter.
    TcpSocket* clients;
    u32 count;

    bool init()
    {
        // Allocate the list and start with no members.
        self.clients = alloc<TcpSocket>((usize)ROOM_CAPACITY);
        if (self.clients == null) return false;
        self.mutex.init();
        self.count = 0;
        return true;
    }

    bool join(TcpSocket sock)
    {
        // Under the lock, check for room and append the socket.
        self.mutex.lock();
        bool ok = self.count < ROOM_CAPACITY;
        if (ok) { self.clients[self.count] = sock; self.count += 1; }
        self.mutex.unlock();
        return ok;
    }

    void leave(TcpSocket sock)
    {
        self.mutex.lock();
        // Find the socket, then compact by moving the last entry into its slot.
        u32 i = 0;
        while (i < self.count && (i32)self.clients[i] != (i32)sock) i += 1;
        if (i < self.count)
        {
            self.clients[i] = self.clients[self.count - 1];
            self.count -= 1;
        }
        self.mutex.unlock();
    }

    void broadcast(TcpSocket from, str line)
    {
        self.mutex.lock();
        // Send the line to every member except its originator.
        for (u32 i = 0; i < self.count; i += 1)
        {
            if ((i32)self.clients[i] != (i32)from)
                tcpSend(self.clients[i], line.ptr, line.len);
        }
        self.mutex.unlock();
    }
}

struct ClientJob { Room* room; TcpSocket sock; }

// The same one-byte framing helper used in 40.3.
Result<isize, IoError> readLine(TcpSocket sock, String* out, usize max)
{
    out.clear();
    while (out.len < max)
    {
        u8 b = 0;
        Result<isize, IoError> r = tcpRecv(sock, &b, 1);
        if (r.isErr()) return r;
        if (r.unwrap() == 0) break;
        out.pushByte(b);
        if (b == (u8)'\n') break;
    }
    return Result<isize, IoError>::Ok { .value = (isize)out.len };
}

rawptr chatClient(rawptr arg)
{
    // Unpack the job and take ownership of its socket.
    ClientJob* job = (ClientJob*)arg;
    Room* room = job->room;
    TcpSocket sock = job->sock;
    dealloc<ClientJob>(job);

    // Refuse and close if the room is already full.
    if (!room->join(sock)) { tcpClose(sock); return null; }

    // One reusable line buffer for the client's whole session.
    String line = String::new();
    while (true)
    {
        Result<isize, IoError> r = readLine(sock, &line, 512);
        if (r.isErr()) break;
        if (r.unwrap() == 0) break;
        room->broadcast(sock, line.asView());
    }

    // Leave before closing so no broadcast targets a dead socket.
    room->leave(sock);
    tcpClose(sock);
    return null;
}

i32 main()
{
    // The room lives in main's frame, so it outlives every worker.
    Room room;
    if (!room.init()) return 1;

    // Listener for the chat; one worker thread per connection.
    Result<TcpSocket, IoError> server = tcpListen((u16)8080);
    if (server.isErr()) { return 1; }
    TcpSocket listener = server.unwrap();
    println("chat server listening on port 8080");

    while (true)
    {
        Result<TcpSocket, IoError> conn = tcpAccept(listener);
        if (conn.isErr()) break;

        // Each job carries a pointer to the shared room and its own socket.
        ClientJob* job = alloc<ClientJob>(1);
        if (job == null) { tcpClose(conn.unwrap()); break; }
        job->room = &room;
        job->sock = conn.unwrap();

        Result<Thread, ThreadError> t = threadCreate(chatClient, (rawptr)job);
        if (t.isErr()) { tcpClose(job->sock); dealloc<ClientJob>(job); }
    }
    tcpClose(listener);
    return 0;
}

Room protects its list with one mutex. leave swaps the departing socket with the last element before shrinking, so removal is O(1) and the array stays compact; order does not matter, which makes the swap legal. broadcast holds the lock while sending, so a line cannot slip past a client that just joined or target one that just left.

Cost and notes

Every broadcast is O(clients) sends under one lock. Holding the lock during tcpSend is the sharp edge: a slow client whose buffer is full blocks the send, and every other client waits behind the lock. The honest fix is a per-client outgoing queue with a dedicated writer, more machinery than this example carries.

Edge cases and variations

The room is bounded at eight; a ninth is refused and its socket closed, not left half-joined. A disconnecting client is removed, so the room does not accumulate dead sockets, but one that hangs holds a slot forever. The sender does not receive its own line; that is a product decision. The Room lives in main's frame and outlives every worker, so pointers stay valid. Variation: prefix lines with a client number or send join/leave notices, both using the existing lock.

Error Handling: Refused and Timed-Out Connections

The problem

Network operations fail for reasons the program cannot prevent: nothing listening, no route, no answer. Ignoring Result values discards the only information about the outside world.

The idea

tcpConnect returns Result<TcpSocket, IoError>, where IoError's Os case carries the system error number and the failed operation. A refused connection is immediate, with ECONNREFUSED (111 on Linux). A dropped or filtered address produces no answer, so connect blocks for the kernel's default timeout and fails with ETIMEDOUT (110). The application controls only the number of attempts.

The implementation.

import(lib) std::io::net { tcpConnect, tcpClose, TcpSocket };
import(lib) std::io::fs { IoError };
import(lib) std::time { sleepMs };

i32 main()
{
    // Three attempts; each tcpConnect may block for the kernel timeout.
    for (u32 attempt = 1; attempt <= 3; attempt += 1)
    {
        // Port 9 is the conventional discard port; nothing is listening,
        // so this connect is refused immediately on a local host.
        Result<TcpSocket, IoError> opened = tcpConnect("127.0.0.1", (u16)9);
        if (opened.isOk())
        {
            println("connected on attempt {}", attempt);
            tcpClose(opened.unwrap());
            return 0;
        }

        // Pull the error apart by case; naming all three keeps it exhaustive.
        IoError e = opened.unwrapErr();
        switch (e)
        {
            IoError::Os { code, op } => {
                println("attempt {}: {} failed, errno {}", attempt, op, code);
            },
            IoError::BadUsage { msg } => {
                println("bad address: {}", msg);
            },
            IoError::Eof { op } => {
                println("unexpected end of stream in {}", op);
            }
        }
        // Fixed short back-off; a real client would widen it each round.
        sleepMs(250);
    }

    println("gave up after three attempts");
    return 1;
}

The switch names all three IoError cases, so it is exhaustive and needs no else. Os { code, op } binds the number and operation, enough to distinguish 'refused, try elsewhere' from 'timed out, host unreachable.' The back-off is a fixed sleep; a real client widens it and gives up on permanent errors.

Cost and notes

A failed tcpConnect costs one round trip when the host resets, and the whole kernel timeout when it does not; that asymmetry makes a network program feel fast on a healthy network and hang on a broken one. sleepMs sleeps at least the requested time, so spacing is approximate. errno is platform-specific, so the field is reported rather than hard-coded.

Edge cases and variations

IoError::BadUsage is the library's own complaint about a malformed address such as "999.1.2.3", not a network failure. With no timeout parameter, the loop cannot bound a single attempt; it returns when the kernel decides, typically around a minute for a filtered host. There is no asynchronous cancellation either. Variation: retry only on ETIMEDOUT, give up immediately on ECONNREFUSED, and use a wall-clock budget rather than a fixed attempt count.
