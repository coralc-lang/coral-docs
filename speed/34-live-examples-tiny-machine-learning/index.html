Live Examples: Tiny Machine Learning

Learning From Data, Without the Framework

AI magic dissolves when written down. A model that predicts a price, classifies an email, or clusters customers is three ordinary things: a guess function with tunable numbers, a measure of error, and a rule for nudging the numbers to reduce it. Libraries add speed, not a different idea.

This chapter builds thirteen small pieces in Coral, with Vec<f64> as the only data structure and std::math as the only numerical help: linear regression with a hand-derived gradient, feature normalisation, logistic regression, k-nearest-neighbours, k-means, a one-hidden-layer network with a hand-derived backward pass, metrics, gradient checking, a perceptron, naive Bayes, one-hot and hashed features, a decision stump, and principal components by power iteration.

Everything is deliberately tiny: datasets of tens of points. The goal is to see each moving part and understand why it is there. Once you train a line by hand, w = w - lr * grad is exactly what it says.

Unless stated otherwise, every value is an f64, the approximate arithmetic of Chapter 32.9. Training accumulates small errors over many iterations, which is why losses wobble and why gradient checking exists: it catches a sign error before you blame the data.

Linear Regression by Gradient Descent

The problem

Given pairs such as hours studied and exam score, find the straight line that comes closest and use it to predict a new point.

The intuition

A line has a slope and a height. Start at zero, measure the mean squared error, and ask which way each knob should move. The gradient answers, and stepping opposite it lowers the error. Repeat until the line sits near the bottom.

The approach

Write the guess, the loss, and two partial derivatives, then loop. The slope's derivative is the average of 2 * (prediction - actual) * x; the intercept's is the average of 2 * (prediction - actual).

The implementation.

coral
import(lib) std::vec { Vec };

pub struct LinReg {
    // the two knobs: slope w and intercept b
    f64 w;
    f64 b;

    static LinReg new() {
        // start from the worst guess, a flat line through the origin
        return LinReg { .w = 0.0, .b = 0.0 };
    }

    f64 predict(f64 x) {
        // the line itself: score = slope * x + intercept
        return self.w * x + self.b;
    }

    f64 loss(const Vec<f64>* xs, const Vec<f64>* ys) {
        usize n = xs->count();
        f64 total = 0.0;
        // mean squared error: average of the squared vertical misses
        for (usize i = 0; i < n; i += 1) {
            f64 err = self.predict(xs->at(i)) - ys->at(i);
            total += err * err;
        }
        return total / (f64)n;
    }

    void fit(const Vec<f64>* xs, const Vec<f64>* ys, f64 lr, u64 epochs) {
        usize n = xs->count();
        // invariants: at least one example, and the two vectors aligned
        @assertOut(n > 0, "fit() needs at least one example");
        @assertOut(ys->count() == n, "xs and ys must have the same length");

        for (u64 epoch = 0; epoch < epochs; epoch += 1) {
            f64 gradW = 0.0;
            f64 gradB = 0.0;
            // accumulate the two partial derivatives over the batch
            for (usize i = 0; i < n; i += 1) {
                f64 err = self.predict(xs->at(i)) - ys->at(i);
                gradW += err * xs->at(i);
                gradB += err;
            }
            // gradient step: move each knob opposite its gradient
            f64 scale = 2.0 / (f64)n;
            self.w -= lr * scale * gradW;
            self.b -= lr * scale * gradB;
        }
    }
}

The loop body is the gradient step: accumulate err * x and err, scale by two over the point count, and subtract a learning-rate multiple. Too small a rate is glacial; too large diverges.

Cost and notes

Each epoch is O(n), the whole fit O(epochs * n). Linear regression is convex, so gradient descent cannot get stuck in a local minimum, a guarantee lost with logistic regression or a neural network.

Edge cases

An empty dataset divides by zero; the assertion refuses it. Mismatched lengths are a bug. Large x values produce enormous gradients and divergence; a huge offset makes the intercept drift.

Variation

Add a second feature, y = w1*x1 + w2*x2 + b, with three gradients, and verify that fitting y = 3*x1 - 2*x2 + 1 recovers the coefficients.

Feature Normalisation

The problem

The previous fit works in theory at any scale but crawls or diverges when input spans a wide range. Standardising fixes it.

The intuition

With features on wildly different scales, the error bowl is a long thin tilted valley. Gradient descent steps across it and zigzags. Rescaling each feature to mean zero and standard deviation one rounds the valley.

The approach

Compute the mean, then the standard deviation, then rewrite the vector in place. The library's sqrt supplies the root.

The implementation.

coral
import(lib) std::vec { Vec };
import(lib) std::math::math { sqrt };

pub struct Stats {
    // the two summary numbers used to rescale a feature
    f64 mean;
    f64 std;
}

pub Stats computeStats(const Vec<f64>* xs) {
    usize n = xs->count();
    @assertOut(n > 0, "computeStats() on an empty vector");

    // first pass: the mean
    f64 sum = 0.0;
    for (usize i = 0; i < n; i += 1) sum += xs->at(i);
    f64 mean = sum / (f64)n;

    // second pass: average squared distance from the mean, then its root
    f64 sq = 0.0;
    for (usize i = 0; i < n; i += 1) {
        f64 d = xs->at(i) - mean;
        sq += d * d;
    }
    return Stats { .mean = mean, .std = sqrt(sq / (f64)n) };
}

pub void standardise(Vec<f64>* xs) {
    // summarise first, then rewrite each value in place
    Stats s = computeStats(xs);
    // a constant feature has no spread; map it to zero and avoid dividing by zero
    if (s.std == 0.0) {
        for (usize i = 0; i < xs->count(); i += 1) xs->set(i, 0.0);
        return;
    }
    // rewrite each value as its z-score: (x - mean) / std
    for (usize i = 0; i < xs->count(); i += 1)
        xs->set(i, (xs->at(i) - s.mean) / s.std);
}

Cost and notes

Two passes, O(n) time, O(1) space. The transformed data has mean zero and standard deviation one, so one learning rate works for all features. Normalise first when a model refuses to learn.

Edge cases

A constant feature has zero standard deviation; the routine maps every value to zero rather than divide by zero. The two-pass calculation loses precision when the mean is huge relative to the spread. Standardisation differs from min-max scaling to [0, 1].

Variation

Write minMaxScale(Vec<f64>* xs) mapping data into [0, 1] and compare the two on data with an outlier. Standardisation keeps the outlier meaningful; min-max squashes everything else.

Logistic Regression

The problem

Predict a yes-or-no answer, such as spam or churn, and produce a probability, not just a label.

The intuition

A probability must lie in (0, 1), which a straight line does not. Squash the line's output through sigmoid(z) = 1 / (1 + exp(-z)): negative becomes near zero, positive near one, zero a half. With the log-loss, the gradient with respect to the line's output is simply (prediction - actual); the sigmoid and log-loss derivatives cancel.

The approach

One weight, one bias, a sigmoid, and the training loop from 33.1 with the new error.

The implementation.

coral
import(lib) std::vec { Vec };
import(lib) std::math::math { exp };

pub f64 sigmoid(f64 z) {
    // squash any real number into (0, 1) so it reads as a probability
    return 1.0 / (1.0 + exp(-z));
}

pub struct LogReg {
    // one weight and one bias, as in linear regression
    f64 w;
    f64 b;

    static LogReg new() {
        return LogReg { .w = 0.0, .b = 0.0 };
    }

    f64 probability(f64 x) {
        // the score run through the sigmoid
        return sigmoid(self.w * x + self.b);
    }

    i32 classify(f64 x) {
        // the decision boundary is where the raw score crosses zero
        return (self.w * x + self.b) >= 0.0 ? 1 : 0;
    }

    void fit(const Vec<f64>* xs, const Vec<i32>* ys, f64 lr, u64 epochs) {
        usize n = xs->count();
        @assertOut(ys->count() == n, "xs and ys must have the same length");

        for (u64 epoch = 0; epoch < epochs; epoch += 1) {
            f64 gradW = 0.0;
            f64 gradB = 0.0;
            // for log-loss the gradient is just (probability - label) * feature
            for (usize i = 0; i < n; i += 1) {
                f64 p = self.probability(xs->at(i));
                f64 err = p - (f64)ys->at(i);
                gradW += err * xs->at(i);
                gradB += err;
            }
            // step against the average gradient
            self.w -= lr * gradW / (f64)n;
            self.b -= lr * gradB / (f64)n;
        }
    }
}

classify does not call sigmoid: the boundary is where w*x + b is zero, which is probability one half. Comparing the raw score to zero avoids the exponential.

Cost and notes

Same O(epochs * n) as linear regression, plus one exp per example per epoch. The log-loss is convex, so training is reliable. The probabilities are not automatically calibrated: a model can rank correctly and still report 0.9.

Edge cases

Labels must be zero or one. For strongly negative inputs exp(-z) overflows to infinity, but 1 / (1 + inf) is zero, so the overflow is benign. If the classes are not linearly separable, a fixed rate walks the weights to infinity.

Variation

Generalise to two features and sketch w1*x1 + w2*x2 + b = 0. The boundary is always a straight line, the model's limitation.

k-Nearest Neighbours

The problem

Classify a new point by the labelled points closest to it, with no training.

The intuition

You are like your neighbours. Measure the distance to every stored example, take the k closest, and vote. All work happens at query time, elegant or a performance disaster.

The approach

Store the points. For a query, compute the squared distance to each, select the k smallest without a full sort, and vote. Squared distance skips the square root.

The implementation.

coral
import(lib) std::vec { Vec };

pub struct Example {
    // one stored training point and its known label
    f64 x;
    f64 y;
    i32 label;
}

f64 squaredDistance(const Example* a, f64 qx, f64 qy) {
    // squared distance preserves ordering and skips the square root
    f64 dx = a->x - qx;
    f64 dy = a->y - qy;
    return dx * dx + dy * dy;
}

pub i32 knnPredict(const Vec<Example>* train, f64 qx, f64 qy, u32 k) {
    usize n = train->count();
    @assertOut(k > 0 && (usize)k <= n, "k must be between 1 and the number of examples");

    // indices of the neighbours chosen so far
    Vec<usize> chosen = Vec<usize>::withCap((usize)k);
    // find the k nearest by repeated selection; no full sort needed
    for (u32 round = 0; round < k; round += 1) {
        usize best = 0;
        f64 bestDist = 0.0;
        bool found = false;
        // one pass picks the nearest point not already chosen
        for (usize i = 0; i < n; i += 1) {
            bool used = chosen.contains(i);
            if (used) continue;
            f64 d = squaredDistance(train->atPtr(i), qx, qy);
            if (!found || d < bestDist) {
                best = i;
                bestDist = d;
                found = true;
            }
        }
        chosen.push(best);
    }

    // vote: labels are 0/1, so count votes for label 1
    u32 votesForOne = 0;
    for (usize j = 0; j < chosen.count(); j += 1)
        if (train->at(chosen.at(j)).label == 1) votesForOne += 1;
    // majority wins; exactly half resolves toward label zero
    if (votesForOne > k / 2) return 1;
    return 0;
}

Selection is k passes, each finding the nearest not-yet-chosen point: O(nk) with no sort. The vote is a count because labels are binary; more classes need an argmax.

Cost and notes

O(nk) per query and no training cost: you pay at prediction time, every time. Fine for thousands of examples, unusable for billions.

Edge cases

A tie needs a policy: this code resolves toward label zero on an exact half, which is arbitrary. k must not exceed the example count. Equal distances break by loop order. Raw distances let large-scale features dominate, so normalise first (33.2).

Variation

Use a distance-weighted vote, where each neighbour counts one over its distance, smoothing the boundary. Compare both on interleaved classes.

k-Means Clustering

The problem

With no labels, divide points into k close groups and report the centres.

The intuition

Guessing centres and memberships together is chicken-and-egg, so k-means alternates: guess k centres, assign each point to the nearest, recompute each centre as its members' mean, repeat. Each step reduces the total distance, so it settles, not necessarily at the best grouping.

The approach

Represent a 2-D point, initialise the centres to the first k points, and alternate for a fixed number of iterations.

The implementation.

coral
import(lib) std::vec { Vec };

pub struct Pt {
    // a 2-D data point
    f64 x;
    f64 y;
}

f64 pointDistance(const Pt* a, const Pt* b) {
    // squared Euclidean distance, ordering preserved
    f64 dx = a->x - b->x;
    f64 dy = a->y - b->y;
    return dx * dx + dy * dy;
}

pub Vec<Pt> kmeans(const Vec<Pt>* data, u32 k, u64 iterations) {
    usize n = data->count();
    @assertOut(k > 0 && (usize)k <= n, "k must be between 1 and the number of points");

    // a poor but simple initialiser: the first k points become the centres
    Vec<Pt> centres = Vec<Pt>::withCap((usize)k);
    for (u32 i = 0; i < k; i += 1) centres.push(data->at((usize)i));

    Vec<u32> assignment = Vec<u32>::withCap(n);
    for (usize i = 0; i < n; i += 1) assignment.push(0);

    for (u64 step = 0; step < iterations; step += 1) {
        // assign each point to its nearest centre
        for (usize i = 0; i < n; i += 1) {
            // scan every centre for the closest one
            u32 best = 0;
            f64 bestDist = pointDistance(data->atPtr(i), centres.atPtr(0));
            for (u32 c = 1; c < k; c += 1) {
                f64 d = pointDistance(data->atPtr(i), centres.atPtr(c));
                if (d < bestDist) { bestDist = d; best = c; }
            }
            assignment.set(i, best);
        }

        // recompute each centre as the mean of its members
        for (u32 c = 0; c < k; c += 1) {
            f64 sx = 0.0;
            f64 sy = 0.0;
            usize count = 0;
            for (usize i = 0; i < n; i += 1) {
                if (assignment.at(i) != c) continue;
                sx += data->at(i).x;
                sy += data->at(i).y;
                count += 1;
            }
            // an empty cluster keeps its old centre rather than dividing by zero
            if (count > 0)
                centres.set((usize)c, Pt { .x = sx / (f64)count, .y = sy / (f64)count });
        }
    }
    return centres;
}

Cost and notes

Each iteration is O(nk); the run is O(iterations * nk). It converges because neither step increases the within-cluster distance and assignments are finite, but it stops at a local optimum.

Edge cases

A cluster can lose all members; the code leaves its centre unchanged rather than dividing by zero. First-k initialisation can put two centres nearly on top of each other; k-means++ spreads them. k is a choice, not learned. Euclidean distance lets scale dominate.

Variation

Initialise by choosing k points far apart and compare the final within-cluster distance to first-k on three obvious blobs. Initialisation is most of the battle.

A One-Hidden-Layer Neural Network

The problem

Fit a relationship that is not a straight line. A single linear model cannot represent XOR or a circle; one hidden layer can, in principle, represent any continuous function.

The intuition

Stack two linear models with a bend between them. The first layer produces intermediate values, each a weighted sum squashed through the sigmoid; the second combines them. The hidden layer is learned features. Backpropagation is just the chain rule applied backward, one layer at a time.

The approach

Two inputs, three hidden units, one output, all parameters in Vec<f64>. The forward pass computes hidden activations, then the output. The backward pass computes the output error, updates the second layer, propagates it through the sigmoid's derivative, and updates the first. That derivative is sigmoid'(z) = h * (1 - h), so no new exponentials are needed.

The implementation.

coral
import(lib) std::vec { Vec };
import(lib) std::math::math { exp };

f64 sigmoidF(f64 z) {
    // the bend between the two linear layers
    return 1.0 / (1.0 + exp(-z));
}

pub struct TinyNet {
    usize inputs;
    usize hidden;
    Vec<f64> w1;    // hidden * inputs, row-major
    Vec<f64> b1;    // hidden
    Vec<f64> w2;    // hidden
    f64 b2;

    static TinyNet new(usize inputs, usize hidden) {
        // sizes plus flat parameter vectors
        TinyNet net;
        net.inputs = inputs;
        net.hidden = hidden;
        net.w1 = Vec<f64>::new();
        net.b1 = Vec<f64>::new();
        net.w2 = Vec<f64>::new();
        // a small deterministic starting point; real code would randomise
        for (usize i = 0; i < inputs * hidden; i += 1) net.w1.push(0.1);
        for (usize i = 0; i < hidden; i += 1) net.b1.push(0.0);
        for (usize i = 0; i < hidden; i += 1) net.w2.push(0.1);
        net.b2 = 0.0;
        return net;
    }

    // forward pass: fills hidden[j] and returns the output probability
    f64 forward(const Vec<f64>* x, Vec<f64>* hidden) {
        hidden.clear();
        // first layer: one weighted sum of the inputs per hidden unit
        for (usize j = 0; j < self.hidden; j += 1) {
            f64 z = self.b1.at(j);
            for (usize i = 0; i < self.inputs; i += 1)
                z += self.w1.at(j * self.inputs + i) * x->at(i);
            hidden.push(sigmoidF(z));
        }
        // second layer: combine the bent hidden values into one score
        f64 out = self.b2;
        for (usize j = 0; j < self.hidden; j += 1)
            out += self.w2.at(j) * hidden->at(j);
        return sigmoidF(out);
    }

    // one example, one gradient step, output is a probability, label is 0/1
    void trainOne(const Vec<f64>* x, f64 label, f64 lr) {
        Vec<f64> hidden = Vec<f64>::new();
        f64 out = self.forward(x, &hidden);

        // d(loss)/d(output pre-activation) for log-loss + sigmoid
        f64 deltaOut = out - label;

        // second layer gradients
        for (usize j = 0; j < self.hidden; j += 1)
            self.w2.set(j, self.w2.at(j) - lr * deltaOut * hidden.at(j));
        self.b2 -= lr * deltaOut;

        // first layer gradients, via the chain rule through the sigmoid
        for (usize j = 0; j < self.hidden; j += 1) {
            f64 h = hidden.at(j);
            // scale the output error by the weight and the sigmoid's derivative
            f64 deltaHidden = deltaOut * self.w2.at(j) * h * (1.0 - h);
            self.b1.set(j, self.b1.at(j) - lr * deltaHidden);
            // each first-layer weight's gradient is that hidden error times its input
            for (usize i = 0; i < self.inputs; i += 1) {
                usize idx = j * self.inputs + i;
                f64 grad = deltaHidden * x->at(i);
                self.w1.set(idx, self.w1.at(idx) - lr * grad);
            }
        }
    }

    void train(const Vec<Vec<f64>>* xs, const Vec<f64>* ys, f64 lr, u64 epochs) {
        // plain epoch-by-epoch, example-by-example stochastic descent
        for (u64 epoch = 0; epoch < epochs; epoch += 1)
            for (usize i = 0; i < xs->count(); i += 1)
                self.trainOne(xs->atPtr(i), ys->at(i), lr);
    }
}

Read the backward pass as the chain rule. The output error out - label updates the second-layer weights by multiplying with the hidden activation that fed them. To reach the first layer, scale it by the weight (w2[j]) and the sigmoid's derivative (h * (1 - h)); the first-layer gradient is that error times the input.

Cost and notes

A forward pass is O(inputs hidden) multiply-adds, the backward pass the same again plus updates, so a step is O(inputs hidden) and an epoch O(n inputs hidden). Real networks differ in size, not structure.

Edge cases

Initialising all weights to the same value makes every hidden unit learn the same thing; production code randomises to break symmetry. The sigmoid's derivative is at most a quarter, so gradients shrink with each layer: the vanishing-gradient problem. Labels must be zero or one. Too large a rate produces NaN.

Variation

Change the hidden activation to relu(z) = max(z, 0), derivative one for positive inputs and zero otherwise. Training is cheaper and gradients vanish less; only the h * (1 - h) factor changes. Train both on XOR.

The Confusion Matrix and the Metrics That Read It

The problem

A model that always answers no can be 99% accurate on a dataset that is 99% negative and still useless. Accuracy hides the truth.

The intuition

Every prediction falls into one of four boxes: true positive, false positive, true negative, false negative. Every metric is a ratio of these counts. Accuracy is (tp + tn) / all. Precision is tp / (tp + fp). Recall is tp / (tp + fn). F1 is their harmonic mean, punishing a model good at one and terrible at the other.

The approach

A small struct accumulates the four counts and computes metrics on demand.

The implementation.

coral
pub struct Confusion {
    // the four boxes every prediction falls into
    u64 truePositive;
    u64 falsePositive;
    u64 trueNegative;
    u64 falseNegative;

    static Confusion new() {
        return Confusion {
            .truePositive = 0, .falsePositive = 0,
            .trueNegative = 0, .falseNegative = 0
        };
    }

    // sort one (predicted, actual) pair into its box
    void observe(i32 predicted, i32 actual) {
        if (predicted == 1 && actual == 1) self.truePositive += 1;
        else if (predicted == 1 && actual == 0) self.falsePositive += 1;
        else if (predicted == 0 && actual == 0) self.trueNegative += 1;
        else self.falseNegative += 1;
    }

    u64 total() {
        return self.truePositive + self.falsePositive +
               self.trueNegative + self.falseNegative;
    }

    f64 accuracy() {
        // denominator guarded so an empty matrix reports zero, not NaN
        if (self.total() == 0) return 0.0;
        return (f64)(self.truePositive + self.trueNegative) / (f64)self.total();
    }

    f64 precision() {
        // of the positives we claimed, how many were right
        u64 denom = self.truePositive + self.falsePositive;
        if (denom == 0) return 0.0;
        return (f64)self.truePositive / (f64)denom;
    }

    f64 recall() {
        // of the real positives, how many we caught
        u64 denom = self.truePositive + self.falseNegative;
        if (denom == 0) return 0.0;
        return (f64)self.truePositive / (f64)denom;
    }

    f64 f1() {
        // harmonic mean punishes a model strong at one and weak at the other
        f64 p = self.precision();
        f64 r = self.recall();
        if (p + r == 0.0) return 0.0;
        return 2.0 * p * r / (p + r);
    }
}

Cost and notes

Every metric is O(1), and observing a prediction is a few comparisons. Report all four numbers: precision and recall separate the two ways to be wrong, and a spam filter and a rare-disease screen prefer opposite trade-offs.

Edge cases

Each ratio can have a zero denominator; the code returns zero rather than NaN, a conservative policy. Labels are assumed to be exactly zero or one. Accuracy on imbalanced data is misleading: a constant negative predictor can score 99% and zero F1.

Variation

Add a threshold parameter so the caller varies where a probability becomes positive, and plot the precision-recall trade-off. The threshold is a decision, not a default.

Checking Your Gradient

The problem

Most methods here depend on a hand-derived derivative, and a single wrong sign trains in the wrong direction forever. How do you check it first?

The intuition

A derivative is the tangent's slope, estimable by a finite difference: step slightly right and left and see how much the function changed. It is not exact, but it derives from the function itself, so it independently checks your calculus. Agreement to several decimals makes the gradient almost certainly right.

The approach

A central difference, more accurate than one-sided, compared against the analytic gradient, one weight at a time.

The implementation.

coral
import(lib) std::math::math { fabs };

// scalar case: f is some function of one variable
pub f64 numericalGradient(f64(f64) f, f64 x, f64 eps) {
    // central difference: slope of the chord through x-eps and x+eps
    return (f(x + eps) - f(x - eps)) / (2.0 * eps);
}

pub f64 analyticGradient(f64 x) {
    return 2.0 * x;              // example: f(x) = x^2
}

pub f64 f(f64 x) {
    // the function being differentiated
    return x * x;
}

pub bool gradientChecks(f64 x) {
    // the hand-derived slope and the numeric estimate must agree closely
    f64 numeric = numericalGradient(f, x, 1e-5);
    f64 analytic = analyticGradient(x);
    return fabs(numeric - analytic) < 1e-4;
}

For many parameters, pick one, add eps, compute the loss, subtract 2 * eps, compute again, restore, and divide by 2 * eps. That is its numerical gradient, compared with the backward pass.

Cost and notes

Each numerical gradient costs two loss evaluations, so P parameters cost 2P forward passes: absurd for training, reasonable for a one-time test. Error falls as the step shrinks, then rises with catastrophic cancellation, so 1e-5 is common.

Edge cases

The step must be neither too large (an average slope) nor too small (nearly equal numbers lose precision). The check is a test, not training: run it once on a small model. It checks the gradient, not the update rule.

Variation

Add a gradient check to TinyNet: for each weight and bias, compare the backward pass's value with the numerical estimate on a small network. It is the most convincing evidence that backpropagation is correct.

The Perceptron

The problem

Learn a straight-line boundary from labelled examples with the smallest update rule. Logistic regression gives a probability; the perceptron gives only a hard answer.

The intuition

A perceptron classifies by the sign of w*x + b and learns only from mistakes: a positive example called negative nudges the weights toward it; a negative called positive nudges away; a correct call does nothing. There is no loss, sigmoid, or gradient. Rosenblatt's theorem: if the data is linearly separable, this finds a boundary in finite steps.

The approach

Logistic regression minus the sigmoid: predict a hard label, turn the error into a push, repeat.

The implementation.

coral
import(lib) std::vec { Vec };

pub struct Perceptron {
    // the same two knobs, but a hard decision instead of a probability
    f64 w;
    f64 b;

    static Perceptron new() {
        return Perceptron { .w = 0.0, .b = 0.0 };
    }

    i32 predict(f64 x) {
        // classify by the sign of the raw score
        return (self.w * x + self.b) > 0.0 ? 1 : 0;
    }

    void fit(const Vec<f64>* xs, const Vec<i32>* ys, f64 lr, u64 epochs) {
        usize n = xs->count();
        @assertOut(ys->count() == n, "xs and ys must have the same length");

        for (u64 epoch = 0; epoch < epochs; epoch += 1) {
            for (usize i = 0; i < n; i += 1) {
                f64 target = (f64)ys->at(i);          // 0 or 1
                // error is one of -1, 0, +1: a plain nudge, not a gradient
                f64 error = target - (f64)self.predict(xs->at(i));
                self.w += lr * error * xs->at(i);     // only moves on a mistake
                self.b += lr * error;
            }
        }
    }
}

The error is one of -1, 0, or 1, so the update is a plain nudge. Compare the logistic update from 33.3, which multiplies the same error by a probability and a learning rate.

Cost and notes

O(epochs * n), like linear and logistic regression, with no exponential per step. Convergence holds only for linearly separable classes; on inseparable data the weights cycle forever, which is why smooth-loss logistic regression is preferred.

Edge cases

Labels must be zero or one; other encodings silently produce the wrong push. Feature scale matters as in 33.1 and 33.2, so standardise first. A perfectly classified pass changes nothing, a clean early-stopping test.

Variation

Generalise to two features and return the boundary line, then train on XOR and watch it fail: no line separates XOR, which motivates the hidden layer in 33.6.

Naive Bayes

The problem

Classify with a tiny probabilistic model built from counts rather than gradients. It trains in a single pass.

The intuition

Bayes' rule says the odds of a class are proportional to the prior odds times the likelihood. The naive assumption makes features independent given the class, turning the likelihood into a product of per-feature terms. For binary features, each term is a count. Smooth the counts by pretending each outcome occurred once more, so an unseen feature does not zero everything, and add logarithms so a long document does not underflow.

The approach

Two classes, binary features. Train by counting; predict by summing log-probabilities.

The implementation.

coral
import(lib) std::vec { Vec };
import(lib) std::math::math { log };

pub struct NaiveBayes {
    // learned per-feature probabilities plus the class prior
    Vec<f64> pOnGiven0;
    Vec<f64> pOnGiven1;
    f64 prior1;
    usize features;

    static NaiveBayes new(usize numFeatures) {
        NaiveBayes nb;
        nb.features = numFeatures;
        nb.prior1 = 0.5;
        nb.pOnGiven0 = Vec<f64>::new();
        nb.pOnGiven1 = Vec<f64>::new();
        // uninformed starting probabilities, one slot per feature
        for (usize j = 0; j < numFeatures; j += 1) {
            nb.pOnGiven0.push(0.5);
            nb.pOnGiven1.push(0.5);
        }
        return nb;
    }

    void fit(const Vec<Vec<u8>>* rows, const Vec<i32>* labels, u64 smoothing) {
        usize n = rows->count();
        @assertOut(labels->count() == n, "rows and labels must align");

        // one occurrence counter per class per feature
        Vec<u64> count0 = Vec<u64>::new();
        Vec<u64> count1 = Vec<u64>::new();
        for (usize j = 0; j < self.features; j += 1) { count0.push(0); count1.push(0); }

        u64 n0 = 0;
        u64 n1 = 0;
        // single pass: tally class sizes and per-feature on-counts
        for (usize i = 0; i < n; i += 1) {
            i32 c = labels->at(i);
            if (c == 1) n1 += 1; else n0 += 1;
            for (usize j = 0; j < self.features; j += 1) {
                if (rows->at(i).at(j) != 0) {
                    if (c == 1) count1.set(j, count1.at(j) + 1);
                    else count0.set(j, count0.at(j) + 1);
                }
            }
        }

        // class prior estimated from the observed label counts
        if (n > 0) self.prior1 = (f64)n1 / (f64)n;

        f64 s = (f64)smoothing;
        for (usize j = 0; j < self.features; j += 1) {
            self.pOnGiven0.set(j, ((f64)count0.at(j) + s) / ((f64)n0 + 2.0 * s));
            self.pOnGiven1.set(j, ((f64)count1.at(j) + s) / ((f64)n1 + 2.0 * s));
        }
    }

    i32 predict(const Vec<u8>* row) {
        // work in log space so a long row does not underflow to zero
        f64 log0 = log(1.0 - self.prior1);
        f64 log1 = log(self.prior1);
        // the "naive" step: multiply per-feature likelihoods independently
        for (usize j = 0; j < self.features; j += 1) {
            bool on = row->at(j) != 0;
            f64 p0 = on ? self.pOnGiven0.at(j) : 1.0 - self.pOnGiven0.at(j);
            f64 p1 = on ? self.pOnGiven1.at(j) : 1.0 - self.pOnGiven1.at(j);
            log0 += log(p0);
            log1 += log(p1);
        }
        // the larger log-posterior wins
        return log1 > log0 ? 1 : 0;
    }
}

The smoothing constant adds one imagined observation of each outcome; with smoothing one, an unseen feature has estimate one half, not zero, so a missing word cannot veto a prediction. Training is one pass of counting.

Cost and notes

Training is O(n * features) and prediction O(features), cheaper than the gradient methods with no learning rate. The independence assumption is usually false: correlated features are counted more than once, distorting probabilities but leaving the ranking intact.

Edge cases

Smoothing keeps a zero-count class finite; smoothing must exceed zero, or an unseen feature produces log(0). Features must be binary; other types need a different likelihood. A zero prior cannot happen here because n > 0 is checked. The feature space is fixed at construction, so unseen tokens have no slot.

Variation

Use word counts and the multinomial form: the likelihood becomes powers of per-word probabilities, and training counts appearances rather than presence. It is the version introductory text classifiers use.

One-Hot Encoding and Feature Hashing

The problem

A model consumes numbers, but a feature is often a label: a colour, an operating system, a word. Turn categories into vectors, compressing unbounded sets into a fixed size.

The intuition

One-hot encoding gives every category its own dimension: one where it lives, zeros elsewhere. Vectors are far apart and categories independent, but a language needs a dimension per word. Feature hashing hashes each category to an index in a fixed-size vector and counts the hit. Collisions are possible but rare in a large table, and memory is fixed.

The approach

A one-hot function over a vocabulary, and hashing into fixed buckets using the library's FNV-1a hash.

The implementation.

coral
import(lib) std::vec { Vec };
import(lib) std::crypto::hash { fnv1aStr };

pub Vec<f64> oneHot(str category, const Vec<str>* vocab) {
    // one dimension per known category, all zero until the match
    Vec<f64> v = Vec<f64>::withCap(vocab->count());
    for (usize j = 0; j < vocab->count(); j += 1) v.push(0.0);
    // linear scan for the category's slot
    for (usize j = 0; j < vocab->count(); j += 1) {
        if (vocab->at(j).equals(category)) {
            v.set(j, 1.0);
            break;
        }
    }
    return v;                          // unknown category: all zeros
}

pub Vec<f64> hashFeatures(const Vec<str>* tokens, usize buckets) {
    @assertOut(buckets > 0, "need at least one bucket");

    // fixed-size vector no matter how large the vocabulary grows
    Vec<f64> v = Vec<f64>::withCap(buckets);
    for (usize j = 0; j < buckets; j += 1) v.push(0.0);

    for (usize i = 0; i < tokens->count(); i += 1) {
        // deterministic hash so train and predict agree on the bucket
        u64 h = fnv1aStr(tokens->at(i));
        usize idx = (usize)(h % (u64)buckets);
        v.set(idx, v.at(idx) + 1.0);   // count occurrences in the bucket
    }
    return v;
}

The one-hot vector has a one where the category lives, so its dot product with a weight vector picks out that category's weight. The hashed vector counts how many tokens fell into each bucket, and a linear model learns one weight per bucket. An unknown category yields all zeros.

Cost and notes

oneHot is O(vocab) to build and search; a hash map would make it O(1) for large vocabularies. hashFeatures is O(tokens) with one FNV hash per token, and its memory is exactly buckets doubles. That fixed budget makes online text learning possible, at the cost of collision noise.

Edge cases

A duplicate category makes oneHot set the first match and ignore the rest; remove duplicates. An unknown category produces all zeros indistinguishable from absent; reserve an index for unknown. Hashing is lossy and not invertible, and colliding tokens share a weight; the error falls as buckets rise. fnv1aStr must be deterministic.

Variation

Add a sign to the hashing trick: hash each token a second way and use the low bit as +1 or -1. Collisions cancel instead of adding, reducing bias, at one more hash and a multiply.

A Decision Stump

The problem

Build the simplest decision tree: one feature, one threshold, two constant predictions. A stump is legible and is boosting's weak learner.

The intuition

A stump asks one question, is this value above or below a threshold?, splits the data, and predicts the majority label on each side. Try every sensible threshold and keep the split with the fewest mistakes. You can read the rule aloud, but one split only cuts the space in two, which is why a stump cannot solve XOR.

The approach

Try every data value as a threshold and both labellings of the two sides, keeping the lowest error. Deliberately quadratic.

The implementation.

coral
import(lib) std::vec { Vec };

pub struct Stump {
    // one threshold and two constant predictions: the whole model
    f64 threshold;
    i32 leftLabel;       // prediction when x <= threshold
    i32 rightLabel;      // prediction when x > threshold
    f64 error;

    static Stump new() {
        // error 1.0 is the worst possible, so the first split improves on it
        return Stump { .threshold = 0.0, .leftLabel = 0, .rightLabel = 0, .error = 1.0 };
    }

    i32 predict(f64 x) {
        // the stump is entirely the threshold and the two answers
        return x <= self.threshold ? self.leftLabel : self.rightLabel;
    }
}

u64 mistakesAt(const Vec<f64>* xs, const Vec<i32>* ys, f64 t, i32 left, i32 right) {
    // count how many points this candidate split gets wrong
    u64 wrong = 0;
    for (usize i = 0; i < xs->count(); i += 1) {
        i32 pred = xs->at(i) <= t ? left : right;
        if (pred != ys->at(i)) wrong += 1;
    }
    return wrong;
}

pub Stump fitStump(const Vec<f64>* xs, const Vec<i32>* ys) {
    usize n = xs->count();
    @assertOut(n > 0 && ys->count() == n, "need aligned, non-empty data");

    Stump best = Stump::new();
    // brute force: try every data value as a threshold
    for (usize i = 0; i < n; i += 1) {
        f64 t = xs->at(i);
        // and every labelling of the two sides
        for (i32 left = 0; left <= 1; left += 1) {
            for (i32 right = 0; right <= 1; right += 1) {
                u64 wrong = mistakesAt(xs, ys, t, left, right);
                f64 err = (f64)wrong / (f64)n;
                // keep the split with the lowest error
                if (err < best.error) {
                    best.threshold = t;
                    best.leftLabel = left;
                    best.rightLabel = right;
                    best.error = err;
                }
            }
        }
    }
    return best;
}

For each threshold the code tries all four labellings, more than necessary but obviously complete. error starts at 1.0, the worst possible, so the first real split improves on it.

Cost and notes

The search is O(n^2): each of n thresholds costs a full pass and four labellings. The efficient version sorts once and sweeps with running label counts: O(n log n) for the sort and O(n) for the sweep.

Edge cases

A threshold at a data value assigns the boundary point to the left (x <= t); using < flips it, which matters when values repeat. If one split separates perfectly, error reaches zero and later ties are ignored. For inseparable data the best error stays above zero, and reporting it honestly beats pretending a fit.

Variation

Choose the threshold as the midpoint between adjacent sorted values, and add a predict returning the error-weighted vote for boosting. Train two stumps on XOR and add their votes.

Principal Component Analysis by Power Iteration

The problem

Take data with many correlated features and find the direction along which it varies most, so you can compress it, visualise it, or reduce noise.

The intuition

The direction of greatest spread is an eigenvector of the covariance matrix, and the largest eigenvalue measures that spread. Forming the matrix is wasteful; instead exploit what an eigenvector means: applying the matrix returns the same direction, only longer. Power iteration starts with any vector, applies the matrix, and renormalises, so the dominant direction wins. For data, each multiply is one project and one accumulate pass.

The approach

Standardise each dimension first (33.2), start from a unit vector, and iterate v ← normalise(Xᵀ(Xv)) a fixed number of times.

The implementation.

coral
import(lib) std::vec { Vec };
import(lib) std::math::math { sqrt };

f64 dotProduct(const Vec<f64>* a, const Vec<f64>* b) {
    // one projection: sum of elementwise products
    f64 s = 0.0;
    for (usize i = 0; i < a->count(); i += 1) s += a->at(i) * b->at(i);
    return s;
}

f64 norm(const Vec<f64>* v) {
    // Euclidean length, used to renormalise after each power step
    f64 s = 0.0;
    for (usize i = 0; i < v->count(); i += 1) s += v->at(i) * v->at(i);
    return sqrt(s);
}

// rows: n examples, each a d-dimensional point, already standardised
pub Vec<f64> firstPrincipalComponent(const Vec<Vec<f64>>* rows, usize d, u64 iters) {
    usize n = rows->count();
    Vec<f64> v = Vec<f64>::withCap(d);
    // any unit vector will do to start the iteration
    for (usize j = 0; j < d; j += 1) v.push(1.0 / sqrt((f64)d));   // unit start

    for (u64 step = 0; step < iters; step += 1) {
        Vec<f64> next = Vec<f64>::withCap(d);
        for (usize j = 0; j < d; j += 1) next.push(0.0);

        // apply the data matrix twice without ever building the covariance
        for (usize i = 0; i < n; i += 1) {
            f64 proj = dotProduct(rows->atPtr(i), &v);             // X v
            for (usize j = 0; j < d; j += 1)
                next.set(j, next.at(j) + proj * rows->at(i).at(j)); // Xᵀ (X v)
        }

        // renormalise so the vector does not grow without bound
        f64 len = norm(&next);
        if (len == 0.0) break;                                     // no variance to find
        for (usize j = 0; j < d; j += 1) v.set(j, next.at(j) / len);
    }
    return v;
}

The two nested loops are the data matrix and its transpose multiplied out, so the covariance matrix never exists. The fixed iteration count is a simplification: in practice you stop when the direction stops changing, and a dozen iterations suffices here.

Cost and notes

Each iteration is O(n d), so the routine is O(iters n * d). Convergence is geometric, at a rate set by the ratio of the first two eigenvalues; when they are close, the direction is ill-defined and convergence slow.

Edge cases

Standardise first: otherwise a feature measured in millions dominates one measured in units. The sign of the returned vector is arbitrary, since v and -v are the same direction. If the data is constant, norm returns zero and the starting vector stands. Nearly equal top eigenvalues make any answer unstable.

Variation

Deflate for the second component: subtract each row's projection onto the first and iterate again, then check orthogonality. Report the variance fraction each component captures.
