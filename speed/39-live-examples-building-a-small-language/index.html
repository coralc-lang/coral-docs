Live Examples: Building a Small Language

A Tokenizer, a Parser, and an Interpreter You Can Read

Every program that reads a program (compiler, interpreter, linter, config loader, query planner) has three parts: a lexer turning text into tokens, a parser turning tokens into a tree, and an evaluator walking the tree. Each is a page of code, and the pipeline fits in an afternoon.

The language is deliberately tiny: integers, arithmetic, comparison, variables, if, while, and print. No types, functions, strings, or garbage collector. That is the point. Real languages add features but keep this shape, with more switch cases. The grammar is small enough to trace every decision.

The pipeline is one-way: bytes to tokens (39.1), tokens to an abstract syntax tree (39.2, 39.3), the tree walked (39.5 to 39.7) or lowered to bytecode (39.8). Errors are values carrying source positions (39.4), and a REPL wires the stages together (39.9). Each stage knows nothing about those after it, so each can be tested alone.

The headings are a build order. Read them in order the first time. The tokenizer defines TokenKind, the AST defines Expr, and the environment is the hash map from Chapter 26. Only new code is shown; the REPL in 39.9 is the final assembly.

Everything is an i64. Booleans are integers too: comparison yields 1 or 0, and a condition is true when nonzero. That removes the type-checking pass. It also means division by zero needs a hand-defined meaning, which we set to 0. These are the usual hand-rolled-language warts.

The programs use Vec, String, println/print, alloc/dealloc, and HashMap. Option, Result, str, and the integer types are in the prelude. Each block repeats its imports. A str is borrowed; a String is owned, and the REPL is careful about which survives a line.

The Tokenizer

The problem

Turn source text into tokens: a small tagged record per number, name, operator, or delimiter, each with a source position so errors can point at it.

The idea

Walk the bytes once. Skip whitespace; a digit run is a number; a run of letters, digits, and underscores is a name, promoted to a keyword if it spells one; every other byte is a one-character operator or delimiter. Append a sentinel token so lookahead never checks for the end, which shortens every later stage.

The implementation.

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

enum TokenKind {
    Number, Ident,
    Plus, Minus, Star, Slash, Less, Greater,
    LParen, RParen, LBrace, RBrace,
    Semi, Assign,
    If, Else, While, Print,
    Eof,
}

// a token is a tag, a source offset, a value, and its spelling
struct Token {
    TokenKind kind;
    usize pos;
    i64 value;
    str text;
}

// byte classifiers keep the scanner's branches short
bool isDigit(u8 c) { return c >= '0' && c <= '9'; }

bool isAlpha(u8 c) {
    return (c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z') || c == '_';
}

bool isAlnum(u8 c) { return isAlpha(c) || isDigit(c); }

void pushToken(Vec<Token>* out, TokenKind kind, usize pos, i64 value, str text) {
    // text is a view into the source; nothing is copied
    out->push(Token { .kind = kind, .pos = pos, .value = value, .text = text });
}

Vec<Token> tokenize(str src) {
    Vec<Token> out = Vec<Token>::new();
    // i is the cursor over the source bytes
    usize i = 0;
    // one pass of the loop produces exactly one token
    while (i < src.len) {
        u8 c = src.at(i);
        // whitespace separates tokens but carries no meaning of its own
        if (c == ' ' || c == '\t' || c == '\n' || c == '\r') { i += 1; continue; }
        // a number: fold digits with Horner's rule
        if (isDigit(c)) {
            usize start = i;
            i64 value = 0;
            // consume the whole run of digits, not just the first
            while (i < src.len && isDigit(src.at(i))) {
                value = value * 10 + (i64)(src.at(i) - '0');
                i += 1;
            }
            pushToken(&out, TokenKind::Number, start, value, src.slice(start, i));
            continue;
        }
        // a name, or a keyword that looks exactly like one
        if (isAlpha(c)) {
            usize start = i;
            // a name runs until a byte that cannot be part of one
            while (i < src.len && isAlnum(src.at(i))) i += 1;
            str word = src.slice(start, i);
            TokenKind kind = TokenKind::Ident;
            // the four reserved words are recognized by spelling alone
            if (word.equals("if")) kind = TokenKind::If;
            else if (word.equals("else")) kind = TokenKind::Else;
            else if (word.equals("while")) kind = TokenKind::While;
            else if (word.equals("print")) kind = TokenKind::Print;
            pushToken(&out, kind, start, 0, word);
            continue;
        }
        // every other byte is a one-character operator or delimiter
        // the default is overwritten by whichever case matches below
        TokenKind kind = TokenKind::Eof;
        switch (c) {
            '+' => kind = TokenKind::Plus,
            '-' => kind = TokenKind::Minus,
            '*' => kind = TokenKind::Star,
            '/' => kind = TokenKind::Slash,
            '<' => kind = TokenKind::Less,
            '>' => kind = TokenKind::Greater,
            '(' => kind = TokenKind::LParen,
            ')' => kind = TokenKind::RParen,
            '{' => kind = TokenKind::LBrace,
            '}' => kind = TokenKind::RBrace,
            ';' => kind = TokenKind::Semi,
            '=' => kind = TokenKind::Assign,
            // an unknown byte is skipped: this is a tokenizer, not a checker
            else => { i += 1; continue; },
        }
        // record the operator at its own byte, then step past it
        pushToken(&out, kind, i, 0, src.slice(i, i + 1));
        i += 1;
    }
    // the End Of File sentinel never has a real position past the source
    pushToken(&out, TokenKind::Eof, src.len, 0, "");
    return out;
}

str kindName(TokenKind k) {
    // a printable name, used for diagnostics and for this demo
    switch (k) {
        TokenKind::Number  => return "Number",
        TokenKind::Ident   => return "Ident",
        TokenKind::Plus    => return "Plus",
        TokenKind::Minus   => return "Minus",
        TokenKind::Star    => return "Star",
        TokenKind::Slash   => return "Slash",
        TokenKind::Less    => return "Less",
        TokenKind::Greater => return "Greater",
        TokenKind::LParen  => return "LParen",
        TokenKind::RParen  => return "RParen",
        TokenKind::LBrace  => return "LBrace",
        TokenKind::RBrace  => return "RBrace",
        TokenKind::Semi    => return "Semi",
        TokenKind::Assign  => return "Assign",
        TokenKind::If      => return "If",
        TokenKind::Else    => return "Else",
        TokenKind::While   => return "While",
        TokenKind::Print   => return "Print",
        TokenKind::Eof     => return "Eof",
    }
}

void main() {
    str src = "x = 1 + 2*3; if x < 10 { print x; }";
    Vec<Token> toks = tokenize(src);
    for (usize i = 0; i < toks.count(); i += 1) {
        Token t = toks.at(i);
        // the text column is the exact slice the token covers
        println("{} {}", kindName(t.kind), t.text);
    }
}

Tokens keep a str rather than a copied String, because the source outlives parsing; this is Chapter 10's lifetime rule. pos is the first byte's offset, printed as a column in errors. The Eof sentinel is appended unconditionally, so an empty source yields one token and lookahead is total.

Cost and notes

Time is O(n): each byte is consumed by one branch and never examined twice. Space is O(t) for tokens plus the uncopied source. This is a single-pass scanner, so lexing a megabyte is memory-bandwidth bound. A production lexer adds maximal munch for ==, <=, &&, number bases, and escapes; each is one more while, not a new architecture.

Edge cases and variations

An empty source yields exactly one token. A number too large for i64 wraps silently in value * 10 + digit; a real lexer checks overflow. An unknown byte such as @ is skipped rather than diagnosed, a simplification; 39.4 puts diagnosis in the parser, the first stage that knows the grammar. The variation is maximal munch: peek at the next byte and emit <= or == as one token.

The AST as a Variant

The problem

Represent a parsed expression as data the evaluator can walk: numbers, variable references, negation, and binary operations whose operands may themselves be operations.

The idea

This is a variant from Chapter 13, and self-reference is the story. An expression is one of four cases, two pointing back at more expressions. Pointers make the type finite: a variant containing whole Expr values would ask the compiler to size a box in terms of itself. alloc/dealloc frees the heap nodes.

The implementation.

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println, print };

enum Op { Add, Sub, Mul, Div, Less, Greater }

variant Expr {
    Num { i64 value; }
    Var { str name; }
    Neg { Expr* operand; }
    Bin { Op op; Expr* left; Expr* right; }
}

Expr* mkNum(i64 value) {
    // one node per allocation; the tag records which case is live
    Expr* e = alloc<Expr>(1);
    *e = Expr::Num { .value = value };
    return e;
}

Expr* mkVar(str name) {
    // the name is a view into the source, not a copy
    Expr* e = alloc<Expr>(1);
    *e = Expr::Var { .name = name };
    return e;
}

Expr* mkNeg(Expr* operand) {
    // negation holds a single child pointer
    Expr* e = alloc<Expr>(1);
    *e = Expr::Neg { .operand = operand };
    return e;
}

Expr* mkBin(Op op, Expr* left, Expr* right) {
    // a binary node is the only case with two children
    Expr* e = alloc<Expr>(1);
    *e = Expr::Bin { .op = op, .left = left, .right = right };
    return e;
}

str opName(Op op) {
    // the symbol, for printing a tree back out
    switch (op) {
        Op::Add => return "+",
        Op::Sub => return "-",
        Op::Mul => return "*",
        Op::Div => return "/",
        Op::Less => return "<",
        Op::Greater => return ">",
    }
}

void show(Expr* e) {
    // copy the variant out so its fields are bound by the switch
    Expr node = *e;
    switch (node) {
        Expr::Num { value } => print("{}", value),
        Expr::Var { name } => print("{}", name),
        Expr::Neg { operand } => { print("(- "); show(operand); print(")"); },
        Expr::Bin { op, left, right } => {
            // fully parenthesized so grouping is unambiguous
            print("(");
            show(left);
            print(" {} ", opName(op));
            show(right);
            print(")");
        },
    }
}

// deallocate bottom-up: children before the parent that points at them
void freeExpr(Expr* e) {
    Expr node = *e;
    switch (node) {
        // leaves own nothing beneath them
        Expr::Num | Expr::Var => {},
        Expr::Neg { operand } => freeExpr(operand),
        Expr::Bin { left, right } => { freeExpr(left); freeExpr(right); },
    }
    // children are freed first, so the parent's pointers are dead here
    dealloc<Expr>(e);
}

void main() {
    // 1 + 2 * 3, built by hand for now; the parser comes next
    Expr* e = mkBin(Op::Add, mkNum(1), mkBin(Op::Mul, mkNum(2), mkNum(3)));
    // the printed form should read (+ 1 (* 2 3))
    show(e);
    println("");
    freeExpr(e);
}

show prints the tree fully parenthesized, which confirms parsing produced the intended tree: (+ 1 (* 2 3)) differs visibly from (* (+ 1 2) 3). freeExpr is postorder deallocation, as freeTree in Chapter 28, because a parent's pointers are the only route to its children.

Cost and notes

Construction is O(1) per node. show and freeExpr are O(n). A tree of n nodes uses O(n) heap and O(h) stack for depth h; a right-leaning chain of a million additions recurses a million frames deep. No sharing, no cycles: each node is allocated once and freed once.

Edge cases and variations

freeExpr on a Num or Var frees only the node, since the str name is a view. Freeing null never happens. New cases such as Call { str name; Vec<Expr*> args; } or Index stop show, freeExpr, and the evaluator compiling until handled, which is Chapter 13's exhaustiveness doing real work.

A Recursive-Descent Parser with Precedence

The problem

Turn the token vector into a tree respecting precedence: 1 + 2 * 3 groups as 1 + (2 * 3), and subtraction is left-associative so 1 - 2 - 3 is (1 - 2) - 3.

The idea

One function per precedence level, each calling the tighter level for operands: comparison calls addition, which calls multiplication, which calls unary negation, which calls atoms. Multiplication loops while it sees * or /, swallowing them before returning to addition. The loop, not recursion, makes each level left-associative. This is recursive descent.

The implementation

This builds on the Token/TokenKind definitions of 39.1 and the Expr, Op, and mk* constructors of 39.2. Only the parser is new.

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

struct Parser {
    Vec<Token> toks;
    usize pos;
}

// peek never advances; every level looks before it consumes
Token peek(Parser* p) { return p->toks.at(p->pos); }

Token advance(Parser* p) {
    Token t = p->toks.at(p->pos);
    // the Eof sentinel guarantees advance can never run off the end
    if (p->pos + 1 < p->toks.count()) p->pos += 1;
    return t;
}

// check combines peek and a comparison; it never consumes
bool check(Parser* p, TokenKind k) { return peek(p).kind == k; }

// operator tokens become the tree operators of the AST
Op toOp(TokenKind k) {
    switch (k) {
        TokenKind::Plus => return Op::Add,
        TokenKind::Minus => return Op::Sub,
        TokenKind::Star => return Op::Mul,
        TokenKind::Slash => return Op::Div,
        TokenKind::Less => return Op::Less,
        TokenKind::Greater => return Op::Greater,
        // reached only for tokens each level has already accepted
        else => return Op::Add,
    }
}

// the precedence chain: loosest at the top, atoms at the bottom
Expr* parseExpr(Parser* p) { return parseComparison(p); }

Expr* parseComparison(Parser* p) {
    Expr* left = parseAddSub(p);
    // comparison is the loosest level, so it is parsed first
    while (check(p, TokenKind::Less) || check(p, TokenKind::Greater)) {
        Token opTok = advance(p);
        Expr* right = parseAddSub(p);
        left = mkBin(toOp(opTok.kind), left, right);
    }
    return left;
}

Expr* parseAddSub(Parser* p) {
    Expr* left = parseMulDiv(p);
    // the loop folds left, which is what makes a - b - c group left
    while (check(p, TokenKind::Plus) || check(p, TokenKind::Minus)) {
        Token opTok = advance(p);
        Expr* right = parseMulDiv(p);
        left = mkBin(toOp(opTok.kind), left, right);
    }
    return left;
}

Expr* parseMulDiv(Parser* p) {
    Expr* left = parseUnary(p);
    // multiplying binds tighter than adding, so this level runs first
    while (check(p, TokenKind::Star) || check(p, TokenKind::Slash)) {
        Token opTok = advance(p);
        Expr* right = parseUnary(p);
        left = mkBin(toOp(opTok.kind), left, right);
    }
    return left;
}

Expr* parseUnary(Parser* p) {
    // unary minus binds tighter than any binary operator
    if (check(p, TokenKind::Minus)) {
        advance(p);
        // recursion makes --x and -x both legal, unlike the loop levels
        return mkNeg(parseUnary(p));
    }
    return parsePrimary(p);
}

Expr* parsePrimary(Parser* p) {
    Token t = peek(p);
    switch (t.kind) {
        TokenKind::Number => { advance(p); return mkNum(t.value); },
        TokenKind::Ident => { advance(p); return mkVar(t.text); },
        TokenKind::LParen => {
            // parentheses re-enter at the loosest level
            advance(p);
            Expr* inner = parseExpr(p);
            if (check(p, TokenKind::RParen)) advance(p);
            return inner;
        },
        // an unexpected token becomes a zero, for now
        else => { advance(p); return mkNum(0); },
    }
}

void main() {
    str src = "1 + 2 * 3 - 4 < 2 * -5";
    Parser p = Parser { .toks = tokenize(src), .pos = 0 };
    Expr* e = parseExpr(&p);
    // the tree prints with precedence made explicit
    show(e);
    println("");
    freeExpr(e);
}

The non-obvious move is that parseComparison calls parseAddSub for both sides, not itself. Operands always come from a stricter level, which stops left recursion, the infinite regress of expr := expr '+' expr. The while loops handle repetition. Read the four levels as one idea repeated, and Chapter 3's precedence table becomes a stack of functions.

Cost and notes

Parsing is O(t): each token is consumed by one advance, and lookahead never backtracks. Recursion depth is bounded by nesting, not length. Recursive descent suits small grammars; larger ones grow to dozens of levels or a table-driven parser, but the shape, a function per precedence and a loop per repetition, remains.

Edge cases and variations

1 + 2 * 3 - 4 < 2 * -5 parses as ((1 + (2 * 3)) - 4) < (2 * (-5)). A missing closing parenthesis is silently accepted: (1 + 2 returns the tree for 1 + 2 because of the if (check(...)) advance(p) guard, a bug fixed in 39.4. An unexpected token yields zero rather than an error, convenient here but wrong in production. The variation is a precedence table: one parseBinary(minPrec) looping while precedence(peek.kind) > minPrec.

Errors That Carry a Position

The problem

When input is invalid, report where and why instead of silently substituting zero or dropping a token. The report must point at a byte offset in the source.

The idea

Make the error a value: a ParseError variant carrying a message and position, stored in the parser. Every parse function keeps going after recording an error, so one run reports the first problem without early returns. The first error wins, since later ones are consequences. A Result carries the tree or error out, following Chapter 15.

The implementation

This adds error state to the parser of 39.3 and changes the entry point; the tokenizer and tree are unchanged.

import(lib) std::vec { Vec };
import(lib) std::result { Result };
import(lib) std::io::ios { println };

// errors are values, not exceptions: each one carries where it happened
variant ParseError {
    Unexpected { str what; usize pos; }
    TrailingTokens { usize pos; }
}

struct Parser {
    Vec<Token> toks;
    usize pos;
    // failed latches once, so parse can report and still keep going
    bool failed;
    ParseError err;
}

void fail(Parser* p, str what, usize pos) {
    // keep the first error; later ones are consequences of it
    if (p->failed) return;
    p->failed = true;
    p->err = ParseError::Unexpected { .what = what, .pos = pos };
}

// expect consumes the wanted token, or reports and keeps going
Token expect(Parser* p, TokenKind k, str what) {
    if (check(p, k)) return advance(p);
    Token t = peek(p);
    fail(p, what, t.pos);
    // return the offending token so callers can keep making progress
    return t;
}

Expr* parsePrimary(Parser* p) {
    Token t = peek(p);
    switch (t.kind) {
        // a number's digits were already folded to i64 by the lexer
        TokenKind::Number => { advance(p); return mkNum(t.value); },
        TokenKind::Ident => { advance(p); return mkVar(t.text); },
        TokenKind::LParen => {
            advance(p);
            Expr* inner = parseExpr(p);
            expect(p, TokenKind::RParen, "expected ')'");
            return inner;
        },
        else => { fail(p, "expected an expression", t.pos); advance(p); return mkNum(0); },
    }
}

Result<Expr*, ParseError> parse(str src) {
    // err is initialized to a harmless value; failed gates its use
    Parser p = Parser {
        .toks = tokenize(src), .pos = 0, .failed = false,
        .err = ParseError::TrailingTokens { .pos = 0 }
    };
    Expr* e = parseExpr(&p);
    // any token left before the sentinel is input the grammar did not use
    if (!p.failed && !check(&p, TokenKind::Eof)) {
        p.failed = true;
        p.err = ParseError::TrailingTokens { .pos = peek(&p).pos };
    }
    if (p.failed) return Result<Expr*, ParseError>::Err { .error = p.err };
    return Result<Expr*, ParseError>::Ok { .value = e };
}

void report(ParseError e) {
    // one arm per failure case, so nothing is forgotten
    switch (e) {
        ParseError::Unexpected { what, pos } => println("error at {}: {}", pos, what),
        ParseError::TrailingTokens { pos } => println("error at {}: unexpected extra tokens", pos),
    }
}

void main() {
    str src = "1 + * 3";
    Result<Expr*, ParseError> r = parse(src);
    // explicit propagation: handle the Err before unwrapping
    if (r.isErr()) {
        report(r.unwrapErr());
        return;
    }
    Expr* e = r.unwrap();
    show(e);
    println("");
    freeExpr(e);
}

fail records only the first error and ignores later ones; otherwise a recovering parser piles up cascading messages, all symptoms of one mistake. Result<Expr*, ParseError> never holds a null tree and an error at once.

Cost and notes

Error handling adds constant work per token and leaves O(t) unchanged, since fail is O(1). The error value is small, so returning it by value costs nothing meaningful. Production parsers batch diagnostics, keep a list, and resume at a synchronization point such as the next semicolon.

Edge cases and variations

An empty source parses to Err TrailingTokens, because the sentinel reaches parsePrimary, which reports 'expected an expression' at zero. A stray closing parenthesis or trailing operator is caught at the leftover token. toOp's else is reachable only if the precedence chain already accepted the token, so it never fires. The variation is recovery with a synchronization token: skip to the next ;, discard the partial statement, and continue.

A Tree-Walking Evaluator

The problem

Given a tree from 39.2, compute its integer value by walking it, handling arithmetic, comparison, and negation.

The idea

The evaluator's recursion mirrors the tree. A number evaluates to itself; negation evaluates and negates; a binary node evaluates both children and applies the operator. Comparisons yield 1 or 0, so there is one value type and no coercion. The interesting choices are at the boundaries, such as division by zero.

The implementation

The tree and constructors come from 39.2; only eval and main are new.

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

i64 eval(Expr* e) {
    // bind the variant so its fields are visible to the arms
    Expr node = *e;
    switch (node) {
        Expr::Num { value } => return value,
        // no environment yet: every name is zero
        Expr::Var { name } => return 0,
        Expr::Neg { operand } => return -eval(operand),
        Expr::Bin { op, left, right } => {
            // evaluate children first: this is a postorder walk
            i64 l = eval(left);
            i64 r = eval(right);
            switch (op) {
                // each arm turns two integers into one
                Op::Add => return l + r,
                Op::Sub => return l - r,
                Op::Mul => return l * r,
                // division by zero has no integer answer; define it as 0
                Op::Div => return r == 0 ? 0 : l / r,
                Op::Less => return l < r ? 1 : 0,
                Op::Greater => return l > r ? 1 : 0,
            }
        },
    }
}

void main() {
    // (1 + 2) * (3 - 4) is 3 * -1, which is -3
    Expr* e = mkBin(Op::Mul,
        mkBin(Op::Add, mkNum(1), mkNum(2)),
        mkBin(Op::Sub, mkNum(3), mkNum(4)));
    // show the tree, then its value, on one line
    show(e);
    println(" = {}", eval(e));
    freeExpr(e);
}

The tree-walker is the reference every faster engine is measured against. It is slow because the recursion touches the heap once per node and rediscovers the operator through a runtime switch a compiler would resolve at build time. That gap is what 39.8 closes.

Cost and notes

Time is O(n) in nodes, each eval a call plus a tag switch. Space is O(h) for recursion. Every node is visited once, so a tree of additions is linear; exponential blowups come from re-evaluating shared subtrees, which this representation cannot express.

Edge cases and variations

Division by zero returns 0, a choice rather than a truth: a real language faults, returns an Option, or moves to floating point (Chapter 3). Integer overflow wraps silently. Deeply left-nested input can overflow the stack. The variation is to return Result<i64, EvalError> with a DivisionByZero case.

Variables and an Environment

The problem

Make names meaningful: x = expr stores a value under a name, and a later x reads it back. This also needs statements, because assignment is not an expression.

The idea

Keep a hash map from name to value, the environment, and add a second tree, the statement tree. A program is a sequence of statements; runStmt walks them with the environment in hand. The map is HashMap<str, i64> from Chapter 26, keyed by a source view, safe because the source outlives the run.

The implementation

This adds the Stmt variant and an environment parameter threaded through evaluation; the expression tree and constructors are unchanged from 39.2.

import(lib) std::vec { Vec };
import(lib) std::collections.hashmap { HashMap };
import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

// a program is a list of these; a statement has an effect, not a value
variant Stmt {
    Assign { str name; Expr* value; }
    Print { Expr* value; }
    ExprStmt { Expr* value; }
}

// djb2, the same hash Chapter26 uses for str keys
usize hashStr(str s) {
    // 5381 is the djb2 seed; any odd constant would do
    usize h = 5381;
    for (usize i = 0; i < s.len; i += 1) {
        h = h * 33 + (usize)s.at(i);
    }
    return h;
}

// equality is what disambiguates a hash collision
bool eqStr(str a, str b) { return a.equals(b); }

Stmt* mkAssign(str name, Expr* value) {
    // the name stays a view; the source outlives the environment here
    Stmt* s = alloc<Stmt>(1);
    *s = Stmt::Assign { .name = name, .value = value };
    return s;
}

Stmt* mkPrint(Expr* value) {
    Stmt* s = alloc<Stmt>(1);
    // printing is a statement because it is an effect
    *s = Stmt::Print { .value = value };
    return s;
}

Stmt* mkExprStmt(Expr* value) {
    // an expression used only for its own value
    Stmt* s = alloc<Stmt>(1);
    *s = Stmt::ExprStmt { .value = value };
    return s;
}

// evaluation now threads the environment through every call
i64 eval(Expr* e, HashMap<str, i64>* env) {
    Expr node = *e;
    switch (node) {
        Expr::Num { value } => return value,
        // an unbound name reads as zero, so evaluation is total
        Expr::Var { name } => return env->get(name).unwrapOr(0),
        Expr::Neg { operand } => return -eval(operand, env),
        Expr::Bin { op, left, right } => {
            i64 l = eval(left, env);
            i64 r = eval(right, env);
            switch (op) {
                Op::Add => return l + r,
                Op::Sub => return l - r,
                Op::Mul => return l * r,
                Op::Div => return r == 0 ? 0 : l / r,
                Op::Less => return l < r ? 1 : 0,
                Op::Greater => return l > r ? 1 : 0,
            }
        },
    }
}

// statements perform effects; they do not return a value
void runStmt(Stmt* s, HashMap<str, i64>* env) {
    Stmt st = *s;
    switch (st) {
        Stmt::Assign { name, value } => {
            // the insert result is ignored: i64 values cannot fail to store
            env->insert(name, eval(value, env));
        },
        Stmt::Print { value } => println("{}", eval(value, env)),
        Stmt::ExprStmt { value } => eval(value, env),
    }
}

void main() {
    HashMap<str, i64> env = HashMap<str, i64>::new(hashStr, eqStr);
    // the backing store is a plain vector of statement pointers
    Vec<Stmt*> program = Vec<Stmt*>::new();
    // x = 10; y = x * x + 5; print y;
    program.push(mkAssign("x", mkNum(10)));
    program.push(mkAssign("y",
        mkBin(Op::Add, mkBin(Op::Mul, mkVar("x"), mkVar("x")), mkNum(5))));
    program.push(mkPrint(mkVar("y")));
    // run statements in order, all sharing one environment
    for (usize i = 0; i < program.count(); i += 1) {
        runStmt(program.at(i), &env);
    }
    println("x = {}", env.get("x").unwrapOr(0));
    // the map owns heap storage that must be released by hand
    env.dispose();
}

The environment is threaded as a pointer because every statement shares and mutates the same map, the one state outside the tree. runStmt being separate from eval is the moment the language stops being an expression calculator and becomes a sequence of effects.

Cost and notes

Each assignment and read is an O(1) average hash operation, so a program of length p is O(p) evaluations plus O(p) map work. The map grows with distinct variables, not assignments. The str key is safe only because the source outlives the run; 39.9 solves the dangling case with owned String keys.

Edge cases and variations

Reading before assignment yields 0 via unwrapOr(0); a stricter language returns Result. Reassigning replaces in place. The environment is disposed by hand because HashMap storage is not returned automatically. The variation is scope: a stack of nested environments, pushed on entry and popped on exit, searched innermost outward.

Control Flow: if and while

The problem

Let statements decide what runs next: if chooses between two blocks, and while repeats a block while a condition holds.

The idea

Add a Block, a sequence of statements, and two statement cases pointing at blocks. if evaluates its condition and runs one block; while re-evaluates before every pass and runs the body while nonzero. Since the body is a list of statements and runStmt is recursive, nesting is free.

The implementation

This extends the Stmt variant and runStmt of 39.6; the environment and expression evaluator are unchanged.

import(lib) std::vec { Vec };
import(lib) std::collections.hashmap { HashMap };
import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

// a block is just a sequence of statements, so nesting is free
struct Block { Vec<Stmt*> stmts; }

variant Stmt {
    Assign { str name; Expr* value; }
    Print { Expr* value; }
    ExprStmt { Expr* value; }
    If { Expr* cond; Block* thenBody; Block* elseBody; }
    // while has no else: either the body runs or it does not
    While { Expr* cond; Block* body; }
}

Block* mkBlock(Vec<Stmt*> stmts) {
    Block* b = alloc<Block>(1);
    // ownership of the vector moves into the block
    b->stmts = stmts;
    return b;
}

Stmt* mkIf(Expr* cond, Block* thenBody, Block* elseBody) {
    // a null elseBody is the "no else clause" case
    Stmt* s = alloc<Stmt>(1);
    *s = Stmt::If { .cond = cond, .thenBody = thenBody, .elseBody = elseBody };
    return s;
}

Stmt* mkWhile(Expr* cond, Block* body) {
    Stmt* s = alloc<Stmt>(1);
    *s = Stmt::While { .cond = cond, .body = body };
    return s;
}

void runBlock(Block* b, HashMap<str, i64>* env) {
    // statements run left to right, sharing the environment
    for (usize i = 0; i < b->stmts.count(); i += 1) {
        runStmt(b->stmts.at(i), env);
    }
}

// now five cases, two of which recurse into blocks
void runStmt(Stmt* s, HashMap<str, i64>* env) {
    Stmt st = *s;
    switch (st) {
        Stmt::Assign { name, value } => { env->insert(name, eval(value, env)); },
        Stmt::Print { value } => println("{}", eval(value, env)),
        Stmt::ExprStmt { value } => eval(value, env),
        Stmt::If { cond, thenBody, elseBody } => {
            // a null elseBody means there was no else clause
            if (eval(cond, env) != 0) runBlock(thenBody, env);
            else if (elseBody != null) runBlock(elseBody, env);
        },
        Stmt::While { cond, body } => {
            // re-test before every pass, so the condition can change
            while (eval(cond, env) != 0) runBlock(body, env);
        },
    }
}

void main() {
    HashMap<str, i64> env = HashMap<str, i64>::new(hashStr, eqStr);
    Vec<Stmt*> program = Vec<Stmt*>::new();
    // sum = 0; i = 1; while (i < 6) { sum = sum + i; i = i + 1; } print sum;
    Vec<Stmt*> body = Vec<Stmt*>::new();
    // the loop body adds i to sum, then advances i
    body.push(mkAssign("sum", mkBin(Op::Add, mkVar("sum"), mkVar("i"))));
    body.push(mkAssign("i", mkBin(Op::Add, mkVar("i"), mkNum(1))));
    program.push(mkAssign("sum", mkNum(0)));
    program.push(mkAssign("i", mkNum(1)));
    program.push(mkWhile(mkBin(Op::Less, mkVar("i"), mkNum(6)), mkBlock(body)));
    program.push(mkPrint(mkVar("sum")));
    for (usize i = 0; i < program.count(); i += 1) {
        runStmt(program.at(i), &env);
    }
    env.dispose();
}

runStmt and runBlock are mutually recursive. Here runStmt inlines the block loop rather than calling runBlock, keeping recursion single-function and definition order valid. elseBody is null when there is no else, checked explicitly; an Option<Block*> would make forgetting impossible at compile time.

Cost and notes

The interpreter's cost is the program's cost: each iteration is one condition evaluation plus one block execution, with no compilation to amortize. Recursion depth is block nesting depth, not loop count, because while is a loop, not a recursive call.

Edge cases and variations

A while whose condition is initially zero runs zero times. An if with no else and a false condition does nothing. Because conditions are integers, while 1 { ... } loops forever with no break; adding break means giving runBlock a signal return rather than void. The other variation is for, desugared to a while with initializer and increment, implemented entirely in the parser.

A Tiny Stack-Based Bytecode VM

The problem

Walking a tree is simple but slow: every node costs a recursive call and a runtime tag switch. Compile the tree once to a flat instruction sequence and run that.

The idea

A stack machine: instructions push values, operators pop operands and push results. Compiling an expression is a postorder walk: emit left, right, then the operator, so operands are on the stack when the operator runs. The tree is read once at compile time; run time is a loop and an array, no recursion or tags.

The implementation

The tree and constructors come from 39.2; the evaluator is replaced by a compiler and a machine.

import(lib) std::vec { Vec };
import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

// one opcode per operation, plus Push and a Halt terminator
enum OpCode { Push, Neg, Add, Sub, Mul, Div, Less, Greater, Halt }

struct Instr {
    // arg is used only by Push; every other opcode ignores it
    OpCode op;
    i64 arg;
}

struct Compiler {
    Vec<Instr> code;
}

void emit(Compiler* c, OpCode op, i64 arg) {
    // append one instruction to the growing program
    c->code.push(Instr { .op = op, .arg = arg });
}

// a tree operator and a machine opcode are different types
OpCode opToCode(Op op) {
    switch (op) {
        Op::Add => return OpCode::Add,
        Op::Sub => return OpCode::Sub,
        Op::Mul => return OpCode::Mul,
        Op::Div => return OpCode::Div,
        Op::Less => return OpCode::Less,
        Op::Greater => return OpCode::Greater,
    }
}

void compile(Compiler* c, Expr* e) {
    Expr node = *e;
    switch (node) {
        // a literal becomes a push of its own value
        Expr::Num { value } => emit(c, OpCode::Push, value),
        // variables are not compiled yet: they push zero
        Expr::Var { name } => emit(c, OpCode::Push, 0),
        Expr::Neg { operand } => { compile(c, operand); emit(c, OpCode::Neg, 0); },
        Expr::Bin { op, left, right } => {
            // postorder: operands first, operator last
            compile(c, left);
            compile(c, right);
            emit(c, opToCode(op), 0);
        },
    }
}

void apply(Vec<i64>* stack, OpCode op) {
    // operands come off in reverse order of how they were pushed
    // the right operand was pushed last, so it pops first
    i64 r = stack->pop();
    i64 l = stack->pop();
    switch (op) {
        OpCode::Add => stack->push(l + r),
        OpCode::Sub => stack->push(l - r),
        OpCode::Mul => stack->push(l * r),
        OpCode::Div => stack->push(r == 0 ? 0 : l / r),
        OpCode::Less => stack->push(l < r ? 1 : 0),
        OpCode::Greater => stack->push(l > r ? 1 : 0),
        // Push, Neg, and Halt are handled by the machine, not here
        else => stack->push(0),
    }
}

i64 run(const Vec<Instr>* code) {
    Vec<i64> stack = Vec<i64>::new();
    // the machine is a flat array, an index, and a value stack
    for (usize i = 0; i < code->count(); i += 1) {
        Instr in = code->at(i);
        switch (in.op) {
            OpCode::Push => stack.push(in.arg),
            // unary negate needs only the top of the stack
            OpCode::Neg => stack.push(-stack.pop()),
            OpCode::Add | OpCode::Sub | OpCode::Mul | OpCode::Div
                | OpCode::Less | OpCode::Greater => apply(&stack, in.op),
            OpCode::Halt => break,
        }
    }
    // a well-formed program leaves exactly one value on the stack
    return stack.pop();
}

void main() {
    // (1 + 2 * 3) - 4 compiles to five pushes and three operators
    Expr* e = mkBin(Op::Sub,
        mkBin(Op::Add, mkNum(1), mkBin(Op::Mul, mkNum(2), mkNum(3))),
        mkNum(4));
    // compilation happens once; the machine then replays the array
    Compiler c = Compiler { .code = Vec<Instr>::new() };
    compile(&c, e);
    println("{} instructions", c.code.count());
    println("result {}", run(&c.code));
    freeExpr(e);
}

The multi-case arm Add | Sub | Mul | Div | Less | Greater => apply(...) is the payoff: six operators dispatch through one call, and a seventh means one new OpCode case and one line in apply. The machine has no idea it runs a tree; it has an array and an index. This is the split a real compiler makes twice, tree to bytecode and bytecode to machine code.

Cost and notes

Compilation is one O(n) postorder pass. Execution is O(k) instructions, each a constant-time stack operation plus one array access, with no recursion or per-step heap. The win over tree-walking is the absence of per-node calls and tag dispatch. Production VMs use direct threading to remove the loop overhead.

Edge cases and variations

An empty program, or one not ending in Halt, falls off the loop and returns whatever is on the stack, which is why a real compiler always appends Halt. Div by zero pushes 0 through the same guard as 39.5. Popping an empty stack is undetected; a defensive version checks depth before every pop, which also validates untrusted bytecode. The variation is variables: add Load and Store opcodes resolved in a compile-time scope pass.

A REPL on stdin

The problem

Wire the pipeline into a read-eval-print loop that reads a line, parses it as a statement, runs it against a persistent environment, and prints the result: the smallest complete language front end.

The idea

Everything is written: the tokenizer, tree, error-carrying parser extended with statements, and the environment and evaluator. The new problem is ownership. A REPL reuses one input buffer, so a name captured during parsing would dangle when the next line overwrites it. The environment therefore owns its keys, storing String, not str.

The implementation

This is the full assembly. It parses three statement forms, print, assignment, and a bare expression, which a REPL echoes; if and while are left to 39.7 as an exercise.

import(lib) std::vec { Vec };
import(lib) std::text::string { String };
import(lib) std::collections.hashmap { HashMap };
import(lib) std::mman { alloc, dealloc };
import(lib) std::result { Result };
import(lib) std::io::ios { println, readLine };

// the tokenizer, tree, and parser helpers are as in 39.1 through 39.6
variant ParseError {
    Unexpected { str what; usize pos; }
    TrailingTokens { usize pos; }
}

// a fresh parser per line; the environment persists across lines
struct Parser {
    Vec<Token> toks;
    usize pos;
    // failed latches once per line; the first error is kept
    bool failed;
    ParseError err;
}

void fail(Parser* p, str what, usize pos) {
    // first error wins; later ones are usually downstream symptoms
    if (p->failed) return;
    p->failed = true;
    p->err = ParseError::Unexpected { .what = what, .pos = pos };
}

// expect consumes the wanted token or records an error and moves on
Token expect(Parser* p, TokenKind k, str what) {
    if (check(p, k)) return advance(p);
    Token t = peek(p);
    fail(p, what, t.pos);
    return t;
}

// the statement grammar is deliberately small: three forms
Stmt* parseStatement(Parser* p) {
    // print is a keyword, so it is recognized before names
    if (check(p, TokenKind::Print)) {
        advance(p);
        Expr* value = parseExpr(p);
        expect(p, TokenKind::Semi, "expected ';' after print");
        return mkPrint(value);
    }
    // a leading name followed by '=' is an assignment
    if (check(p, TokenKind::Ident)) {
        Token name = peek(p);
        if (p->toks.at(p->pos + 1).kind == TokenKind::Assign) {
            advance(p);
            advance(p);
            Expr* value = parseExpr(p);
            expect(p, TokenKind::Semi, "expected ';' after assignment");
            return mkAssign(name.text, value);
        }
    }
    // anything else is an expression statement, which a REPL echoes
    Expr* value = parseExpr(p);
    expect(p, TokenKind::Semi, "expected ';'");
    return mkExprStmt(value);
}

Result<Stmt*, ParseError> parseLine(str src) {
    Parser p = Parser {
        .toks = tokenize(src), .pos = 0, .failed = false,
        .err = ParseError::TrailingTokens { .pos = 0 }
    };
    Stmt* s = parseStatement(&p);
    if (!p.failed && !check(&p, TokenKind::Eof)) {
        p.failed = true;
        p.err = ParseError::TrailingTokens { .pos = peek(&p).pos };
    }
    if (p.failed) return Result<Stmt*, ParseError>::Err { .error = p.err };
    return Result<Stmt*, ParseError>::Ok { .value = s };
}

// the environment owns its keys, because the input line is reused
usize hashString(String key) {
    // hash the bytes the String owns, via a borrowed view
    str s = key.asView();
    usize h = 5381;
    for (usize i = 0; i < s.len; i += 1) {
        h = h * 33 + (usize)s.at(i);
    }
    return h;
}

// compare contents, not pointers: two copies of "x" are equal
bool eqString(String a, String b) { return a.equalsView(b.asView()); }

void assign(HashMap<String, i64>* env, str name, i64 value) {
    // copy the name so it survives the next readLine
    String key = String::from(name);
    bool existed = env->get(key).isSome();
    env->insert(key, value);
    // on overwrite the map keeps its old key, so this copy is redundant
    if (existed) key.free();
}

i64 lookup(HashMap<String, i64>* env, str name) {
    // the map is keyed by owned String, so build a temporary key
    String key = String::from(name);
    i64 v = env->get(key).unwrapOr(0);
    // the temporary key is freed as soon as the lookup finishes
    key.free();
    return v;
}

// the evaluator is identical to 39.6 except for the key type
i64 eval(Expr* e, HashMap<String, i64>* env) {
    Expr node = *e;
    switch (node) {
        Expr::Num { value } => return value,
        Expr::Var { name } => return lookup(env, name),
        Expr::Neg { operand } => return -eval(operand, env),
        Expr::Bin { op, left, right } => {
            i64 l = eval(left, env);
            i64 r = eval(right, env);
            switch (op) {
                Op::Add => return l + r,
                Op::Sub => return l - r,
                Op::Mul => return l * r,
                Op::Div => return r == 0 ? 0 : l / r,
                Op::Less => return l < r ? 1 : 0,
                Op::Greater => return l > r ? 1 : 0,
            }
        },
    }
}

// three statement forms in the REPL
void runStmt(Stmt* s, HashMap<String, i64>* env) {
    Stmt st = *s;
    switch (st) {
        Stmt::Assign { name, value } => assign(env, name, eval(value, env)),
        // at a terminal, a print and a bare expression both show a value
        Stmt::Print { value } => println("{}", eval(value, env)),
        Stmt::ExprStmt { value } => println("{}", eval(value, env)),
    }
}

void report(ParseError e) {
    // errors report a byte offset into the current line
    switch (e) {
        ParseError::Unexpected { what, pos } => println("error at {}: {}", pos, what),
        ParseError::TrailingTokens { pos } => println("error at {}: trailing tokens", pos),
    }
}

void main() {
    HashMap<String, i64> env = HashMap<String, i64>::new(hashString, eqString);
    // one reused buffer holds every line the user types
    String line = String::new();
    println("tiny repl; type statements, ctrl-d to quit");
    // readLine returns false only at end of input
    while (readLine(&line)) {
        // a blank line produces no statement and no output
        if (line.isEmpty()) continue;
        Result<Stmt*, ParseError> r = parseLine(line.asView());
        // a bad line is reported and skipped; the session continues
        if (r.isErr()) {
            report(r.unwrapErr());
            continue;
        }
        runStmt(r.unwrap(), &env);
    }
    line.free();
    env.dispose();
}

Ownership is the heart of this section. The tree's names are str views into line, correct while the statement runs, before the next read. But the environment outlives the line: a variable set on line one must read back on line fifty. So assign copies the name into an owned String, while lookup builds a temporary key and frees it immediately. This is Chapter 10's borrow-versus-own split: the tree borrows, the environment owns.

Cost and notes

Each line is lexed, parsed, and run in time proportional to its length, and the environment costs an O(1) average hash operation per statement. The only new cost is the String copy on each assignment and lookup; assignments are rare and lookups short, so it is negligible and buys correctness. The REPL holds no state between lines except the environment.

Edge cases and variations

A blank line is skipped before parsing. A final line without a newline is still processed, because readLine returns true after reading any bytes. A parse error prints its position and leaves the environment untouched. Freeing line and disposing env releases everything. The variations are to add if and while by reusing 39.7's arms, to keep a history and re-run the last statement on an empty line, and to swap the tree-walker for the bytecode VM of 39.8, which changes only runStmt.
