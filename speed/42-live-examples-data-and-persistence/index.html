Live Examples: Data and Persistence

Bytes That Outlive the Process

Memory dies with the process. Persistence moves data into files a later run or another program can read back. This chapter builds nine tools: CSV writer and reader, quoted-field parser, key=value config loader, JSON-like serializer, fixed-layout binary record, CRC32 checksum, append-only key-value store, key-to-offset index, and atomic temp-file swap.

A file is bytes made meaningful by a contract: layout, encoding, order. Writing encodes values; reading decodes them. Most persistence bugs break the contract on one side only: byte order, character versus byte lengths, quoting. Each example keeps its contract small enough to hold in your head.

std::io::fs provides fileOpen, fileRead, fileWrite, fileSeek, readFileToString, and writeFileFromString; formats above it are yours. std::fmt::format is a stub, so text uses String plus formatInt and formatFloat. Writing bytes is not making them durable, and a rename is atomic only under conditions the code cannot check; each disk section states its guarantee.

Imports: std::io::fs for File, IoError, the open/read/write/seek family, and O_*/SEEK_*; std::text::strutil for splitVec, trim, and indexOfChar; std::fmt::fmt for formatInt and formatFloat; std::collections::hashmap { HashMap } for maps. Vec and str are prelude names; println is prelude-imported.

Writing and Reading a CSV File

The problem

You have a table of records in memory and want them as comma-separated values, one record per line, in a file you can read back.

CSV is line-oriented: each line is a record, each field separated by commas. A field containing a comma, newline, or double quote must be wrapped in quotes with inner quotes doubled. A writer that ignores this produces a file a strict reader splits wrongly. The example writes the rule once, in csvField, and uses it for every field.

import(lib) std::io::fs { fileOpen, fileClose, fileWrite, writeFileFromString,
                           readFileToString, File, IoError };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };
import(lib) std::text::strutil { splitVec, trim };
import(lib) std::fmt::fmt { formatInt, formatFloat };
import(lib) std::vec { Vec };

struct Row {
    str name;
    i32 age;
    f64 score;
}

void csvField(String* out, str field) {
    // Quote the field only when a comma, quote, or newline would split it.
    bool needsQuotes = field.containsByte((u8)',') ||
                       field.containsByte((u8)'"') ||
                       field.containsByte((u8)'\n');
    // Bare field: copy the bytes through unchanged.
    if (!needsQuotes) {
        out->appendView(field);
        return;
    }
    // Quoted field: wrap it and double any embedded quote.
    out->pushChar((u8)'"');
    for (usize i = 0; i < field.len; i += 1) {
        u8 c = field.at(i);
        if (c == (u8)'"') out->pushChar((u8)'"');   // a quote becomes two
        out->pushChar(c);
    }
    out->pushChar((u8)'"');
}

String csvFromRows(const Vec<Row>* rows) {
    // Header line first, then one line per record.
    String out = String::from("name,age,score");
    for (usize i = 0; i < rows->count(); i += 1) {
        out.pushChar((u8)'\n');
        Row r = rows->at(i);
        // The name is the only field that may need quoting.
        csvField(&out, r.name);
        out.pushChar((u8)',');
        // Integers and floats become ASCII digits via the fmt helpers.
        String age = formatInt((i64)r.age, 10u, false);
        out.appendView(age.asView());
        out.pushChar((u8)',');
        String score = formatFloat(r.score, 2u);
        out.appendView(score.asView());
    }
    return out;
}

void main() {
    Vec<Row> rows = Vec<Row>::new();
    rows.push(Row { .name = "Ada Lovelace", .age = 36, .score = 91.5 });
    rows.push(Row { .name = "Grace \"Amazing\" Hopper", .age = 45, .score = 99.25 });

    String csv = csvFromRows(&rows);
    String path = String::from("/tmp/coral-people.csv");

    // Mode "w" creates or truncates the file, then writes the buffer whole.
    Result<bool, IoError> wr = writeFileFromString(path.asView(), &csv);
    // Error path: the write failed, so stop before reading.
    if (wr.isErr()) { println("write failed"); return; }
    println("wrote {} bytes", csv.len);

    // Read the entire file back into an owned buffer.
    Result<String, IoError> rr = readFileToString(path.asView());
    // Error path: nothing to parse if the read failed.
    if (rr.isErr()) { println("read failed"); return; }
    String back = rr.unwrap();
    // Split on newlines; the trailing newline yields one empty line.
    Vec<str> lines = splitVec(back.asView(), (u8)'\n');
    for (usize i = 0; i < lines.count(); i += 1) {
        str line = lines.at(i);
        // Skip the empty field after the final newline.
        if (line.len == 0) continue;
        println("line {}: {}", i, line);
    }
}

csvField is the whole contract: a field is bare unless it contains a comma, quote, or newline, in which case it is wrapped and its quotes doubled. csvFromRows writes the header then each row, using formatInt and formatFloat. writeFileFromString writes the finished buffer in one call; readFileToString reads it back.

Cost and notes

Encoding is O(total bytes) with one append per byte run. Text wastes space (an i32 can cost eleven bytes instead of four) and every read pays to parse, but it buys inspectability across programs and decades.

Edge cases and variations

A reader handling the escaping (41.2) agrees with this writer. A field containing \r is not quoted, fine when splitting on \n; a Windows-targeting writer should quote both. CSV does not trim, so spaces are preserved. A real writer would reject NaN rather than print nan. An empty table still emits the header, giving readers column names.

Parsing Quoted CSV with a State Machine

The problem

You have a CSV file, possibly from the previous section or a spreadsheet, and need its fields as slices without copying. A naive splitVec(..., ',') cannot tell a separator from a comma inside quotes.

A CSV parser is a tiny state machine: inside a bare field or a quoted one; inside quotes, a quote either closes the field or, if doubled, is literal. Quoted content is a view into the input, so the buffer must stay alive and unmodified; output built by appending must reserve up front, because growing a String can move its bytes and invalidate earlier views.

import(lib) std::io::fs { readFileToString, IoError };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };
import(lib) std::text::strutil { splitVec };
import(lib) std::vec { Vec };

// A parsed field, plus whether it was written in quotes.
struct Field {
    str text;
    bool quoted;
}

// Parse one line into fields; quoted fields may hold commas.
Vec<Field> parseCsvLine(str line) {
    Vec<Field> fields = Vec<Field>::new();
    usize i = 0;
    // Walk the line; i is the position of the next unread byte.
    while (i <= line.len) {
        if (i == line.len) {
            break;
        }
        // A leading quote begins a quoted field.
        if (line.at(i) == (u8)'"') {
            i += 1;
            usize start = i;
            // A quoted field cannot be returned as a single view if it
            // contains doubled quotes, so build only when needed.
            usize extraQuotes = 0;
            usize scan = i;
            // Scan to the closing quote, skipping doubled pairs.
            while (scan < line.len) {
                if (line.at(scan) == (u8)'"') {
                    if (scan + 1 < line.len && line.at(scan + 1) == (u8)'"') {
                        extraQuotes += 1;
                        scan += 2;
                        continue;
                    }
                    break;
                }
                scan += 1;
            }
            // No escapes: the field is a zero-copy slice of the line.
            if (extraQuotes == 0) {
                fields.push(Field { .text = line.slice(start, scan),
                                    .quoted = true });
            } else {
                // Escaped: build a decoded copy of the field.
                usize cap = (scan - start) - extraQuotes;
                // Reserve exactly once so views into buf stay valid.
                String buf = String::withCap(cap + 1);
                usize p = start;
                while (p < scan) {
                    if (line.at(p) == (u8)'"' && p + 1 < scan &&
                        line.at(p + 1) == (u8)'"') {
                        buf.pushChar((u8)'"');
                        p += 2;
                    } else {
                        buf.pushChar(line.at(p));
                        p += 1;
                    }
                }
                fields.push(Field { .text = buf.asView(), .quoted = true });
            }
            // Skip the closing quote and, if present, the comma.
            i = scan + 1;
            if (i < line.len && line.at(i) == (u8)',') i += 1;
        } else {
            // Bare field: scan to the next comma.
            usize start = i;
            while (i < line.len && line.at(i) != (u8)',') i += 1;
            fields.push(Field { .text = line.slice(start, i),
                                .quoted = false });
            if (i < line.len) i += 1;
        }
    }
    return fields;
}

void describe(str line) {
    Vec<Field> fs = parseCsvLine(line);
    // Header count, then one indented line per field.
    println("{} fields:", fs.count());
    for (usize i = 0; i < fs.count(); i += 1) {
        Field f = fs.at(i);
        println("  [{}] {}{}", i, if (f.quoted) "Q " else "B ", f.text);
    }
}

void main() {
    // Exercise bare, escaped, embedded-comma, and empty lines.
    describe("Ada Lovelace,36,91.5");
    describe("\"Grace \"\"Amazing\"\" Hopper\",45,99.25");
    describe("\"a,b\",c");
    describe("");
}

The outer loop alternates: a quote starts a quoted field, scanned to its closing quote with doubled quotes collapsed; otherwise a bare field is scanned to the next comma. A quoted field without doubled quotes is a slice of the line, no copy. Only when quotes must be collapsed is a scratch String built, pre-sized with withCap(cap + 1) so storage is allocated once and never reallocated while its view is stretched. That line separates a working parser from one producing a dangling view when the buffer grows.

Cost and notes

Each line is one pass, O(bytes), usually allocating only the Vec<Field>. Unquoted and unescaped cases cost nothing beyond the slice; the escaped case costs one allocation per field. The parser copies nothing else, so line must outlive the fields. String literals in main live for the whole program; a caller reading a real buffer must keep it alive while any returned str is used.

Edge cases and variations

A trailing comma produces a final empty field, correct for "a,". An empty line produces zero fields; a stricter reader might return one empty field, and spreadsheets disagree. A quote mid-field is treated literally; dialects differ. Quoted fields broken across lines are unsupported, the price of line-by-line parsing; whole-file parsing must carry the inside-quotes state across \n. withCap(cap + 1) reserves one byte for a terminator asView does not need, but the slack keeps the invariant obvious.

A key=value Configuration File

The problem

A program needs a few user-editable settings: a host, a port, a retry count. The smallest useful format is one key=value per line, ignoring blank lines and lines beginning with #.

The idea

Read the whole file into one buffer, split into lines, and for each non-blank line find the first =; trimmed text left is the key, right is the value. Store pairs in a hash map keyed by key text. Split on the first =, so values may contain =; the map holds str views into the buffer, so the buffer must outlive it. A duplicate key takes the later assignment.

The implementation.

import(lib) std::io::fs { readFileToString, writeFileFromString, IoError };
import(lib) std::io::ios { println, parseU64 };
import(lib) std::text::string { String };
import(lib) std::text::strutil { splitVec };
import(lib) std::collections::hashmap { HashMap };
import(lib) std::option { Option };
import(lib) std::vec { Vec };

// Hash and equality for str keys. The map stores borrowed views, so the
// whole config buffer must outlive it (see main); eq must match hash.
usize hashView(str s) {
    usize h = 5381;
    // Fold each byte into the running hash.
    for (usize i = 0; i < s.len; i += 1)
        h = h * 33 + (usize)s.at(i);         // djb2: cheap, spreads bytes
    return h;
}

// Equality must match hashView, or lookups miss.
bool eqView(str a, str b) {
    return a.equals(b);                      // consistent with hashView
}

// Parse the whole buffer into a map of views.
HashMap<str, str> parseConfig(str text) {
    HashMap<str, str> cfg = HashMap<str, str>::new(hashView, eqView);
    Vec<str> lines = splitVec(text, (u8)'\n');
    for (usize i = 0; i < lines.count(); i += 1) {
        // Trim surrounding whitespace before deciding.
        str line = lines.at(i).trim();       // drop edge whitespace
        if (line.len == 0) continue;         // blank line
        if (line.at(0) == (u8)'#') continue; // comment line
        // Split on the first '=', so a value may itself contain '='.
        usize eq = line.findByte((u8)'=');
        if (eq >= line.len) continue;        // no '=' => not an assignment
        // Key and value are trimmed slices of the buffer.
        str key = line.slice(0, eq).trim();
        str val = line.slice(eq + 1, line.len).trim();
        if (key.len == 0) continue;          // refuse an empty key
        cfg.insert(key, val);                // duplicate key: last wins
    }
    return cfg;
}

// Typed accessor: default on a missing key or a malformed number.
u64 getConfigU64(HashMap<str, str>* cfg, str key, u64 fallback) {
    Option<str> v = cfg->get(key);
    if (v.isNone()) return fallback;         // absent key uses the default
    bool ok;
    // parseU64 signals failure through its bool out-parameter.
    u64 n = parseU64(v.unwrap(), &ok);
    return ok ? n : fallback;                // malformed value -> default
}

void main() {
    String sample = String::from("# coral demo\nhost = localhost\nport = 8080\nretries=5\n");
    String path = String::from("/tmp/coral.conf");
    writeFileFromString(path.asView(), &sample);

    // Read it back; text owns the bytes the map will view.
    Result<String, IoError> rr = readFileToString(path.asView());
    if (rr.isErr()) { println("cannot read config"); return; }
    String text = rr.unwrap();               // owns the bytes the map views

    // Parse into a map whose keys and values borrow text.
    HashMap<str, str> cfg = parseConfig(text.asView());
    println("keys {}", cfg.count());
    Option<str> host = cfg.get("host");
    if (host.isSome()) println("host = {}", host.unwrap());
    println("port = {}", getConfigU64(&cfg, "port", 80u));
    println("retries = {}", getConfigU64(&cfg, "retries", 3u));
    println("missing = {}", getConfigU64(&cfg, "missing", 7u));
}

The parser allocates per entry only through the map's table, because every key and value is a slice of text. line.trim() removes spaces around =, findByte locates the separator, and two slice calls carve the halves. The >= line.len test is the parse guard: findByte returns the length when the byte is absent. getConfigU64 looks up the raw string, parses it, and falls back to a default on absence or malformed text.

Cost and notes

Reading and splitting is O(total bytes); the map is O(1) average per lookup. Values are views, so the steady cost is one hash map. getConfigU64 parses on demand, fine for startup; a hot path should parse once into a struct. parseU64 takes a bool* out-parameter, the prelude convention for fast numeric parsers.

Edge cases and variations

An empty value (key=) yields an empty view, which parseU64 rejects so the default applies. A line with no = is skipped silently; a stricter parser would report it. The # test is on the first non-space byte, so # note is a comment but key=#value keeps the #. There are no sections, quoting, or escapes for = or #. To layer an override file, parse the base and then the overlay into the same map, letting later inserts win.

A Hand-Rolled JSON-like Serializer

The problem

You have a small struct and want it in another program or file in a readable, parseable format. With no reflection, write the object field by field, plus the matching reader.

The idea

Serialization walks the fields: write "name":, the escaped string, ,"port":, the integer, and so on. Deserialization reads a quoted key, the colon, a value, and dispatches on the key. String escaping is the CSV quoting contract: the writer protects " and \, and the reader undoes exactly that. This is a subset: objects only, one level deep, string/integer/boolean values, no arrays, floats, null, or \u escapes.

The implementation.

import(lib) std::io::ios { println, parseI64 };
import(lib) std::text::string { String };
import(lib) std::fmt::fmt { formatInt };

struct Server {
    String name;                             // owned, so it outlives `json`
    i32 port;
    bool tls;
}

// Write `s` as a JSON string: wrap in quotes, escape " and \ and newline.
void jsonEscape(String* out, str s) {
    out->pushChar((u8)'"');
    for (usize i = 0; i < s.len; i += 1) {
        u8 c = s.at(i);
        if (c == (u8)'"' || c == (u8)'\\') {
            out->pushChar((u8)'\\');         // a backslash before the byte
            out->pushChar(c);
        // A newline becomes the two-character escape \n.
        } else if (c == (u8)'\n') {
            out->appendView("\\n");          // two characters for a newline
        } else {
            out->pushChar(c);                // ordinary byte passes through
        }
    }
    out->pushChar((u8)'"');
}

// Serialize the struct field by field, in a fixed order.
String jsonFromServer(const Server* s) {
    String out = String::from("{");
    out.appendView("\"name\":");
    jsonEscape(&out, s->name.asView());
    out.appendView(",\"port\":");
    String p = formatInt((i64)s->port, 10u, false);
    out.appendView(p.asView());
    out.appendView(",\"tls\":");
    out.appendView(s->tls ? "true" : "false");
    out.pushChar((u8)'}');
    return out;
}

// Read a JSON string beginning at json.at(i) == '"'; unescape into `out`
// and return the index just past the closing quote.
usize jsonReadString(str json, usize i, String* out) {
    i += 1;                                  // skip the opening quote
    while (i < json.len) {
        u8 c = json.at(i);
        if (c == (u8)'"') { i += 1; break; } // closing quote ends it
        // A backslash begins a two-byte escape sequence.
        if (c == (u8)'\\' && i + 1 < json.len) {
            u8 e = json.at(i + 1);
            if (e == (u8)'n') out->pushChar((u8)'\n');
            else out->pushChar(e);           // \" and \\ map to themselves
            i += 2;                          // consume the pair
        } else {
            out->pushChar(c);
            i += 1;
        }
    }
    return i;
}

// Advance i past JSON's insignificant whitespace.
void jsonSkipSpace(str json, usize* i) {
    while (*i < json.len) {
        u8 c = json.at(*i);
        if (c == (u8)' ' || c == (u8)'\t' || c == (u8)'\n') *i += 1;
        else break;
    }
}

// Parse an object into the struct, keyed by field name.
bool jsonToServer(str json, Server* out) {
    usize i = 0;
    jsonSkipSpace(json, &i);
    if (i >= json.len || json.at(i) != (u8)'{') return false;
    i += 1;                                  // past the opening brace
    while (i < json.len) {
        jsonSkipSpace(json, &i);
        // A closing brace means the object is complete.
        if (i < json.len && json.at(i) == (u8)'}') return true;  // done
        if (i >= json.len || json.at(i) != (u8)'"') return false;
        String key = String::withCap(16);    // scratch key, freed below
        i = jsonReadString(json, i, &key);
        jsonSkipSpace(json, &i);
        // A missing colon means malformed input.
        if (i >= json.len || json.at(i) != (u8)':') { key.free(); return false; }
        i += 1;                              // consume the colon
        jsonSkipSpace(json, &i);
        // Dispatch on the key name, not its position.
        if (key.asView().equals("name")) {
            out->name.clear();
            i = jsonReadString(json, i, &out->name);
        } else if (i < json.len && json.at(i) == (u8)'"') {
            String discard = String::new();  // unknown string: read and drop
            i = jsonReadString(json, i, &discard);
            discard.free();
        } else {
            // Otherwise read a bare token up to ',' or '}'.
            usize start = i;
            while (i < json.len && json.at(i) != (u8)',' && json.at(i) != (u8)'}') i += 1;
            str token = json.slice(start, i).trim();
            bool ok;
            i64 n = parseI64(token, &ok);
            // Assign only the matching key.
            if (ok && key.asView().equals("port")) out->port = (i32)n;
            if (token.equals("true") && key.asView().equals("tls")) out->tls = true;
            if (token.equals("false") && key.asView().equals("tls")) out->tls = false;
        }
        key.free();
        jsonSkipSpace(json, &i);
        // A comma separates this pair from the next.
        if (i < json.len && json.at(i) == (u8)',') i += 1;  // next pair
    }
    // Ran out of input without a closing brace.
    return false;                            // no closing brace: malformed
}

void main() {
    Server s = Server { .name = String::from("db \"primary\""), .port = 5432, .tls = true };
    String json = jsonFromServer(&s);
    println("{}", json.asView());

    Server back = Server { .name = String::new(), .port = 0, .tls = false };
    // Parse it back into a fresh struct with known defaults.
    bool ok = jsonToServer(json.asView(), &back);
    println("parsed {} name={} port={} tls={}",
            ok, back.name.asView(), back.port, back.tls);

    s.name.free(); back.name.free(); json.free();  // replenish the heap
}

The serializer is low-tech: String appends, formatInt, and a ternary. jsonReadString mirrors jsonEscape; after a backslash, the next byte stands for itself except \n. Keys dispatch by field name, not position, so unknown keys are skipped and reordering tolerated. String::withCap(16) allocates the scratch key once; key.free() avoids a leak. Server::name is owned, so the result outlives the input.

Cost and notes

Both directions are one pass, O(total bytes), with one output allocation and one scratch String per key. The name is copied twice, the price of ownership when the input may be freed. A real serializer would use reflection or a trait, and a real parser a value tree, more machinery for the same bytes.

Edge cases and variations

Unknown string keys are read and discarded, so an older parser ignores fields a newer writer added. A missing key leaves the destination at the caller's initialization, which is why back starts with explicit defaults. Keys with escaped quotes are unsupported. A number too large for i64 fails parseI64 and leaves port unchanged. Trailing text after } is never examined; a strict reader should check i == json.len. Arrays are the natural extension: after [, loop values separated by commas until ].

A Fixed-Layout Binary Record

The problem

Text is inspectable but wasteful: an i32 costs up to eleven bytes as digits and must be parsed on every read. When only machines read a file, give each record a known size at a known offset so a reader can seek straight to record i.

The idea

Define fixed-layout structs and write fields one at a time in a chosen byte order rather than dumping raw memory. Compute offsets from @sizeof and freeze them in a helper, then check the layout with a comptime assertion so adding a field fails the build instead of silently shifting records. The header is sixteen bytes (u32, two u16s, u64), each record sixteen (u64 id, f64 score), so record i starts at 16 + i * 16.

The implementation.

import(lib) std::io::fs { fileOpen, fileClose, fileSeek, File, IoError, SEEK_SET };
import(lib) std::io::bio { FileReader, FileWriter };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };
import(lib) std::vec { Vec };

const u32 MAGIC = 0x41524F43u;               // 'CORA' little-endian
const u16 VERSION = 1u;

// Exactly sixteen bytes: 4 + 2 + 2, then the u64 at its aligned offset 8.
struct Header {
    u32 magic;                               // offset 0
    u16 version;                             // offset 4
    u16 flags;                               // offset 6
    u64 count;                               // offset 8
}

// Exactly sixteen bytes: a u64 id, then an f64 score, both 8-aligned.
struct Entry {
    u64 id;                                  // offset 0
    f64 score;                               // offset 8
}

// Frozen address of record i: header, then sixteen bytes per record.
usize entryOffset(u64 i) {
    return (usize)(16 + i * 16);
}

// Write the 16-byte header followed by n fixed records.
bool writeRecords(str path, const Vec<Entry>* rows) {
    comptime {
        if (@sizeof(Header) != 16) @compileError("Header must be 16 bytes");
        if (@sizeof(Entry) != 16) @compileError("Entry must be 16 bytes");
    }

    Result<File, IoError> fo = fileOpen(path, "w");
    // Error path: cannot open the file, so report failure.
    if (fo.isErr()) return false;
    File f = fo.unwrap();
    FileWriter w = FileWriter::fromFd(f);

    // Fields are written explicitly, little-endian, never by struct dump.
    // Header: magic, version, reserved flags, then the record count.
    w.writeU32Le(MAGIC);
    w.writeU16Le(VERSION);
    w.writeU16Le((u16)0);                    // flags reserved for now
    w.writeU64Le((u64)rows->count());

    // Each record lands at 16 + i*16 because both writes are fixed-width.
    // Each record is written field by field, little-endian.
    for (usize i = 0; i < rows->count(); i += 1) {
        Entry e = rows->at(i);
        w.writeU64Le(e.id);
        w.writeF64Le(e.score);
    }
    // Flush and close before returning success.
    fileClose(f);
    return true;
}

// Read the header, then seek to and load each record.
bool readRecords(str path, Vec<Entry>* out) {
    Result<File, IoError> fo = fileOpen(path, "r");
    if (fo.isErr()) return false;
    File f = fo.unwrap();
    FileReader r = FileReader::fromFd(f);

    // Read the header fields in the order they were written.
    u32 magic = r.readU32Le();
    u16 version = r.readU16Le();
    r.readU16Le();                           // flags: read, not needed here
    u64 count = r.readU64Le();
    // A wrong magic or version means this is not our file.
    if (magic != MAGIC || version != VERSION) { fileClose(f); return false; }

    for (u64 i = 0; i < count; i += 1) {
        // Jump to the frozen offset, then read the two fields in order.
        // Seek to the frozen offset instead of reading sequentially.
        fileSeek(f, (isize)entryOffset(i), SEEK_SET);
        u64 id = r.readU64Le();
        f64 score = r.readF64Le();
        // Append the decoded record to the output vector.
        out->push(Entry { .id = id, .score = score });
    }
    fileClose(f);
    return true;
}

void main() {
    Vec<Entry> rows = Vec<Entry>::new();
    rows.push(Entry { .id = 1, .score = 91.5 });
    rows.push(Entry { .id = 2, .score = 99.25 });
    rows.push(Entry { .id = 3, .score = 72.0 });

    String path = String::from("/tmp/coral-records.bin");
    // Error path: if the write fails, stop.
    if (!writeRecords(path.asView(), &rows)) { println("write failed"); return; }
    println("wrote {} entries", rows.count());

    // Read the records back and print them.
    Vec<Entry> back = Vec<Entry>::new();
    if (!readRecords(path.asView(), &back)) { println("read failed"); return; }
    for (usize i = 0; i < back.count(); i += 1) {
        Entry e = back.at(i);
        println("id {} score {}", e.id, e.score);
    }
}

The comptime block keeps the contract: it refuses to compile if Header stops being sixteen bytes, so the hard-coded 16 in entryOffset cannot go stale. FileWriter writes each field little-endian regardless of host order; FileReader reads it the same way. Seeking to entryOffset(i) before each read is redundant for contiguous records, but it makes the offset part of the format, exactly what the index in 41.8 exploits.

Cost and notes

Writing is O(records) system-buffered writes; reading is O(records), each two fixed-width reads. The file is 16 + 16n bytes with no delimiters and no per-field parsing: a u64 read is a load, not a parseU64. The header's count lets a reader allocate the right size up front. FileReader's typed readers discard their Result and yield zero on a short read, so this code trusts count; a defensive reader would use readBytes and check it.

Edge cases and variations

A truncated file makes count larger than the data; typed readers then return zeros past the end, producing bogus entries, so validate file size against count. The magic and version fields guard against the wrong file or a future layout. Layout depends on compiler padding; for byte-for-byte control, pack the struct or keep writing fields one at a time. Big-endian calls change nothing structurally and match network byte order.

A CRC32 Checksum

The problem

A file read back from disk may differ from what was written: a bad sector, a truncated write, a writer bug. A checksum lets a reader notice and refuse corrupted data instead of acting on it.

The idea

CRC32 treats the bytes as one enormous polynomial over GF(2) and takes the remainder modulo a fixed polynomial. Practically: keep a thirty-two-bit register, XOR in each byte, shift right eight times, conditionally XOR-ing the reflected polynomial 0xEDB88320 whenever the shifted-out bit was one. Start at all ones and complement the final value. CRC32 detects every single-bit error and every burst up to thirty-two bits; it is not cryptographic and cannot resist forgery.

The implementation.

import(lib) std::io::fs { readFileToString, writeFileFromString, IoError };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };
import(lib) std::fmt::fmt { formatHex };

// Reflected CRC-32, polynomial 0xEDB88320, one bit per input bit. The
// register is threaded through so callers can feed data in pieces.
u32 crc32Update(u32 crc, const u8* data, usize len) {
    u32 c = crc;
    for (usize i = 0; i < len; i += 1) {
        // Fold each input byte into the low bits of the register.
        c ^= (u32)data[i];                   // fold the next byte in
        // Eight shifts, conditionally XOR-ing the reflected polynomial.
        for (u8 k = 0; k < 8; k += 1) {
            if ((c & 1u) != 0) c = (c >> 1) ^ 0xEDB88320u;
            else c = c >> 1;                 // shift, sometimes xor
        }
    }
    return c;
}

// Whole-buffer CRC: preset all ones, then complement the final register.
u32 crc32(str data) {
    // Preset all ones, then complement the final value.
    return crc32Update(0xFFFFFFFFu, data.asU8(), data.len) ^ 0xFFFFFFFFu;
}

void main() {
    // The standard check value: crc32("123456789") == 0xCBF43926.
    // The nine-byte test string used to sanity-check the CRC.
    str check = "123456789";
    println("check {}", formatHex((u64)crc32(check), true).asView());

    String payload = String::from("the quick brown fox");
    u32 sum = crc32(payload.asView());
    String record = payload.clone();          // payload plus its trailer
    // Write the four trailer bytes, least significant first.
    record.pushByte((u8)sum);                 // checksum, little-endian
    record.pushByte((u8)(sum >> 8));
    record.pushByte((u8)(sum >> 16));
    record.pushByte((u8)(sum >> 24));
    // Persist payload and trailer as one buffer.
    writeFileFromString("/tmp/coral-crc.bin", &record);

    // Read the whole record back.
    Result<String, IoError> rr = readFileToString("/tmp/coral-crc.bin");
    if (rr.isErr()) return;
    // Parse guard: fewer than four bytes cannot hold a trailer.
    String back = rr.unwrap();
    if (back.len < 4) return;                 // too short to hold a crc
    // The body is everything except the trailing four bytes.
    str body = back.asView().slice(0, back.len - 4);
    u32 stored = (u32)back.at(back.len - 4) |
                 ((u32)back.at(back.len - 3) << 8) |
                 ((u32)back.at(back.len - 2) << 16) |
                 ((u32)back.at(back.len - 1) << 24);
    // Verification: the recomputed CRC must match the stored one.
    println("verified {}", stored == crc32(body));
}

crc32Update is separate from crc32 so a record can be checksummed in pieces without concatenating buffers; the log store in 41.7 uses that split to hash key and value without joining them. crc32 is the one-shot form. The checksum is written little-endian after the payload, and main's reconstruction is that agreement written down. The back.len < 4 guard rejects a file too short to hold a trailer.

Cost and notes

The bitwise form does eight shift-and-branch steps per byte, roughly an order of magnitude more work than reading. The standard optimization is a 256-entry table indexed by (c ^ byte) & 0xFF, replacing the inner loop with one load and one shift; build it once at startup. For occasional files the bitwise version is adequate and keeps the polynomial visible. The library's std::crypto::crc::crc32(str) is the table version.

Edge cases and variations

CRC32 detects accidental corruption, not tampering: messages can collide, and an attacker can construct one. For adversarial integrity use SHA-256 or HMAC. The empty buffer has CRC32 0x00000000 because the preset and final complement cancel. Storing the checksum in a different byte order silently fails every verification, so trailer endianness is part of the format. CRC-64 extends the same idea with a sixty-four-bit register and longer polynomial; the library provides crc64.

A Log-Structured Append-Only Key-Value Store

The problem

You want key-value pairs to survive between runs. Rewriting a file in place is dangerous: a crash mid-rewrite leaves it half-old, half-new. An append-only store never rewrites, so a crash can only damage the last record, and a reader that skips a bad tail loses at most the final write.

The idea

Every write appends a record: [u32 keyLen][u32 valLen][key bytes][val bytes][u32 crc]. Reading scans sequentially; the last record for a key wins, so an update is an append and a delete is an empty-value tombstone. The CRC catches a torn or corrupted record, which the scanner skips. Mode "a" creates the file if needed and writes at the end, so writers cannot clobber earlier records, though they can interleave.

The implementation.

import(lib) std::io::fs { fileOpen, fileClose, deleteFile, File, IoError };
import(lib) std::io::bio { FileReader, FileWriter };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };

const u32 KV_MAX_FIELD = 255u;               // one stack buffer per field

// Same reflected CRC-32 as 41.6, threaded so key and value hash in turn.
u32 crc32Update(u32 crc, const u8* data, usize len) {
    u32 c = crc;
    for (usize i = 0; i < len; i += 1) {
        c ^= (u32)data[i];
        for (u8 k = 0; k < 8; k += 1)
            c = (c & 1u) != 0 ? ((c >> 1) ^ 0xEDB88320u) : (c >> 1);
    }
    return c;
}

// Read a 4-byte little-endian u32, or fail at EOF.
bool readU32Le(FileReader* r, u32* out) {
    u8 b[4];
    if (r->readBytes(b, 4).isErr()) return false;  // clean EOF or error
    *out = (u32)b[0] | ((u32)b[1] << 8) | ((u32)b[2] << 16) | ((u32)b[3] << 24);
    return true;
}

// Append one record: lengths, key, value, then a CRC trailer.
bool kvPut(str path, str key, str val) {
    if (key.len > KV_MAX_FIELD || val.len > KV_MAX_FIELD) return false;

    Result<File, IoError> fo = fileOpen(path, "a");   // create + append
    // Error path: cannot open for append, so report failure.
    if (fo.isErr()) return false;
    File f = fo.unwrap();
    FileWriter w = FileWriter::fromFd(f);

    // CRC the key, then extend it over the value.
    u32 crc = crc32Update(0xFFFFFFFFu, key.asU8(), key.len);
    crc = crc32Update(crc, val.asU8(), val.len) ^ 0xFFFFFFFFu;

    w.writeU32Le((u32)key.len);              // lengths first, then payload
    w.writeU32Le((u32)val.len);
    w.writeBytes(key.asU8(), key.len);
    w.writeBytes(val.asU8(), val.len);
    w.writeU32Le(crc);                       // trailer last
    fileClose(f);
    return true;
}

// Scan the log; the last record for `key` wins, and an empty value is
// a tombstone meaning the key is deleted.
bool kvGet(str path, str key, String* out) {
    // Mode "r" opens an existing log; a missing file is an error.
    Result<File, IoError> fo = fileOpen(path, "r");
    if (fo.isErr()) return false;
    File f = fo.unwrap();
    FileReader r = FileReader::fromFd(f);

    bool found = false;
    // Read records until EOF or a malformed one stops the scan.
    while (true) {
        u32 klen = 0;
        u32 vlen = 0;
        if (!readU32Le(&r, &klen)) break;             // end of log
        if (!readU32Le(&r, &vlen)) break;             // truncated record
        if (klen > KV_MAX_FIELD || vlen > KV_MAX_FIELD) break;  // corrupt
        // Fixed stack buffers; the length check above bounds them.
        u8 kbuf[256];
        u8 vbuf[256];
        if (r.readBytes(kbuf, (u64)klen).isErr()) break;
        if (r.readBytes(vbuf, (u64)vlen).isErr()) break;
        u32 storedCrc = 0;
        // Read the CRC trailer, if present.
        if (!readU32Le(&r, &storedCrc)) break;

        // Recompute the CRC over key plus value.
        u32 crc = crc32Update(0xFFFFFFFFu, kbuf, (usize)klen);
        crc = crc32Update(crc, vbuf, (usize)vlen) ^ 0xFFFFFFFFu;
        if (crc != storedCrc) continue;       // skip a corrupt record

        // Only the record for our key matters.
        str recKey = str::fromParts(kbuf, (usize)klen);
        if (recKey.equals(key)) {
            out->clear();
            out->appendView(str::fromParts(vbuf, (usize)vlen));
            found = vlen > 0;                 // empty value deletes
        }
    }
    fileClose(f);
    return found;
}

void main() {
    // Start from a clean log so the demo is deterministic.
    String path = String::from("/tmp/coral-kv.log");
    deleteFile(path.asView());                // start from a clean log
    kvPut(path.asView(), "alpha", "1");
    kvPut(path.asView(), "beta", "2");
    kvPut(path.asView(), "alpha", "3");       // overwrite: last wins

    // Look up two existing keys and one absent key.
    String v = String::new();
    if (kvGet(path.asView(), "alpha", &v)) println("alpha = {}", v.asView());
    if (kvGet(path.asView(), "beta", &v)) println("beta = {}", v.asView());
    if (kvGet(path.asView(), "gamma", &v)) println("gamma = {}", v.asView());
    else println("gamma absent");
}

The record's shape is fixed enough to scan and self-describing enough to skip: lengths come first, so the scanner knows how many bytes to read; the CRC trailer comes last, computed over exactly those bytes. readU32Le exists because FileReader's typed readers swallow a short read and return zero, indistinguishable from a real zero length; the explicit readBytes reports a clean end of log. A torn tail stops the scan under the same guard, so a half-written last record is ignored.

Cost and notes

kvPut is O(key + value) plus the append and never reads the existing file, so writes stay cheap as the store grows. kvGet is O(file size), scanning every record, the price of having no index and the reason the next section exists. Space grows without bound as keys are overwritten; the cure is compaction, rewriting only live records into a fresh file and renaming it into place, which is 41.9 applied to the whole store.

Edge cases and variations

A field longer than KV_MAX_FIELD is refused, not truncated, so data cannot silently vanish. A corrupt record is skipped mid-scan; a torn final record stops the scan, losing only the last append. With no lock, concurrent appenders can interleave records; each stays internally consistent, but ordering is undefined. The deleteFile in main makes the demo deterministic. A tombstone flag or sequence number would let the newest write win by number rather than position and detect duplicate delivery.

An In-Memory Index from Key to File Offset

The problem

The log store of 41.7 finds a key by scanning the whole file, fine for ten records and hopeless for ten million. With a known layout, remember where each key's latest record lives and seek straight to it.

The idea

Scan the file once and build a hash map from key text to the byte offset of its latest record. Later records override earlier ones, so a plain insert leaves the newest offset. A lookup hashes the query, gets the offset, seeks, and reads one record. The map's keys are str views into the in-memory file copy, so that copy must stay alive, which is why main reads the whole file into a String first.

The implementation.

import(lib) std::io::fs { readFileToString, fileOpen, fileClose, fileSeek,
                           File, IoError, SEEK_SET };
import(lib) std::io::bio { FileReader };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };
import(lib) std::collections::hashmap { HashMap };
import(lib) std::option { Option };

// The same djb2 hash as 41.3; eqView must match it.
usize hashView(str s) {
    usize h = 5381;
    for (usize i = 0; i < s.len; i += 1) h = h * 33 + (usize)s.at(i);
    return h;
}

bool eqView(str a, str b) { return a.equals(b); }

// One pass over the in-memory log; each key maps to the offset of its
// newest record. Later inserts overwrite earlier ones, so last wins.
void buildIndex(str log, HashMap<str, usize>* index) {
    usize off = 0;
    // Parse guard: stop unless a full 8-byte header remains.
    while (off + 8 <= log.len) {
        // Read keyLen then valLen, both little-endian.
        u32 klen = (u32)log.at(off) | ((u32)log.at(off + 1) << 8) |
                   ((u32)log.at(off + 2) << 16) | ((u32)log.at(off + 3) << 24);
        u32 vlen = (u32)log.at(off + 4) | ((u32)log.at(off + 5) << 8) |
                   ((u32)log.at(off + 6) << 16) | ((u32)log.at(off + 7) << 24);
        // Record size: two lengths, payloads, then the CRC trailer.
        usize recLen = 8 + (usize)klen + (usize)vlen + 4;  // + crc trailer
        // A record that runs past the end is a torn tail: stop.
        if (off + recLen > log.len) break;               // truncated tail
        // The key is a view into the log buffer.
        str key = log.slice(off + 8, off + 8 + (usize)klen);
        // A repeated key overwrites, so the last offset wins.
        index->insert(key, off);                         // view into log
        off += recLen;
    }
}

// Seek straight to the indexed record and read only that one.
bool indexedGet(str path, str key, HashMap<str, usize>* index, String* out) {
    // Absent key: never written, so fail.
    Option<usize> slot = index->get(key);
    if (slot.isNone()) return false;                     // never written
    usize off = slot.unwrap();

    Result<File, IoError> fo = fileOpen(path, "r");
    if (fo.isErr()) return false;
    File f = fo.unwrap();
    FileReader r = FileReader::fromFd(f);
    fileSeek(f, (isize)off, SEEK_SET);                   // skip everything before

    // Read the two length prefixes from the indexed record.
    u8 hb[8];
    if (r.readBytes(hb, 8).isErr()) { fileClose(f); return false; }
    u32 klen = (u32)hb[0] | ((u32)hb[1] << 8) | ((u32)hb[2] << 16) | ((u32)hb[3] << 24);
    u32 vlen = (u32)hb[4] | ((u32)hb[5] << 8) | ((u32)hb[6] << 16) | ((u32)hb[7] << 24);
    if (klen > 255u || vlen > 255u) { fileClose(f); return false; }
    u8 kbuf[256];
    u8 vbuf[256];
    // Read the payloads; a short read fails the lookup.
    if (r.readBytes(kbuf, (u64)klen).isErr() || r.readBytes(vbuf, (u64)vlen).isErr()) {
        fileClose(f);
        return false;
    }
    out->clear();
    out->appendView(str::fromParts(vbuf, (usize)vlen));
    fileClose(f);
    return true;
}

void main() {
    String path = String::from("/tmp/coral-kv.log");
    Result<String, IoError> rr = readFileToString(path.asView());
    if (rr.isErr()) { println("no log yet (run 41.7 first)"); return; }
    String log = rr.unwrap();                // owns the bytes the keys view

    // Build the index once, then use it for lookups.
    HashMap<str, usize> index = HashMap<str, usize>::new(hashView, eqView);
    buildIndex(log.asView(), &index);
    println("indexed {} keys", index.count());

    String v = String::new();
    if (indexedGet(path.asView(), "alpha", &index, &v))
        println("alpha = {}", v.asView());
    else
        println("alpha absent");
}

buildIndex reads the two lengths, computes the record length, and advances off by exactly that much; a self-describing layout means the scanner never parses a key to find the next record. Storing each record's offset, not a copy of its value, keeps the index small: a key view plus one integer. indexedGet is the payoff: one hash lookup, one fileSeek, and one record read, independent of file size.

Cost and notes

Building the index is one O(file size) pass at startup; each lookup is O(1) average plus a seek and a record read. The index holds one entry per distinct key, so memory is proportional to keys, not records, the trade a database makes between a table and its indexes. A seek is bounded; scanning is not. This is the smallest in-memory index atop an append-only log in log-structured stores from LevelDB to Bitcask.

Edge cases and variations

The index is a snapshot; an append afterward is invisible until updated, so a real store updates on every write and rebuilds after restart or compaction. Keys are views into log, so freeing log early leaves dangling views. Offsets go stale if the file is compacted or rewritten in place, another reason compaction swaps in a new file. A corrupted record at a mapped offset fails length and CRC checks in a correct reader; indexedGet checks length bounds but leaves CRC to the caller, so adding the trailer check is natural hardening. Storing a length and CRC with each offset lets a lookup validate without reading.

Atomic Writes with a Temp File and Rename

The problem

A program rewrites a file another program, or a later run, may read. A crash midway leaves a truncated, invalid document. The swap from old to new should look instantaneous: a reader sees the complete old file or the complete new one.

The idea

Write the new contents to a temporary file, then after it is fully written and closed, rename it over the target. On POSIX, rename within one filesystem is atomic: the name refers to the new file, and any reader sees either old or new. The temporary must live in the same directory as the target, because a cross-filesystem rename fails. If anything fails before the rename, unlink the temporary, leaving the target untouched.

The implementation.

import(lib) std::io::fs { writeFileFromString, renameFile, deleteFile, IoError };
import(lib) std::io::ios { println };
import(lib) std::text::string { String };

// Write `data` to `target` by writing a sibling temp file and renaming
// it over the target. On return the target is entirely old or entirely
// new; on failure the target is exactly as it was.
bool atomicWrite(str target, const String* data) {
    // Copy the target path so a suffix can be appended.
    String tmp = String::from(target);
    tmp.appendView(".tmp");                  // sibling => same filesystem

    // Write the complete contents to the temporary file.
    Result<bool, IoError> wr = writeFileFromString(tmp.asView(), data);
    if (wr.isErr()) {
        deleteFile(tmp.asView());            // leave nothing behind
        // Free the temp path string before returning.
        tmp.free();
        return false;
    }

    // Swap the temp into place; rename is atomic on one filesystem.
    Result<bool, IoError> rn = renameFile(tmp.asView(), target);
    if (rn.isErr()) {
        deleteFile(tmp.asView());            // and keep the old target
        // Free the temp path string before returning.
        tmp.free();
        return false;
    }
    tmp.free();
    return true;
}

void main() {
    String path = String::from("/tmp/coral-state.txt");
    String first = String::from("generation 1\n");
    String second = String::from("generation 2\n");

    // Publish the first contents, then replace them with the second.
    if (atomicWrite(path.asView(), &first)) println("published 1");
    if (atomicWrite(path.asView(), &second)) println("published 2");
}

Appending ".tmp" to the target's own path is the trick: "/tmp/coral-state.txt" becomes "/tmp/coral-state.txt.tmp", in the same directory and filesystem. writeFileFromString opens the temp with mode "w", truncating and writing the full buffer, and closes it before returning, so the bytes are in the file when renameFile runs. Both failure paths unlink the temp and leave the target alone, making the operation all-or-nothing from the reader's view.

Cost and notes

The write costs one file's worth of bytes plus a rename, roughly double the data movement of an in-place overwrite. That is the price of the guarantee, a good trade for small state files. It also needs free space for two copies at once.

Edge cases and variations

No fsync and no exposed equivalent, so the write is atomic with respect to other processes seeing the file, but on power loss the new contents may not be on stable storage and the rename may not be durable. This guarantees a consistent view, not persistence across a crash. Durability needs flushing the temp file and its directory before and after the rename, a syscall the module lacks. The fixed ".tmp" suffix assumes one writer; two writers corrupt each other, so use a unique name. A cross-mount rename fails with EXDEV, which is why the temp is a sibling. renameFile atomically overwrites only a regular file, not a directory. Keeping the old target as a backup trades the single-file guarantee for a recoverable prior generation.
