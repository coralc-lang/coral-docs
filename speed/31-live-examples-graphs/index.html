Live Examples: Graphs

The Shape Behind Half of Computer Science

A graph is vertices plus edges. That model covers roads, friendships, web links, build dependencies, wires, game moves, and cell reactions, and the same few algorithms solve all of them.

An undirected edge goes both ways; a directed edge does not. Many algorithms work on both with a one-line change, but some depend on the kind.

An adjacency list is one neighbour list per vertex: O(V + E) memory and fast neighbour iteration. An adjacency matrix is an n×n grid: O(V^2) memory and O(1) edge queries. Sparse graphs favour the list. This chapter uses Vec<Vec<...>>: an outer vector indexed by vertex, each entry a vector of neighbours (Chapter 16).

Most traversals here are O(V + E): every vertex and edge examined once. Dijkstra adds a heap, O((V + E) log V). Kruskal adds a sort and union-find, O(E log E).

Imports: import(lib) std::vec { Vec }; for the graph, import(lib) std::collections::queue { Queue }; for BFS and Kahn's algorithm, and import(lib) std::collections::priorityqueue { PriorityQueue }; for Dijkstra and Prim. Edges are sorted with the sortBy method on Vec. Each code block repeats the imports it needs.

Representing a Graph

The problem

Build an undirected or directed graph with integer-named vertices, supporting edge insertion and efficient neighbour access.

Picture this

A city map where each intersection has a signpost listing its streets. An adjacency list is one drawer per intersection, holding only the streets that leave it.

Brute force, then better

An adjacency matrix stores n^2 entries whether or not they exist, so a sparse million-vertex graph needs a trillion booleans. The adjacency list stores only existing edges and suits neighbour traversal, so it is smaller and better shaped.

import(lib) std::vec { Vec };

// adjacency list: one list of neighbours per vertex
struct Graph {
    // number of vertices
    usize n;
    // adj[u] is the neighbour list of vertex u
    Vec<Vec<i32>> adj;

    // build n empty drawers, so isolated vertices are still valid
    static Graph new(usize n) {
        Graph g = Graph {
            .n = n,
            .adj = Vec<Vec<i32>>::new()
        };
        for (usize i = 0; i < n; i += 1) {
            // one empty inner vector per vertex
            g.adj.push(Vec<i32>::new());
        }
        return g;
    }

    // an undirected edge is mutual
    void addUndirectedEdge(i32 u, i32 v) {
        // record each endpoint in the other's list
        self.adj.atPtr((usize)u)->push(v);
        self.adj.atPtr((usize)v)->push(u);
    }

    // a directed edge is one-way: only u -> v
    void addDirectedEdge(i32 u, i32 v) {
        self.adj.atPtr((usize)u)->push(v);
    }
}

The struct holds the vertex count and Vec<Vec<i32>>: one neighbour vector per vertex. new allocates n empty vectors, so isolated vertices are valid. addUndirectedEdge pushes each endpoint into the other's list; addDirectedEdge pushes only u to v. Both use atPtr deliberately: it returns a pointer without copying the inner vector. Using at copies the owning Vec and risks a double free.

Time and space

Building costs O(V), each edge O(1), and storage is O(V + E) (2E inner entries for an undirected graph). A matrix would be O(V^2).

Edge cases

Zero vertices is legal and empty. Undirected self-loops work. Duplicate edges are not deduplicated; deduplicate at insert or tolerate revisits.

A variation

For weighted graphs, store a struct per edge:

// weighted edge: destination plus cost
struct Edge {
    i32 to;
    // the cost of travelling this edge
    i32 weight;
}

Then the list becomes Vec<Vec<Edge>>, each neighbour carrying its weight, which Dijkstra (30.5) and Prim (30.8) use. A Map from pairs to weights is clumsier for neighbour traversal.

BFS: Shortest Paths in an Unweighted Graph

The problem

Given an unweighted graph and a source, find the number of edges on the shortest path from the source to every vertex (fewest hops).

Picture this

Mark the start zero, then every corner one step away one, then every unvisited corner two steps away two, and so on. The first time you reach a corner is the shortest route, so the search expands in rings.

Brute force, then better

Exploring every walk is exponential because walks can loop. BFS visits vertices in distance order, and the first visit is the shortest. A FIFO queue ensures every vertex at distance d leaves before any at d+1.

import(lib) std::collections::queue { Queue };

void bfs(Graph* g, i32 source, Vec<i32>* dist) {
    for (usize i = 0; i < g->n; i += 1) {
        dist->push(-1);                       // -1 means "not reached yet"
    }
    // the source is zero hops from itself
    dist->set((usize)source, 0);
    // FIFO order is what lets BFS find shortest paths
    Queue<i32> q = Queue<i32>::new();
    // seed the frontier with the source
    q.enqueue(source);
    // process vertices in non-decreasing distance order
    while (!q.isEmpty()) {
        // take the next vertex to expand
        i32 u = q.dequeue();
        Vec<i32>* neighbors = g->adj.atPtr((usize)u);
        for (usize i = 0; i < neighbors->count(); i += 1) {
            i32 v = neighbors->at(i);
            // the first visit is necessarily the shortest visit
            if (dist->at((usize)v) == -1) {
                // record one hop more than u's distance
                dist->set((usize)v, dist->at((usize)u) + 1);
                // discover v so it is expanded in a later ring
                q.enqueue(v);
            }
        }
    }
}

The dist vector doubles as the visited marker: -1 means unseen, any non-negative value is a distance. The source starts at 0. Each neighbour of a dequeued vertex, if unseen, gets one more than the current distance and is enqueued. FIFO order makes that the true shortest distance.

Time and space

Each vertex is enqueued at most once and each edge examined once per endpoint, so O(V + E). The distance vector and queue are O(V).

Edge cases

The source is 0 from itself. Unreachable vertices stay -1. No edges leaves every non-source at -1. Negative distances never arise, so the -1 sentinel is safe. Weighted graphs need Dijkstra, not BFS.

A variation

Keep a parent vector and set parent[v] = u on discovery, then walk backward from the target to reconstruct the path. It costs O(V) memory.

DFS: Connected Components and Cycle Detection

The problem

Count the connected components of an undirected graph, and detect whether a directed graph contains a cycle.

Picture this

Components are islands joined by bridges: from one island you can reach exactly its component. Visit every island reachable from a start, then restart from the next unvisited one. DFS goes as deep as possible before backing up.

Brute force, then better

No algorithm can beat linear time for visiting every vertex, so DFS is the algorithm. It marks the current vertex, then recurses into each unvisited neighbour; the recursion stack replaces BFS's queue.

void dfsFrom(Graph* g, i32 u, Vec<bool>* visited) {
    // mark before recursing, or cycles never terminate
    visited->set((usize)u, true);
    Vec<i32>* neighbors = g->adj.atPtr((usize)u);
    for (usize i = 0; i < neighbors->count(); i += 1) {
        i32 v = neighbors->at(i);
        // recurse only into neighbours not yet seen
        if (!visited->at((usize)v)) {
            dfsFrom(g, v, visited);
        }
    }
}

i32 countComponents(Graph* g) {
    Vec<bool> visited = Vec<bool>::new();
    for (usize i = 0; i < g->n; i += 1) {
        visited.push(false);
    }
    // each restart from an unseen vertex is a new component
    i32 count = 0;
    for (usize u = 0; u < g->n; u += 1) {
        if (!visited.at(u)) {
            // count it, then flood-fill it away
            count += 1;
            dfsFrom(g, (i32)u, &visited);
        }
    }
    return count;
}

dfsFrom floods from one vertex through every unvisited neighbour, marking as it goes. countComponents restarts from each unreached vertex, and each restart is a new component. Passing &visited is essential: the whole flood must share one visited set.

For directed cycle detection, track three states: white (untouched), gray (on the current recursion path), and black (finished). An edge to a gray vertex is a back edge and closes a cycle; an edge to black is harmless. An enum expresses the three states (Chapter 13):

// white = untouched, gray = on the current path, black = done
enum Color {
    White,
    Gray,
    Black,
}

bool dfsCycle(Graph* g, i32 u, Vec<Color>* state) {
    state->set((usize)u, Color::Gray);        // on the current path
    Vec<i32>* neighbors = g->adj.atPtr((usize)u);
    for (usize i = 0; i < neighbors->count(); i += 1) {
        i32 v = neighbors->at(i);
        // what state is this neighbour in?
        Color c = state->at((usize)v);
        if (c == Color::Gray) return true;    // back edge: a cycle
        // recurse only into vertices never explored
        if (c == Color::White && dfsCycle(g, v, state)) return true;
    }
    state->set((usize)u, Color::Black);       // finished
    return false;
}

bool hasCycle(Graph* g) {
    // every vertex starts white
    Vec<Color> state = Vec<Color>::new();
    for (usize i = 0; i < g->n; i += 1) {
        state.push(Color::White);
    }
    for (usize u = 0; u < g->n; u += 1) {
        // start a search from each still-uncoloured vertex
        if (state.at(u) == Color::White && dfsCycle(g, (i32)u, &state)) return true;
    }
    return false;
}

White means unexplored, gray means on the current path, black means fully explored. An edge into gray closes a loop; an edge into black does not. Using enum makes the test read as the concept and prevents a mistyped integer from masquerading as a colour.

Time and space

Both are O(V + E) time. The recursion stack is O(V) deep in the worst case, and the visited or state array is O(V). Very large graphs may need an explicit stack, as Chapter 28 warned for deep trees.

Edge cases

An empty graph has zero components and no cycle. Isolated vertices give one component each and no cycle. The three-colour scheme is wrong for undirected graphs, where the edge back to a parent looks like a cycle; ignore the parent when recursing. A self-loop is detected because the vertex is gray while examining its own edge.

A variation

DFS also yields a topological order of a DAG: push each vertex after its neighbours finish, then reverse the postorder. That is the DFS cousin of the queue-based sort in 30.4.

Topological Sort: An Order That Respects Dependencies

The problem

Given a directed acyclic graph, produce a linear order in which every edge points from earlier to later. A cyclic graph has no such order, and the algorithm should report that. The motivating example is a build system: an edge A→B means compile A before B.

Picture this

Some garments depend on others: socks before shoes, shirt before jacket. Repeatedly take any garment whose prerequisites are all on, add it to the list, and remove it from the pile. If items remain but none is free, they form a cycle.

Brute force, then better

Trial and error is exponential. Kahn's algorithm is linear: count each vertex's incoming edges (indegree), repeatedly output a zero-indegree vertex, and decrement its neighbours' indegrees. A vertex becomes available when its last prerequisite is removed.

bool topologicalSort(Graph* g, Vec<i32>* order) {
    // indegree[v] counts v's not-yet-removed prerequisites
    Vec<i32> indegree = Vec<i32>::new();
    for (usize i = 0; i < g->n; i += 1) {
        indegree.push(0);
    }
    for (usize u = 0; u < g->n; u += 1) {
        Vec<i32>* neighbors = g->adj.atPtr(u);
        for (usize i = 0; i < neighbors->count(); i += 1) {
            i32 v = neighbors->at(i);
            // every edge u->v adds one prerequisite to v
            indegree.set((usize)v, indegree.at((usize)v) + 1);
        }
    }
    // seed the queue with vertices that have no prerequisites
    Queue<i32> q = Queue<i32>::new();
    for (usize u = 0; u < g->n; u += 1) {
        if (indegree.at(u) == 0) q.enqueue((i32)u);
    }
    while (!q.isEmpty()) {
        i32 u = q.dequeue();
        // emit u into the topological order
        order->push(u);
        Vec<i32>* neighbors = g->adj.atPtr((usize)u);
        for (usize i = 0; i < neighbors->count(); i += 1) {
            i32 v = neighbors->at(i);
            // removing u satisfies one prerequisite of v
            indegree.set((usize)v, indegree.at((usize)v) - 1);
            // v's last prerequisite is gone, so it is free
            if (indegree.at((usize)v) == 0) {
                q.enqueue(v);
            }
        }
    }
    // a short order means a cycle locked some vertices
    return order->count() == g->n;
}

The first pass computes every indegree. The queue starts with the zero-indegree vertices. Each removal appends a vertex and decrements its neighbours; any neighbour reaching zero is enqueued. If the order is shorter than V, some vertices never became free, which means a cycle.

Time and space

Indegree computation and the main loop are O(V + E), with O(V) for the indegree vector and queue. Any valid order is returned; enqueue order breaks ties deterministically for a given input.

Edge cases

An empty graph gives an empty order and success. A cycle gives an order shorter than V and false. Multiple valid orders are expected. Self-loops are immediate cycles, since such a vertex never reaches indegree zero.

A variation

The DFS postorder version pushes vertices after their descendants, then reverses. It is free if you are already doing DFS, but cycle detection needs the three-colour machinery of 30.3, while Kahn's detects a cycle from the output length. 30.9 shows the course-scheduling application.

Dijkstra: Shortest Paths with Positive Weights

The problem

Given a weighted graph with non-negative weights and a source, find the shortest path length from the source to every vertex.

Picture this

Each road has a travel time, and the best route to a city is the best route to a neighbour plus the road from it. The graph has no natural table order, so Dijkstra always finalises the nearest unfinalised vertex, turning the unordered graph into an ordered process.

Brute force, then better

Considering all paths is exponential. Bellman-Ford relaxes every edge V-1 times in O(V × E) and handles negative weights. Dijkstra is faster, O((V + E) log V), but requires non-negative weights; a priority queue always pulls the smallest tentative distance.

struct Edge {
    i32 to;
    i32 weight;
}

struct QNode {
    i64 dist;
    i32 node;
}

bool qNodeLess(QNode a, QNode b) {
    return a.dist < b.dist;
}

void dijkstra(Vec<Vec<Edge>>* adj, usize n, i32 source, Vec<i64>* dist) {
    i64 infinity = 1000000000000000000;      // a stand-in for "unreachable"
    for (usize i = 0; i < n; i += 1) {
        dist->push(infinity);
    }
    // the source costs nothing to reach
    dist->set((usize)source, 0);
    // the smallest tentative distance always comes out first
    PriorityQueue<QNode> pq = PriorityQueue<QNode>::new(qNodeLess);
    pq.push(QNode { .dist = 0, .node = source });
    while (!pq.isEmpty()) {
        QNode top = pq.pop();
        i32 u = top.node;
        if (top.dist > dist->at((usize)u)) continue;   // a stale, outdated entry
        Vec<Edge>* neighbors = adj->atPtr((usize)u);
        for (usize i = 0; i < neighbors->count(); i += 1) {
            Edge e = neighbors->at(i);
            // cost of reaching e.to by going through u
            i64 candidate = top.dist + (i64)e.weight;
            // relax the edge if this route is shorter
            if (candidate < dist->at((usize)e.to)) {
                dist->set((usize)e.to, candidate);
                // remember the improvement for a later pop
                pq.push(QNode { .dist = candidate, .node = e.to });
            }
        }
    }
}

dist holds the best known distance, infinity except for the source at 0. The priority queue yields the smallest tentative distance, and a popped vertex is finalised because non-negative weights mean no later path can be shorter. Each outgoing edge is relaxed: a shorter route is recorded and pushed. The if (top.dist > dist->at(u)) continue; line discards stale entries, avoiding decrease-key.

Time and space

Each edge causes at most one push, so O(E) heap operations of O(log E) each, total O((V + E) log V). The distance array is O(V) and the heap O(E). Without a heap, Dijkstra is O(V^2), fine for dense graphs and worse for sparse ones.

Edge cases

Unreachable vertices stay at infinity. Non-negative weights are a hard precondition; a negative edge silently produces wrong answers, so use Bellman-Ford instead. i64 distances avoid overflow when many edges add up and provide a safe infinity. A single vertex returns 0.

A variation

Add a parent array updated when a distance improves, then walk backward to recover the path. A* is Dijkstra plus a heuristic estimating distance to the goal, which focuses exploration toward the target; it powers most game pathfinding.

Union-Find: Keeping Track of Groups

The problem

Maintain disjoint groups under two operations: find(x) reports x's group, and unite(a, b) merges the groups containing a and b. Whether two elements share a group follows from find.

Picture this

Conversation circles form at a mixer. find(person) asks which circle someone is in, and unite(a, b) merges two circles. Rather than relabel everyone, each circle has a leader and each person points toward the leader; merging points one leader at the other.

Brute force, then better

Relabelling every member on merge is O(n) per merge and O(n^2) overall. Union-find stores only parent pointers, with roots as labels. Union by rank hangs the smaller tree under the larger, and path compression points every element on a find path directly at the root.

struct DSU {
    // parent[x] points toward x's group root
    Vec<i32> parent;
    // rank is an upper bound on the depth of a tree
    Vec<i32> rank;

    static DSU new(usize n) {
        DSU d = DSU {
            .parent = Vec<i32>::new(),
            .rank = Vec<i32>::new()
        };
        for (usize i = 0; i < n; i += 1) {
            d.parent.push((i32)i);            // each element starts as its own root
            d.rank.push(0);
        }
        return d;
    }

    i32 find(i32 x) {
        // first pass: walk up to the root
        i32 root = x;
        while (self.parent.at((usize)root) != root) {
            root = self.parent.at((usize)root);
        }
        // second pass: flatten the path straight to the root
        i32 cur = x;
        while (self.parent.at((usize)cur) != root) {
            i32 next = self.parent.at((usize)cur);
            self.parent.set((usize)cur, root);   // compress: point straight at the root
            cur = next;
        }
        return root;
    }

    bool unite(i32 a, i32 b) {
        // find the roots of both elements
        i32 ra = self.find(a);
        i32 rb = self.find(b);
        if (ra == rb) return false;              // already together
        i32 rankA = self.rank.at((usize)ra);
        i32 rankB = self.rank.at((usize)rb);
        // hang the shallower tree under the deeper one
        if (rankA < rankB) {
            self.parent.set((usize)ra, rb);
        } else if (rankA > rankB) {
            self.parent.set((usize)rb, ra);
        } else {
            self.parent.set((usize)rb, ra);
            // tie: only here does depth grow
            self.rank.set((usize)ra, rankA + 1);
        }
        return true;
    }
}

Each element's parent points to another element; a root points to itself. find walks to the root, then repoints every element on the path directly at it, keeping future finds short. unite hangs the shallower tree under the deeper using rank; only ties increase depth. A false return means a and b were already connected, which is what Kruskal needs.

Time and space

With union by rank and path compression, each operation is amortised O(α(n)), the inverse Ackermann function, below 5 for any practical n, effectively O(1). Storage is O(n) for the two arrays.

Edge cases

new(n) starts n singleton groups. find does not guard out-of-range indices, so callers must respect bounds. unite(a, a) returns false. Without path compression, operations are O(log n); without union by rank, the worst case can become O(n), so keep both.

A variation

Union-find answers connectivity as edges are added, the online version of 30.3's components. It is faster than re-running DFS for growing graphs, but neither handles edge removal directly.

Kruskal's Minimum Spanning Tree

The problem

Given a connected undirected weighted graph, find a subset of edges connecting all vertices with minimum total weight. It is always a tree (V-1 edges, no cycles), a minimum spanning tree.

Picture this

Wiring an office, you consider cables cheapest first and lay each one if it joins two previously separate clusters. Skipping any cable that would close a loop guarantees no redundant connection.

Brute force, then better

Trying every subset of V-1 edges is exponential. Kruskal's algorithm sorts edges by weight and adds each unless it would create a cycle. Union-find's unite returning false is exactly that cycle test, which makes Kruskal fast.

struct WEdge {
    i32 u;
    i32 v;
    i32 weight;
}

bool wEdgeLess(WEdge a, WEdge b) {
    return a.weight < b.weight;
}

i64 kruskal(usize n, Vec<WEdge>* edges) {
    if (n == 0) return 0;
    // cheapest edges first
    edges->sortBy(wEdgeLess);
    // tracks what is already connected
    DSU dsu = DSU::new(n);
    i64 total = 0;
    usize used = 0;
    for (usize i = 0; i < edges->count(); i += 1) {
        WEdge e = edges->at(i);
        // unite is false when this edge would close a cycle
        if (dsu.unite(e.u, e.v)) {
            total += (i64)e.weight;
            used += 1;
            if (used == n - 1) break;         // a spanning tree has n-1 edges
        }
    }
    if (n > 0 && used != n - 1) return -1;    // the graph was not connected
    return total;
}

Sorting puts cheap edges first. unite returns true only when an edge joins two different components, so accepted edges are added and totalled. The loop breaks once n-1 edges are added. If it finishes short, the graph is disconnected and -1 is returned.

Time and space

The sort is O(E log E), and the loop does at most E effectively O(1) union-find operations, so O(E log E) total. Space is O(V + E) for the graph and DSU arrays. Kruskal suits an edge list; Prim (30.8) suits an existing adjacency structure.

Why greedy works here

The cut property: for any partition of the vertices into two non-empty sets, the cheapest edge crossing the cut belongs to some minimum spanning tree. Kruskal always adds a cheapest crossing edge for the cut between the components it joins, so it never makes an unsafe choice.

Edge cases

An empty or single-vertex graph totals 0. A disconnected graph returns -1. Negative and duplicate weights are fine; only their order matters. Self-loops are rejected because unite(u, u) returns false.

A variation

The maximum spanning tree is the same algorithm with the sort reversed. On a complete graph, Prim with a heap is often faster in practice.

Prim's Minimum Spanning Tree

The problem

The same minimum spanning tree as 30.7, grown differently: start from one vertex and repeatedly add the cheapest edge reaching a vertex outside the tree.

Picture this

Light a town from one house, each step extending power by the cheapest wire from the lit area to a dark house. The lit region grows like a snowball, and the wires laid form an MST.

Brute force, then better

Scanning all edges for the next cheapest crossing edge gives O(V^2). A priority queue turns each scan into a heap extraction: push every edge from the newly lit vertex, then pop the cheapest, skipping edges whose endpoint is already lit. That gives O((V + E) log V).

i64 prim(Vec<Vec<Edge>>* adj, usize n) {
    if (n == 0) return 0;
    // which vertices have already joined the tree
    Vec<bool> inTree = Vec<bool>::new();
    for (usize i = 0; i < n; i += 1) {
        inTree.push(false);
    }
    PriorityQueue<QNode> pq = PriorityQueue<QNode>::new(qNodeLess);
    pq.push(QNode { .dist = 0, .node = 0 });       // start anywhere; no edge is "free"
    // running weight of the tree
    i64 total = 0;
    // vertices joined so far
    i32 reached = 0;
    while (!pq.isEmpty() && reached < (i32)n) {
        QNode top = pq.pop();
        i32 u = top.node;
        if (inTree.at((usize)u)) continue;          // already connected; stale entry
        inTree.set((usize)u, true);
        total += top.dist;
        reached += 1;
        Vec<Edge>* neighbors = adj->atPtr((usize)u);
        for (usize i = 0; i < neighbors->count(); i += 1) {
            Edge e = neighbors->at(i);
            // offer each still-dark neighbour as a candidate
            if (!inTree.at((usize)e.to)) {
                pq.push(QNode { .dist = (i64)e.weight, .node = e.to });
            }
        }
    }
    // not every vertex joined: the graph was disconnected
    if (reached != (i32)n) return -1;
    return total;
}

The queue holds (cost to reach this vertex, vertex), starting with the source at cost 0, an artificial edge so the source joins first. Each pop is the cheapest way to reach a new vertex; if it is already in the tree, the entry is stale. Otherwise it joins, its cost is added, and its edges to dark neighbours are pushed. reached detects a disconnected graph and returns -1.

Time and space

Each edge is pushed at most once per endpoint, so O((V + E) log V) time and O(V + E) space. On dense graphs the heap advantage over the O(V^2) scan shrinks; on sparse graphs it is clearly better.

Edge cases

An empty graph returns 0. A disconnected graph returns -1 because reached falls short. The start vertex is arbitrary and does not change the total. Negative edges are handled. The dist = 0 seed is not a real edge and adds nothing.

A variation

Dijkstra and Prim share the same loop. Dijkstra's key is total distance from the source; Prim's is the weight of the single edge reaching the vertex. One accumulates path cost, the other takes the cheapest connecting edge.

A Worked Application: Course Schedule

The problem

Given a course count and prerequisite pairs [a, b] meaning b must be taken before a, decide whether every course can be finished. This is LeetCode's Course Schedule, pure topological sort.

Picture this

Plan a degree with prerequisites. If two courses require each other, no schedule exists. Otherwise a schedule is a topological order of the prerequisite graph.

Brute force, then better

Trying every order is factorial. Build a directed edge from each prerequisite to the course requiring it, then run Kahn's algorithm; the courses are schedulable exactly when the topological sort includes every vertex.

bool canFinish(i32 numCourses, Vec<Vec<i32>>* prerequisites) {
    Graph g = Graph::new((usize)numCourses);
    // one directed edge per prerequisite pair
    for (usize i = 0; i < prerequisites->count(); i += 1) {
        Vec<i32>* pair = prerequisites->atPtr(i);
        i32 course = pair->at(0);
        i32 prereq = pair->at(1);
        g.addDirectedEdge(prereq, course);       // prereq -> course
    }
    Vec<i32> order = Vec<i32>::new();
    // schedulable exactly when every course makes it into the order
    return topologicalSort(&g, &order);
}

The function adds one directed edge per prerequisite in the direction "must come first → depends on it," then delegates to topologicalSort, whose boolean return is the answer. prerequisites->atPtr(i) reads the pair without copying. Any cycle leaves order short, so the function returns false.

Time and space

Building the graph and the topological sort are both O(V + E), so the whole thing is O(V + E) time and space, where V is courses and E is prerequisite pairs. Recognising the graph structure turned an exponential problem linear.

Edge cases

Zero courses returns true with an empty order. Zero prerequisites emits every course immediately. Duplicate prerequisites add parallel edges and are harmless. A self-prerequisite is an immediate cycle and returns false.

A variation

Course Schedule II asks for an actual order, which is the order vector Kahn's algorithm already builds. When true, it is a valid schedule; when false, it holds the courses freed before the cycle. The decision and construction versions share all their machinery.

A Worked Application: Number of Islands

The problem

Given a 2D grid of '1' (land) and '0' (water), count islands: groups of land cells connected horizontally or vertically, not diagonally.

Picture this

Scan a satellite image. On hitting land, you have found a new island; flood the whole island, walking to its four neighbours and marking everything reachable, so it is never counted again.

Brute force, then better

Comparing every land cell with every other is quadratic and error-prone. Each land cell is a vertex joined to its land neighbours, so counting islands is counting connected components (30.3) on a grid.

import(lib) std::collections::queue { Queue };

void exploreDir(Vec<str>* grid, Vec<bool>* visited, Queue<i64>* q, i64 r, i64 c, usize rows, usize cols) {
    // reject negative coordinates
    if (r < 0 || c < 0) return;
    // reject off-grid coordinates
    if ((usize)r >= rows || (usize)c >= cols) return;
    usize flat = (usize)r * cols + (usize)c;
    if (visited->at(flat)) return;
    str row = grid->at((usize)r);
    // water, not land
    if (row.at((usize)c) != (u8)'1') return;
    visited->set(flat, true);
    q->enqueue((i64)flat);
}

void floodFill(Vec<str>* grid, Vec<bool>* visited, usize sr, usize sc, usize rows, usize cols) {
    Queue<i64> q = Queue<i64>::new();
    visited->set(sr * cols + sc, true);
    q.enqueue((i64)(sr * cols + sc));
    // expand until the whole island is consumed
    while (!q.isEmpty()) {
        i64 flat = q.dequeue();
        i64 r = flat / (i64)cols;
        i64 c = flat % (i64)cols;
        exploreDir(grid, visited, &q, r - 1, c, rows, cols);
        exploreDir(grid, visited, &q, r + 1, c, rows, cols);
        exploreDir(grid, visited, &q, r, c - 1, rows, cols);
        exploreDir(grid, visited, &q, r, c + 1, rows, cols);
    }
}

i32 numIslands(Vec<str>* grid) {
    usize rows = grid->count();
    // an empty grid has no islands
    if (rows == 0) return 0;
    str firstRow = grid->at(0);
    usize cols = firstRow.len;
    Vec<bool> visited = Vec<bool>::new();
    for (usize i = 0; i < rows * cols; i += 1) {
        visited.push(false);
    }
    // one flood per island discovered
    i32 count = 0;
    for (usize i = 0; i < rows; i += 1) {
        for (usize j = 0; j < cols; j += 1) {
            str row = grid->at(i);
            if (row.at(j) == (u8)'1' && !visited.at(i * cols + j)) {
                count += 1;
                // consume this island so it is never counted again
                floodFill(grid, &visited, i, j, rows, cols);
            }
        }
    }
    return count;
}

The grid is a Vec<str>, one string per row. str is a borrowed view, so reading a row never copies the data and never risks the double-free that copying an owning Vec would. visited is one flat Vec<bool> indexed by r * cols + c, smaller and faster than a vector of vectors. floodFill is BFS: mark and enqueue a cell, then repeatedly dequeue and try its four neighbours through exploreDir, which bounds-checks, skips visited cells and water, and marks and enqueues land. numIslands calls floodFill once per unvisited land cell, consuming a whole island.

Time and space

Every cell is examined once by the outer scan and at most four times as a neighbour, so O(rows × cols). The visited vector and BFS queue are O(rows × cols). This is O(V + E) with V = cells and E at most 4V, so O(V).

Edge cases

An empty grid or all-water grid returns 0. A single land cell is one island. Diagonal land does not connect; if it did, four more exploreDir calls would be added. Non-rectangular rows would break the flat indexing, so the code assumes a rectangular grid.

A variation

The same flood fill answers maximum island area, island perimeter, and closed-island counting. Only what the flood records changes, which is the signature of a well-chosen model.

Bipartite Check (Two-Colouring)

The problem

Given an undirected graph, decide whether its vertices can be coloured with two colours so every edge joins opposite colours. Such a graph is bipartite.

Picture this

Split people into two teams so nobody who dislikes each other shares a team. Put one person on A, everyone they dislike on B, then everyone those dislike back on A, alternating. If someone would have to be on both teams, no split exists.

Brute force, then better

Trying all 2^V colourings is exponential. One BFS colours a starting vertex and floods outward, giving each neighbour the opposite colour. The first edge joining two vertices of the same colour proves the graph is not bipartite.

import(lib) std::vec { Vec };
import(lib) std::collections::queue { Queue };

bool isBipartite(Vec<Vec<i32>>* adj) {
    usize n = adj->count();
    Vec<i32> color = Vec<i32>::new();
    for (usize i = 0; i < n; i += 1) {
        color.push(-1);                  // -1 means "not coloured yet"
    }
    // restart per component so disconnected graphs are handled
    for (usize start = 0; start < n; start += 1) {
        if (color.at(start) != -1) continue;
        // colour the component's seed 0
        color.set(start, 0);
        Queue<i32> q = Queue<i32>::new();
        q.enqueue((i32)start);
        while (!q.isEmpty()) {
            i32 u = q.dequeue();
            Vec<i32>* neighbors = adj->atPtr((usize)u);
            for (usize i = 0; i < neighbors->count(); i += 1) {
                i32 v = neighbors->at(i);
                // an uncoloured neighbour gets the opposite colour
                if (color.at((usize)v) == -1) {
                    color.set((usize)v, 1 - color.at((usize)u));
                    q.enqueue(v);
                } else if (color.at((usize)v) == color.at((usize)u)) {
                    return false;        // an edge inside one colour: not bipartite
                }
            }
        }
    }
    return true;
}

color holds 0, 1, or -1 for uncoloured. The outer loop restarts the flood from every uncoloured vertex, so each component is coloured independently and all must pass. An uncoloured neighbour gets the opposite colour and is enqueued; an already-coloured neighbour must differ, or an edge joins two equal colours and the answer is false. 1 - color flips between 0 and 1.

Time and space

Each vertex is enqueued once and each edge examined once per endpoint, so O(V + E) time, with O(V) for the colour array and queue. This is BFS with one extra check.

Edge cases

An empty graph is bipartite. A self-loop makes it not bipartite, because its two ends would need opposite colours; the same-colour test catches it. Any odd-length cycle is caught when its closing edge is examined. A graph with no edges is bipartite.

A variation

The two colours are the two sides of a partition, so collecting vertices by colour produces the split when the answer is true. Bipartite is equivalent to having no odd cycle, and every tree is bipartite.

Multi-Source BFS

The problem

In a grid, some cells are rotten and the rest fresh. Every minute, each rotten cell infects its fresh horizontal and vertical neighbours. Report the minutes until no fresh cell remains, or -1 if some fresh cell is unreachable.

Picture this

Several fires break out at once, each spreading one step per minute. With multiple sources, all fronts advance together, and a cell's ignition time is its distance to the nearest source, which is what BFS from all sources computes.

Brute force, then better

Running BFS from every rotten cell and taking the per-cell minimum is O(V × (V + E)), quadratic. Seeding the queue with every rotten cell before the loop lets one pass process cells in non-decreasing distance order, so the first reach is by the nearest source.

import(lib) std::vec { Vec };
import(lib) std::collections::queue { Queue };

void rotCell(Vec<Vec<i32>>* grid, Queue<i64>* q, i32* fresh, i64 nr, i64 nc, usize rows, usize cols) {
    // reject negative coordinates
    if (nr < 0 || nc < 0) return;
    // reject off-grid coordinates
    if ((usize)nr >= rows || (usize)nc >= cols) return;
    if (grid->atPtr((usize)nr)->at((usize)nc) != 1) return;   // not fresh
    grid->atPtr((usize)nr)->set((usize)nc, 2);                // rot it
    *fresh -= 1;
    q->enqueue(nr * (i64)cols + nc);
}

i32 orangesRotting(Vec<Vec<i32>>* grid) {
    usize rows = grid->count();
    if (rows == 0) return 0;
    usize cols = grid->atPtr(0)->count();
    Queue<i64> q = Queue<i64>::new();
    i32 fresh = 0;
    for (usize r = 0; r < rows; r += 1) {
        for (usize c = 0; c < cols; c += 1) {
            i32 cell = grid->atPtr(r)->at(c);
            if (cell == 2) {
                q.enqueue((i64)(r * cols + c));               // every source at once
            } else if (cell == 1) {
                fresh += 1;
            }
        }
    }
    // counts rounds of simultaneous spread
    i32 minutes = 0;
    // stop once the last fresh cell rots
    while (!q.isEmpty() && fresh > 0) {
        // snapshot: one whole BFS level per minute
        usize levelSize = q.count();
        for (usize k = 0; k < levelSize; k += 1) {
            i64 flat = q.dequeue();
            i64 r = flat / (i64)cols;
            i64 c = flat % (i64)cols;
            rotCell(grid, &q, &fresh, r - 1, c, rows, cols);
            rotCell(grid, &q, &fresh, r + 1, c, rows, cols);
            rotCell(grid, &q, &fresh, r, c - 1, rows, cols);
            rotCell(grid, &q, &fresh, r, c + 1, rows, cols);
        }
        // finishing a level is one minute
        minutes += 1;
    }
    // some fresh cell was unreachable
    if (fresh > 0) return -1;
    return minutes;
}

Seeding every rotten cell before processing is the entire difference from ordinary BFS. The fresh counter stops the loop when the last fresh cell rots and detects the impossible case. The inner loop drains one BFS level, and minutes increments once per level, counting rounds of simultaneous spread. rotCell mirrors the four-neighbour flood of 30.10: it bounds-checks, ignores non-fresh cells, and otherwise rots, decrements, and enqueues.

Time and space

Each cell enters the queue at most once and gets at most four neighbour checks, so O(rows × cols). The queue and counters are O(rows × cols) in the worst case, and minutes is at most that. Rotting in the grid doubles as the visited marker.

Edge cases

No fresh cells returns 0, since fresh > 0 is false from the start. No rotten cells with fresh cells returns -1, since the empty queue spreads nothing. Walled-off fresh cells stay fresh and the final check returns -1. An empty grid returns 0. To preserve the grid, use a separate visited array.

A variation

Multi-source BFS answers any nearest-source question: distance to the nearest hospital, flood coverage time, or infection rounds with several index cases. Seeding every source before the loop turns a search per source into a single pass.

Bellman-Ford: Negative Edge Weights

The problem

Given a directed weighted graph and a source, find the shortest distance to every vertex while allowing negative weights, and report whether a negative cycle is reachable from the source.

Picture this

Dijkstra finalises a vertex on pop, trusting no later path is shorter, which requires non-negative edges. Bellman-Ford assumes nothing: relax every edge repeatedly, and each full pass extends known shortest paths by one more edge, so V-1 passes cover every simple path.

Brute force, then better

Considering all paths is exponential. Bellman-Ford runs V-1 rounds of relaxing every edge, O(V × E). It is slower than Dijkstra on non-negative graphs but more general, and it detects negative cycles.

struct WEdge {
    i32 u;
    i32 v;
    i32 weight;
}

bool bellmanFord(i32 n, Vec<WEdge>* edges, i32 source, Vec<i64>* dist) {
    i64 infinity = 1000000000000000000;
    for (i32 i = 0; i < n; i += 1) {
        dist->push(infinity);
    }
    // the source costs nothing
    dist->set((usize)source, 0);
    // V-1 rounds cover every simple path
    for (i32 round = 0; round < n - 1; round += 1) {
        bool changed = false;
        for (usize e = 0; e < edges->count(); e += 1) {
            WEdge edge = edges->at(e);
            i64 du = dist->at((usize)edge.u);
            if (du == infinity) continue;             // u is not reachable yet
            i64 candidate = du + (i64)edge.weight;
            // relax: a shorter route through u
            if (candidate < dist->at((usize)edge.v)) {
                dist->set((usize)edge.v, candidate);
                changed = true;
            }
        }
        if (!changed) break;                          // no improvement: finish early
    }
    for (usize e = 0; e < edges->count(); e += 1) {
        WEdge edge = edges->at(e);
        i64 du = dist->at((usize)edge.u);
        if (du == infinity) continue;
        // still relaxable after all rounds means a negative cycle
        if (du + (i64)edge.weight < dist->at((usize)edge.v)) {
            return false;                             // still improvable: negative cycle
        }
    }
    return true;
}

After k passes the distances are correct for every path of at most k edges, so V-1 passes cover every simple path; a shortest path never repeats a vertex unless a negative cycle exists. The changed flag ends the run early once a pass improves nothing. The final loop tests for a negative cycle: if any edge can still be relaxed, a reachable negative cycle makes the shortest distances undefined.

Time and space

O(V × E) time worst case and O(V) space for the distance array. The du == infinity guard matters for unreachable vertices, since adding a negative weight to the sentinel would manufacture a bogus reachable distance; the sentinel is chosen large enough that no real distance collides with it.

Edge cases

A single-vertex graph needs no relaxations and reports no negative cycle. An unreachable vertex keeps the sentinel. A reachable negative cycle returns false; an unreachable one is skipped by the reachability guard. Weights may be negative, zero, or positive.

A variation

Without negative edges, Dijkstra is better, with O((V + E) log V). Bellman-Ford also underlies distance-vector routing, where each router uses only its own links and its neighbours' estimates.

Floyd-Warshall: All-Pairs Shortest Paths

The problem

Given a weighted directed graph, find the shortest distance between every pair of vertices at once, allowing negative edges but assuming no negative cycles.

Picture this

You want shortest routes between every pair of cities. Admit intermediate cities one at a time: direct roads first, then allow city 0 as a stop, then city 1 as well, and so on. When all cities are allowed, every shortest route is found.

Brute force, then better

Dijkstra from every vertex cannot tolerate negative edges, and Bellman-Ford from every vertex is O(V^2 × E), or O(V^4) on a dense graph. Floyd-Warshall fills one V × V table in O(V^3) with three nested loops.

import(lib) std::vec { Vec };

void floydWarshall(Vec<Vec<i64>>* dist) {
    usize n = dist->count();
    // k is the set of vertices allowed as intermediates
    for (usize k = 0; k < n; k += 1) {
        for (usize i = 0; i < n; i += 1) {
            // best known path from i to k
            i64 throughK = dist->atPtr(i)->at(k);
            if (throughK == 1000000000000000000) continue;   // no path i..k yet
            for (usize j = 0; j < n; j += 1) {
                // cost of routing i -> k -> j
                i64 candidate = throughK + dist->atPtr(k)->at(j);
                if (candidate < dist->atPtr(i)->at(j)) {
                    dist->atPtr(i)->set(j, candidate);
                }
            }
        }
    }
}

The table starts as the adjacency matrix: dist[i][j] is the direct edge weight, zero on the diagonal, and a large sentinel where no edge exists. The outer loop k is the set of allowed intermediates; for each pair (i, j) the code asks whether going through k is shorter. k must be outermost so that when it is processed, dist[i][k] and dist[k][j] already account for every lower-numbered intermediate.

Time and space

Three nested loops give Θ(V^3) time, and the table is Θ(V^2) space. Cubic cost is fine up to a few hundred vertices; Dijkstra from each vertex is faster on sparse graphs, while Floyd-Warshall suits dense graphs and negative edges.

Edge cases

Unreachable pairs keep the sentinel, and the throughK == sentinel check prevents adding two sentinels into an overshoot. A negative entry on the diagonal after the run (dist[i][i] < 0) means a negative cycle passes through i. Initialise the diagonal to 0 and non-edges to the sentinel, guarding it as shown, since it is finite and careless addition can overflow.

A variation

The same triple loop computes transitive closure by swapping arithmetic for boolean reachability (reach[i][j] = reach[i][j] || (reach[i][k] && reach[k][j])). Swapping + for max and < for > finds the minimax path. The triple-loop shape is a reusable engine.

Word Ladder

The problem

Given a begin word, an end word, and a dictionary, transform begin into end one letter at a time, where every intermediate word is in the dictionary and differs from its predecessor by exactly one letter. Return the number of words in the shortest transformation, or 0 if none exists.

Picture this

Each word is a vertex, and two words are adjacent when they differ in exactly one letter. The shortest transformation is a shortest path in an unweighted graph, so BFS from the begin word stops the moment the end word appears; the number of layers is the ladder length.

Brute force, then better

Building the whole graph by comparing every pair costs O(N^2 × L) before BFS even starts. Neighbours can instead be generated on demand by scoring each unused dictionary word, so BFS generates them as it goes, with a visited flag preventing duplicate enqueues.

import(lib) std::vec { Vec };
import(lib) std::collections::queue { Queue };

bool oneLetterApart(str a, str b) {
    // different lengths cannot differ by one
    if (a.len != b.len) return false;
    usize diff = 0;
    for (usize i = 0; i < a.len; i += 1) {
        if (a.at(i) != b.at(i)) diff += 1;
        // already too different to recover
        if (diff > 1) return false;
    }
    return diff == 1;
}

i32 wordLadder(str begin, str end, Vec<str>* words) {
    usize n = words->count();
    Vec<bool> used = Vec<bool>::new();
    for (usize i = 0; i < n; i += 1) {
        used.push(false);
    }
    // BFS frontier of the ladder
    Queue<str> q = Queue<str>::new();
    q.enqueue(begin);
    // the begin word is the first rung
    i32 steps = 1;
    while (!q.isEmpty()) {
        usize levelSize = q.count();
        for (usize k = 0; k < levelSize; k += 1) {
            str cur = q.dequeue();
            // reached the target: report the ladder length
            if (cur.equals(end)) return steps;
            for (usize i = 0; i < n; i += 1) {
                // never enqueue a word twice
                if (used.at(i)) continue;
                str w = words->at(i);
                if (oneLetterApart(cur, w)) {
                    // mark before enqueueing
                    used.set(i, true);
                    q.enqueue(w);
                }
            }
        }
        // finish a level, then count a new rung
        steps += 1;
    }
    return 0;
}

The queue holds words and used marks dictionary words already enqueued, so each word enters at most once. Instead of precomputing the graph, the inner loop scores every unused word against the current one with oneLetterApart, comparing byte by byte. The levelSize snapshot makes steps count words in the ladder, not expansions. Checking the end word on dequeue also handles begin equal to end.

Time and space

Every dictionary word is dequeued once, and each dequeue scans the whole dictionary, so O(N^2 × L) for N words of length L, the same order as building the graph but with far less memory and simpler code. The queue and visited array are O(N).

Edge cases

If begin equals end, the first dequeue returns 1. If the end word is not in the dictionary, it can never be enqueued and the function returns 0. Different lengths cannot be one letter apart, which oneLetterApart reports at once. The dictionary need not contain begin. All words are assumed the same length.

A variation

For large dictionaries, generate a word's neighbours by changing each position through 'a'..'z' and looking each result up in a hash set, which is much faster than scanning the list. Reconstructing the ladder uses the parent-pointer trick of 30.2. Bidirectional BFS, searching from both ends, sharply shrinks the explored set.

Clone a Graph

The problem

Given a connected undirected graph of nodes holding a value and a neighbour-pointer list, produce a deep copy: new nodes with the same values and connectivity, sharing no node with the original.

Picture this

Duplicating a web of friendships means each friend must also be a fresh person whose list points at fresh versions. Keep a map from each original node to its copy: the first time you meet a node, make its copy and record it, and every later reference resolves to that copy. The map stops recursion from chasing a cycle forever.

Brute force, then better

Without a map, a recursive copy follows an edge and then follows it back, looping forever on any cycle. The map breaks the cycle: each node is cloned once, the clone is recorded before its neighbours are visited, and later visits return the recorded clone. It is memoization applied to a graph traversal.

import(lib) std::vec { Vec };
import(lib) std::collections.hashmap { HashMap };
import(lib) std::mman { alloc };

struct GNode {
    i32 val;
    Vec<GNode*> neighbors;
}

usize hashI32(i32 k) { return (usize)k; }
bool eqI32(i32 a, i32 b) { return a == b; }

GNode* cloneNode(GNode* node, HashMap<i32, GNode*>* seen) {
    Option<GNode*> found = seen->get(node->val);
    if (found.isSome()) return found.unwrap();      // already cloned
    // allocate the fresh copy
    GNode* copy = alloc<GNode>(1);
    copy->val = node->val;
    copy->neighbors = Vec<GNode*>::new();
    seen->insert(node->val, copy);                  // record before recursing
    for (usize i = 0; i < node->neighbors.count(); i += 1) {
        // clone each neighbour; seen resolves cycles
        copy->neighbors.push(cloneNode(node->neighbors.at(i), seen));
    }
    return copy;
}

GNode* cloneGraph(GNode* start) {
    if (start == null) return null;
    HashMap<i32, GNode*> seen = HashMap<i32, GNode*>::new(hashI32, eqI32);
    return cloneNode(start, &seen);
}

The map ties each original value to its copy. The copy must go into the map before the neighbour loop: insert it afterward and a cycle recurses back to the original, fails to find a copy, and clones it again forever. Inserting first means a neighbour leading back returns the copy already under construction. node->neighbors is a Vec<GNode*> reached through the pointer, and auto-dereferencing lets the count and indexed read work.

Time and space

Every node is cloned once and every edge crossed once per direction, so O(V + E) time. The map holds one entry per vertex and each clone owns its neighbour list, so O(V + E) space, with recursion depth up to O(V) for a long path.

Edge cases

A null start returns null. A single isolated node clones with an empty neighbour list. Self-loops and repeated edges are copied faithfully rather than deduplicated. Keying by value assumes unique values; if values could repeat, key by node identity (a pointer).

A variation

The same clone-with-memo pattern copies any pointer-linked structure containing cycles: linked lists with loops, doubly linked structures, persistent trees. An iterative version uses a queue: clone the start, put it in the map and the queue, then repeatedly dequeue, clone each unseen neighbour, and append the clone to the current copy's list. Recursion and the explicit queue are the same traversal, with the bookkeeping moved from the call stack into a container.
