Live Examples: Stacks, Queues, and Linked Lists

The Shapes of Ordered Access

The last two chapters stored and looked up data. This one is about retrieval order and about storing without arrays.

A stack is a pile of plates: last in, first out. It drives undo, bracket matching, and call stacks.

A queue is a checkout line: first in, first out. It drives scheduling and breadth-first search.

A linked list is a treasure hunt: each clue points to the next. Inserting rewrites one arrow; reaching a clue means walking and jumping around memory. Chapter 16 introduced LinkedList<T>; here we build nodes to manipulate arrows directly.

Coral has no separate Stack type: a stack is a Vec used with push and pop. A queue is a Deque at one end or the Queue wrapper; the ring buffer lives in std::collections.deque and ringbuf (16.6). The structure is a pattern of access; Coral's containers supply the storage.

Valid Parentheses

The problem

Given a string of ()[]{}, decide whether the brackets are balanced: each opener closed by the matching kind, in order.

Picture this

Push openers. On a closer, pop and check the kind. An empty stack means nothing to close; a non-empty stack at the end means an opener was never closed. The nearest unmatched opener is always on top, so nesting is automatic.

Brute force

Repeatedly delete adjacent matching pairs and rescan: quadratic, and awkward because deletion shifts the string.

The better approach

One pass: opener push, closer pop and verify, and the stack must end empty. The stack enforces "most recent unmatched opener closes first."

The implementation

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

bool isValid(str s) {
    Vec<u8> stack = Vec<u8>::new();
    for (usize i = 0; i < s.len; i++) {
        u8 c = s.at(i);
        if (c == '(' || c == '[' || c == '{') {
            stack.push(c);
        } else {
            if (stack.isEmpty()) {
                return false;
            }
            u8 open = stack.pop();
            if (c == ')' && open != '(') return false;
            if (c == ']' && open != '[') return false;
            if (c == '}' && open != '{') return false;
        }
    }
    return stack.isEmpty();
}

The stack.isEmpty() check catches a closer with nothing to match (")"); the final return stack.isEmpty() catches an unmatched opener ("("). Forgetting the final check accepts "(".

The cost

Time is linear: each character is pushed and popped at most once. Space is linear in the worst case (all openers), unavoidable because the answer depends on nesting depth.

Edge cases and a variation

An empty string is valid; an odd-length string cannot be, so add if (s.len % 2 == 1) return false;. Variation: * stands for an opener, closer, or nothing, a small DP or greedy-with-stack problem. Another variation pushes each opener's index to report the first mismatch.

Min Stack

The problem

Design a stack that returns its minimum in constant time.

Picture this

Each box carries a note: "the smallest item at or below me," the smaller of its content and the note beneath it. The top note is the minimum.

Brute force

Scanning all elements per query is linear, failing the requirement.

The better approach

Two stacks. The data stack holds values; the minimum stack holds, at each level, the minimum from the bottom up. Push min(value, currentMin), pop both in lockstep; the top of the minimum stack is the answer.

The implementation

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

struct MinStack {
    Vec<i32> data;
    Vec<i32> mins;

    static MinStack new() {
        return MinStack {
            .data = Vec<i32>::new(),
            .mins = Vec<i32>::new()
        };
    }

    void push(i32 v) {
        self.data.push(v);
        if (self.mins.isEmpty() || v <= self.mins.back()) {
            self.mins.push(v);
        } else {
            self.mins.push(self.mins.back());
        }
    }

    void pop() {
        self.data.pop();
        self.mins.pop();
    }

    i32 top() {
        return self.data.back();
    }

    i32 getMin() {
        return self.mins.back();
    }

    bool isEmpty() {
        return self.data.isEmpty();
    }
}

The <= is deliberate: equal minima must both go on the minimum stack because both come off as data pops. A strict < would corrupt getMin once the first popped.

The cost

Every operation is constant time, including one extra push and pop for the minimum stack. Space is linear, twice a plain stack; that is the price of a constant-time query. Precompute on writes so reads are free.

Edge cases and a variation

The mins.isEmpty() branch handles the first push. getMin on an empty stack is misuse; the underlying back asserts (Chapter 15). A frugal variation stores only changes to the minimum: keep one minimum and a stack of old minima, pushed on a new smaller value and popped when it is removed. Constant time, less memory when values rarely decrease.

Evaluate Reverse Polish Notation

The problem

Evaluate postfix notation, where operators follow operands: ["2", "1", "+", "3", "*"] means (2 + 1) * 3 = 9.

Picture this

Each number is a completed piece; each operator combines the two most recent pieces into one. That is a stack: numbers go on; an operator pops two and pushes one.

Brute force

Evaluation is naturally linear. A naive list implementation searches backward for operands at each operator, making it quadratic.

The better approach

One pass: push numbers; on an operator, pop the right operand, then the left, apply, and push. Exactly one value remains.

The implementation

import(lib) std::vec { Vec };
import(lib) std::io::ios { parseI64, println };

bool isOperator(str t) {
    if (t.len != 1) return false;
    u8 c = t.at(0);
    return c == '+' || c == '-' || c == '*' || c == '/';
}

i32 applyOp(u8 op, i32 a, i32 b) {
    if (op == '+') return a + b;
    if (op == '-') return a - b;
    if (op == '*') return a * b;
    return a / b;
}

i32 evalRPN(const Vec<str>* tokens) {
    Vec<i32> stack = Vec<i32>::new();
    for (usize i = 0; i < tokens->count(); i++) {
        str t = tokens->at(i);
        if (isOperator(t)) {
            i32 b = stack.pop();
            i32 a = stack.pop();
            stack.push(applyOp(t.at(0), a, b));
        } else {
            bool ok = false;
            i64 n = parseI64(t, &ok);
            stack.push((i32)n);
        }
    }
    return stack.pop();
}

The critical line is the pop order: b before a, then applyOp(op, a, b), because b was the top and therefore the right operand. Reversing them is the classic RPN bug: correct for addition and multiplication, wrong for subtraction and division.

The cost

Time is linear: one pass, constant work per token. Space is linear in the worst case, a long run of numbers.

Edge cases and a variation

A well-formed expression leaves one value; a malformed one underflows, and the pop assertion catches it. Division truncates toward zero. Promote the stack to i64 for large inputs to avoid overflow. Variation: push node pointers and combine subtrees into operator nodes, building an abstract syntax tree (Chapter 13's Expr variant) to evaluate, print, or compile.

Daily Temperatures

The problem

For each day, return how many days until a warmer day, or 0 if none comes.

Picture this

Keep a monotonic stack of waiting days, temperatures decreasing bottom to top. A warmer day resolves every waiting day it beats; those pop and record answers. The stack never holds a day after its warmer arrives.

Brute force

Look forward from each day for a warmer one: quadratic when temperatures strictly decrease.

The better approach

One pass with indices of waiting days. For day i, while the stack is non-empty and today is warmer than the temperature at the top index, pop that index j and record i - j; then push i. Days left at the end keep zero.

The implementation

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

Vec<i32> dailyTemperatures(const Vec<i32>* t) {
    Vec<i32> out = Vec<i32>::new();
    for (usize i = 0; i < t->count(); i++) {
        out.push(0);
    }

    Vec<usize> stack = Vec<usize>::new();
    for (usize i = 0; i < t->count(); i++) {
        while (!stack.isEmpty() && t->at(i) > t->at(stack.back())) {
            usize j = stack.pop();
            out.set(j, (i32)(i - j));
        }
        stack.push(i);
    }
    return out;
}

Indices, not temperatures, let a later day compute the wait i - j; the answer is a distance. The comparison is strict >, so equal temperatures do not resolve each other.

The cost

Time is linear: each index is pushed once and popped at most once. Space is linear in the worst case, a strictly decreasing list.

Edge cases and a variation

Empty or single-element lists yield all zeroes. Equal temperatures leave both days waiting. Variation: next greater element to the right uses the same decreasing stack; for "colder" use an increasing stack. The only choice is the stack's order.

Implement a Queue Using Two Stacks

The problem

Implement a FIFO queue with only two stacks.

Picture this

Enqueue onto the "in" pile. To dequeue, move plates to the "out" pile, reversing them, then take the top. Reversing only when the out pile is empty means each plate moves once and service order is arrival order.

Brute force

One stack serves the newest first. Copying the whole stack on every dequeue is O(n) per dequeue and no better.

The better approach

Two stacks, inStack and outStack. Enqueue pushes onto inStack. Dequeue, when outStack is empty, pours all of inStack into outStack, then pops. A single dequeue can cost O(n), but each element is poured once, so the amortized cost is constant.

The implementation

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

struct StackQueue {
    Vec<i32> inStack;
    Vec<i32> outStack;

    static StackQueue new() {
        return StackQueue {
            .inStack = Vec<i32>::new(),
            .outStack = Vec<i32>::new()
        };
    }

    void enqueue(i32 v) {
        self.inStack.push(v);
    }

    i32 dequeue() {
        if (self.outStack.isEmpty()) {
            while (!self.inStack.isEmpty()) {
                self.outStack.push(self.inStack.pop());
            }
        }
        return self.outStack.pop();
    }

    bool isEmpty() {
        return self.inStack.isEmpty() && self.outStack.isEmpty();
    }

    usize count() {
        return self.inStack.count() + self.outStack.count();
    }
}

The lazy pour is the point: pour on every enqueue and elements move repeatedly. Pouring only when needed moves each element exactly twice, into the in stack and then the out stack.

The cost

Enqueue is constant; dequeue is O(n) when it pours but amortized constant, because each element is poured once. This is the same accounting that makes Vec pushes constant on average (Chapter 16). Space is linear.

Edge cases and a variation

Dequeuing from empty asserts. An enqueue then dequeue works on the first pour. In practice, std::collections::queue { Queue } provides constant-time enqueue, dequeue, and peek from a ring buffer (16.6). The two-stack queue is an interview exercise in amortized analysis, not production code.

Reverse a Linked List

The problem

Given a singly linked list's head, reverse it and return the new head.

Picture this

Walk and turn each arrow around. Keep three fingers: previous, current, and next, because overwriting the current arrow would lose your place. Saving "next" before the rewrite is the detail people forget.

Brute force

Copy values into an array and rebuild in reverse: linear time and space, but it misses the point of manipulating links in place.

The better approach

Iterate with three pointers: save next, point current's next at prev, then advance all three. When current falls off the end, prev is the new head.

The implementation

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

struct Node {
    i32 value;
    Node* next;
}

Node* newNode(i32 v) {
    Node* n = alloc<Node>(1);
    n->value = v;
    n->next = null;
    return n;
}

Node* reverseList(Node* head) {
    Node* prev = null;
    Node* cur = head;
    while (cur != null) {
        Node* next = cur->next;
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}

The recursive version shows what the explicit "next" finger does:

Node* reverseRec(Node* head) {
    if (head == null || head->next == null) {
        return head;
    }
    Node* newHead = reverseRec(head->next);
    head->next->next = head;
    head->next = null;
    return newHead;
}

It reverses the tail, then stitches the current node onto the end. Shorter and worse: stack space is proportional to length, so a hundred thousand nodes can overflow the call stack; the iterative version uses constant space.

The cost

Iterative: linear time, one pass, constant space. Recursive: linear time but linear stack space. Freeing nodes is separate from reversing (see the exercises), the boundary between an algorithm and Chapter 11's ownership discipline.

Edge cases and a variation

An empty list returns null; a single node returns itself. Variation: reverse the sub-list between m and n, using the same walk plus a saved node before the interval and one extra stitch.

Merge Two Sorted Linked Lists

The problem

Given two sorted linked lists, merge them into one sorted list, reusing nodes.

Picture this

Compare the two fronts, take the smaller, and append. The smallest remaining card is always at a front, so the greedy choice is correct. A dummy head avoids special-casing the first card; keep a tail pointer.

Brute force

Collect both lists, concatenate, sort, and rebuild: O((m+n) log(m+n)) instead of O(m+n), and it allocates.

The better approach

Merge in place with a dummy head and tail. While both lists have nodes, append the smaller and advance that list. When one runs out, append the other's entire remainder with one pointer assignment. Free the dummy and return its next.

The implementation

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

struct Node {
    i32 value;
    Node* next;
}

Node* newNode(i32 v) {
    Node* n = alloc<Node>(1);
    n->value = v;
    n->next = null;
    return n;
}

Node* mergeTwoLists(Node* a, Node* b) {
    Node* dummy = newNode(0);
    Node* tail = dummy;
    while (a != null && b != null) {
        if (a->value <= b->value) {
            tail->next = a;
            a = a->next;
        } else {
            tail->next = b;
            b = b->next;
        }
        tail = tail->next;
    }
    tail->next = (a != null) ? a : b;
    Node* result = dummy->next;
    dealloc<Node>(dummy);
    return result;
}

The <={ makes the merge stable: equal fronts take a first. With <, equal elements from b jump ahead. The dummy makes the first output node just another node, removing the special case.

The cost

Time is linear in the combined length; each iteration consumes one node. Space is constant: a few pointers and a temporary dummy, freed before returning. Nodes are reused, so the loop allocates nothing.

Edge cases and a variation

An empty input appends the other list; two empty inputs give null. Variation: merge k sorted lists. Pairwise merging is O(N log k) with rescans; better is a min-heap of the k fronts, O(N log k) with no rescans, exactly Chapter 16's PriorityQueue.

Linked List Cycle

The problem

Decide whether a linked list contains a cycle.

Picture this

Two runners, one step and two steps per tick. On a straight track the fast one reaches the end; on a loop it laps the slow one. Standing on the same spot proves a cycle. This is Floyd's tortoise-and-hare, using no extra memory.

Brute force

Record visited nodes in a set; reaching a recorded node means a cycle. Linear time and linear extra space.

The better approach

Slow advances one, fast two. If fast falls off the end, no cycle; if they meet, a cycle. Constant space and linear time, since the gap shrinks by one each tick inside the loop.

The implementation

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

struct Node {
    i32 value;
    Node* next;
}

Node* newNode(i32 v) {
    Node* n = alloc<Node>(1);
    n->value = v;
    n->next = null;
    return n;
}

bool hasCycle(Node* head) {
    Node* slow = head;
    Node* fast = head;
    while (fast != null && fast->next != null) {
        slow = slow->next;
        fast = fast->next->next;
        if (slow == fast) {
            return true;
        }
    }
    return false;
}

The condition must check fast != null and fast->next != null before fast->next->next. Checking only fast misses the second hop, a null dereference on any even-length list.

The cost

Time is linear: acyclic fast reaches the end in about n/2 ticks; cyclic the pointers meet within one loop length. Space is constant, the point over set-marking.

Edge cases and a variation

Empty and single-node lists return false; a self-loop is detected immediately. Variation: find the cycle entry. After the meeting, move one pointer to the head and advance both one step; they meet at the entry. The proof is distance arithmetic. The same idea solves Chapter 26's Happy Number.

Sliding Window Maximum

The problem

Given an array and width k, return the maximum of every contiguous window. For [1, 3, -1, -3, 5, 3] with k = 3, the answer is [3, 3, 5, 3].

Picture this

Keep a decreasing deque of candidate indices; its front is the window maximum. A new value removes from the back every candidate it beats, since they can never be maximum while it remains. Insert it; drop the front when it leaves the window. Indices let you detect that.

Brute force

Scan each window's k elements: O(n · k), quadratic when k is a constant fraction of n.

The better approach

One pass with a deque of indices whose values strictly decrease. Before inserting i, pop from the back while its value is less than or equal to v[i]; those are dominated forever. Insert i, pop the front if outside the window, and once full the front is the answer. Each index enters and leaves once.

The implementation

import(lib) std::vec { Vec };
import(lib) std::collections::deque { Deque };
import(lib) std::io::ios { println };

Vec<i32> maxSlidingWindow(const Vec<i32>* nums, usize k) {
    Vec<i32> out = Vec<i32>::new();
    Deque<usize> dq = Deque<usize>::new();
    for (usize i = 0; i < nums->count(); i++) {
        while (!dq.isEmpty() && nums->at(dq.back()) <= nums->at(i)) {
            dq.popBack();
        }
        dq.pushBack(i);
        if (dq.front() + k <= i) {
            dq.popFront();
        }
        if (i + 1 >= k) {
            out.push(nums->at(dq.front()));
        }
    }
    return out;
}

The <= is deliberate: a new equal value retires the old candidate because the newer index outlives it. Strict < leaves stale equals and wastes space but remains correct. dq.front() + k <= i means the front has left [i - k + 1, i].

The cost

Time is linear: each index is pushed once and popped once from either end. Space is O(k). Each element is discarded once.

Edge cases and a variation

A window wider than the array yields an empty result; k = 1 returns the array. A strictly decreasing array keeps every index, the worst case for space and still linear time. Variation: return the maximum with its index via dq.front(); a sliding minimum flips the comparison to an increasing deque.

Implement a Stack Using Queues

The problem

Implement a LIFO stack using only enqueue and dequeue.

Picture this

A queue serves oldest first. Make a push wait behind everything present by rotating: enqueue the new element, then dequeue and re-enqueue every older element once, so the new one reaches the front. Then pop is just dequeue.

Brute force

A single queue cannot pop the newest directly. Dequeuing everything, taking the last, and re-enqueuing is O(n) per pop.

The better approach

One queue, rotate on push. Push v, note the older count, then move exactly those elements from front to back. Now v is at the front and pop is O(1). Push is O(n), the mirror image of 26.5.

The implementation

import(lib) std::vec { Vec };
import(lib) std::collections::queue { Queue };
import(lib) std::io::ios { println };

struct QueueStack {
    Queue<i32> q;

    static QueueStack new() {
        return QueueStack { .q = Queue<i32>::new() };
    }

    void push(i32 v) {
        usize older = self.q.count();
        self.q.enqueue(v);
        for (usize i = 0; i < older; i++) {
            self.q.enqueue(self.q.dequeue());
        }
    }

    i32 pop() {
        return self.q.dequeue();
    }

    i32 top() {
        return self.q.peek();
    }

    bool isEmpty() {
        return self.q.isEmpty();
    }
}

older is captured before the enqueue, so the rotation moves exactly the elements that preceded v. Rotate the wrong count and v lands wrong. peek reads the front, already the newest.

The cost

Push O(n), pop O(1), trading against 26.5's enqueue O(1), dequeue amortized O(1). Both ends cannot be constant with one queue; the asymmetry is the point. Space is linear.

Edge cases and a variation

Popping empty asserts through dequeue. Pushing empty rotates nothing. Variation: use two queues, enqueuing onto the secondary and moving the primary into it; the analysis is 26.5 backward. A second variation makes push O(1) and pop pay the rotation.

Remove the Nth Node From the End

The problem

Given a linked list and n, remove the nth node from the end in one pass.

Picture this

Space fast n nodes ahead of slow. When fast reaches the last node, slow is exactly n from the end, so the target is after slow. Advance in lockstep, then unlink.

Brute force

Count the length, then walk to (length - n) and unlink. Two passes and easy off-by-one arithmetic, but correct.

The better approach

One pass with two pointers and a dummy before the head. Slow and fast start at the dummy, fast takes n + 1 steps, and when fast is null, slow is just before the target. Unlink, free, and return dummy->next.

The implementation

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

struct Node {
    i32 value;
    Node* next;
}

Node* newNode(i32 v) {
    Node* n = alloc<Node>(1);
    n->value = v;
    n->next = null;
    return n;
}

Node* removeNthFromEnd(Node* head, i32 n) {
    Node* dummy = newNode(0);
    dummy->next = head;
    Node* fast = dummy;
    Node* slow = dummy;

    for (i32 i = 0; i <= n; i++) {
        if (fast == null) {
            break;
        }
        fast = fast->next;
    }
    while (fast != null) {
        fast = fast->next;
        slow = slow->next;
    }

    Node* target = slow->next;
    if (target != null) {
        slow->next = target->next;
        dealloc<Node>(target);
    }

    Node* result = dummy->next;
    dealloc<Node>(dummy);
    return result;
}

The gap is n + 1, not n: when fast falls off the end, slow is on the node before the target, whose next must be rewritten. A gap of n lands slow on the target, unreachable predecessor.

The cost

Time is linear, one pass. Space is constant: two pointers and a dummy, freed before returning. The removed node is freed at unlink time. This is 26.7's dummy trick applied to deletion.

Edge cases and a variation

Removing the only node leaves the head null. Removing the first node of a longer list needs no branch, the reason for the dummy. If n exceeds the length, nothing is removed rather than crashing. Variation: remove a middle node given only a pointer in O(1) by copying the next value and unlinking the next; it fails on the last node.

Add Two Numbers

The problem

Two non-negative integers are linked lists of digits in reverse order, one digit per node. Add them and return the sum in the same format. (2 -> 4 -> 3) plus (5 -> 6 -> 4) is (7 -> 0 -> 8), since 342 + 465 = 807.

Picture this

Column addition, least significant digit first. Add the digits and carry, write the units digit, pass the tens along. A dummy head owns the result and a tail extends it. Continue while either list has digits or a carry remains.

Brute force

Convert each list to an integer, add, and convert back: it overflows for interesting lengths and discards position-by-position addition.

The better approach

Walk both lists with carry. Sum the carry and existing digits, set the new digit to sum % 10 and carry to sum / 10, then append. The condition a not done, b not done, or carry nonzero lets a final carry become a node.

The implementation

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

struct Node {
    i32 value;
    Node* next;
}

Node* newNode(i32 v) {
    Node* n = alloc<Node>(1);
    n->value = v;
    n->next = null;
    return n;
}

Node* addTwoNumbers(Node* a, Node* b) {
    Node* dummy = newNode(0);
    Node* tail = dummy;
    i32 carry = 0;

    while (a != null || b != null || carry != 0) {
        i32 sum = carry;
        if (a != null) {
            sum = sum + a->value;
            a = a->next;
        }
        if (b != null) {
            sum = sum + b->value;
            b = b->next;
        }
        carry = sum / 10;
        tail->next = newNode(sum % 10);
        tail = tail->next;
    }

    Node* result = dummy->next;
    dealloc<Node>(dummy);
    return result;
}

Least-significant-first digits let the carry flow with the list, with no reversal. Inputs are read but not consumed; the caller owns them. Only the dummy is allocated and freed; the new nodes belong to the result.

The cost

Time is linear in the longer list, plus one step for a final carry. Space is linear in the result, at most one node longer than the longer input. Each column sums at most 9 + 9 + 1 = 19, so i32 suffices.

Edge cases and a variation

Two empty lists give a single 0 node; adjust if you want empty. Different lengths work through the null guards. Variation: most-significant-first digits force a reversal or recursive carry deferral. A second variation subtracts with borrowing, the same skeleton with borrow and sign.

Palindrome Linked List

The problem

Decide whether a singly linked list is a palindrome in O(n) time and O(1) extra space.

Picture this

Find the middle with slow and fast pointers, reverse the second half, and compare from the outside in. Then reverse the second half again to restore the list; a good function leaves its input unchanged.

Brute force

Copy values into a vector and use 24.2's two-pointer test: linear time but linear extra space.

The better approach

Middle pointers, 26.6's reversal for the back half, a lockstep comparison, then a restore. The new idea is only that these combine and the mutation must be undone.

The implementation

import(lib) std::mman { alloc, dealloc };
import(lib) std::io::ios { println };

struct Node {
    i32 value;
    Node* next;
}

Node* newNode(i32 v) {
    Node* n = alloc<Node>(1);
    n->value = v;
    n->next = null;
    return n;
}

Node* reverseList(Node* head) {
    Node* prev = null;
    Node* cur = head;
    while (cur != null) {
        Node* next = cur->next;
        cur->next = prev;
        prev = cur;
        cur = next;
    }
    return prev;
}

bool isPalindromeList(Node* head) {
    if (head == null || head->next == null) return true;

    Node* slow = head;
    Node* fast = head;
    while (fast->next != null && fast->next->next != null) {
        slow = slow->next;
        fast = fast->next->next;
    }

    Node* second = reverseList(slow->next);
    Node* p1 = head;
    Node* p2 = second;
    bool ok = true;
    while (p2 != null) {
        if (p1->value != p2->value) {
            ok = false;
            break;
        }
        p1 = p1->next;
        p2 = p2->next;
    }

    slow->next = reverseList(second);
    return ok;
}

The middle loop leaves slow on the last node of the first half for even and odd lengths, so slow->next starts the second half. Comparing while p2 is non-null ignores the odd middle node. reverseList(second) restores the link.

The cost

Time is linear: each pass touches each node a constant number of times. Space is constant: four pointers, no allocation. This earns its keep only for large lists.

Edge cases and a variation

Empty and single-node lists are palindromes before any mutation. A two-node list is a palindrome only if values match. Skipping the restore silently reorders the caller's list. Variation: drop the final reversal if destroying the input is allowed. A second variation checks a palindrome after at most one deletion, following 24.2.

Largest Rectangle in Histogram

The problem

Given bar heights, find the largest rectangle entirely under the skyline. For [2, 1, 5, 6, 2, 3] the answer is 10, from the bars of height 5 and 6.

Picture this

Each bar can stretch left and right until a shorter bar blocks it. A monotonic increasing stack finds the boundaries: when a shorter bar arrives, each taller bar learns its right boundary, and its left boundary is the bar below on the stack. Pop, compute area, keep the best.

Brute force

Expand left and right from each bar while neighbours are at least as tall: O(n²), re-expanding the same gaps.

The better approach

One pass with a stack of increasing heights. Before pushing i, pop every index with height greater than or equal to h[i], because i is its right boundary. For a popped j, height is h[j], left boundary is the new top plus one (or 0), and width is i - left. A zero-height sentinel at the end flushes the stack. Use i64; wide histograms overflow i32.

The implementation

import(lib) std::vec { Vec };
import(lib) std::io::ios { println };

i64 largestRectangle(const Vec<i32>* h) {
    Vec<usize> stack = Vec<usize>::new();
    i64 best = 0;
    usize n = h->count();

    for (usize i = 0; i <= n; i++) {
        i64 cur = (i == n) ? 0 : (i64)h->at(i);
        while (!stack.isEmpty() && (i64)h->at(stack.back()) >= cur) {
            i64 height = (i64)h->at(stack.pop());
            usize left = stack.isEmpty() ? 0 : stack.back() + 1;
            i64 width = (i64)(i - left);
            i64 area = height * width;
            if (area > best) best = area;
        }
        stack.push(i);
    }
    return best;
}

The zero bar at i == n is the sentinel, hence the loop runs one past the end. The new top after a pop is the nearest shorter bar on the left, so stack.back() + 1 is the first column. >= retires equal heights too; > is still correct but defers them. Each bar pops once.

The cost

Time is linear: each index is pushed once and popped once. Space is O(n), a strictly increasing histogram. The same accounting as 26.4's monotonic stack, with different bookkeeping on pop.

Edge cases and a variation

An empty histogram returns zero; a single bar returns its height. A non-decreasing histogram keeps every bar until the sentinel, then pops right to left. Variation: maximal rectangle in a binary matrix, running this per row with 1s as heights and a 0 resetting a column. The same stack, row by row.
