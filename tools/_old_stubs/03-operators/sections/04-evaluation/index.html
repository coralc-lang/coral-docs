Expressions, order, and side effects

An expression is a piece of code that computes a value. When expressions call functions or change variables, their order can affect what a program does.

Draft lesson · compiler tests required

Start with one small expression

i32 sum = left + right;

The plus expression uses two named values and produces a value used to initialize sum. This illustrates expression shape; compile it with declared variables before relying on it as a runnable program.

Precedence: which operation groups first?

In a mathematical expression such as a + b * c, a reader wants to know whether it means a + (b * c) or (a + b) * c. A language defines grouping rules called precedence and associativity. The token enum does not tell us those rules.

When in doubt in real code, parentheses make the intended grouping visible. For documentation, test each precedence claim against the parser and compiler rather than importing a table from C.

Side effects make order observable

A pure calculation only produces a value. A side effect changes something the rest of the program can observe, such as updating a variable or printing output. To learn whether Coral evaluates subexpressions left-to-right, build a tiny program where each subexpression records that it ran, then inspect the result.

Associativity is not precedence

Precedence answers which operator binds more tightly when different operators are next to each other. Associativity answers how repeated operators at the same level group. They are different questions and should be tested separately.

What this lesson needs before being final

Run compiler tests for representative operator pairs, parenthesized variants, chained assignments, function calls with visible side effects, and short-circuit expressions. Until then this page teaches the questions to ask, not unverified answers.
