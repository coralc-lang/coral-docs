Comparing values

A comparison asks a question about two values. The result is typically used to decide what a program should do next, but the exact accepted types and result rules must come from Coral's compiler.

Vocabulary-confirmed · typing rules pending

Ordering comparisons

The supplied token list contains these spellings:

<   >   <=   >=

They are conventionally read as “less than,” “greater than,” “less than or equal to,” and “greater than or equal to.” Thinking in words makes it easier to catch reversed comparisons.

Equality is not assignment

=   assignment token
==  equality token
!=  inequality token

One equals sign and two equals signs are different tokens. One appears in declarations and assignments; the two-mark form is the equality token. Coral’s lexer also names NotEqual for !=.

The alignment above is a vocabulary illustration, not Coral code to compile.

Ask a question in plain English

For the expression left < right, say “is left less than right?” before reading the surrounding code. That gives the comparison an understandable meaning. Then verify that both operands have compatible types and that the result fits the context.

What equality means for complex values

The token list proves that an equality token exists; it does not tell us how equality works for strings, structs, pointers, or variants. Do not assume values are compared field-by-field or by address. That requires type-checker documentation or direct tests.
