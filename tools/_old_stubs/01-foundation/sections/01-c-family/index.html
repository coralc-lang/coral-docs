Familiar syntax, new capabilities

If you know a little C, much of Coral’s surface will look familiar. If you don’t, the useful starting point is still simple: Coral writes declarations explicitly, uses braces to group blocks, and uses semicolons to end statements.

Beginner lesson · examples from current workspace source

What does “C-family” mean?

“C-family” is a description of the language’s visible shape, not a promise that every C rule also applies to Coral. In both languages you can see a type before a variable name, a function’s result type before its name, braces around a function body, and semicolons at the ends of statements.

For example, read i32 count = 42; as: “make a variable named count, whose type is i32, and initialize it with 42.” The spelling is compact, but each piece has a visible place.

Why keep that familiar shape?

When a type appears first, a reader sees what kind of thing is being declared before reaching its name. For a function, the first type tells us what the function returns. For a field, the first type tells us what kind of value the field stores. That is the “type-first” reading habit we will practise in the next lesson.

Coral could have replaced this with a different style, but it keeps the C-family structure and adds features such as generic declarations and variants within it. That is the design direction visible in the sample; detailed performance and safety guarantees need separate compiler evidence.

What is different from plain C?

The current program contains syntax that is not plain C: generic parameters such as <T, U>, the variant declaration, and the extend block. Coral also writes a function type in a more direct form, such as T(U, i32) fn;. Those features let the language express richer type relationships without adopting a completely different declaration style.

Do not worry yet about how each of those features behaves. We will give each one its own lesson after learning how to read the declarations.

One tiny reading exercise

Look at this signature and say what you know before reading the body:

struct(i32, i32) foooo()

You can already tell that the function is named foooo, has no listed parameters, and returns a tuple-like type containing two i32 types. That is the benefit of a visible declaration: useful information arrives before the function’s implementation.

Takeaway

Coral’s syntax has a familiar C-family backbone, but it is not “just C.” Read the declarations first; then learn each newer construct on its own terms. Next: why types appear before names, including in function-pointer declarations.
