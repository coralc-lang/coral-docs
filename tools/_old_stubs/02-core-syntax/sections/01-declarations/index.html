Declarations: type, name, value

A declaration gives the compiler a name to remember. Usually, it also tells the compiler what kind of value that name refers to.

Read a declaration like a small sentence

i32 count = 42;

Read the line as: “declare a value of type i32; its name is count; start it with 42.” The pieces are always worth locating: type, name, equals sign, initial value, semicolon.

The semicolon marks the end of this statement. It is punctuation with a job, much like the period at the end of this sentence.

Why put the type first?

Put your finger on the first word, i32. Before you read the name, you already know what sort of value this declaration intends to hold. This is Coral’s type-first reading order.

The same order is used in function declarations. A return type comes first, so a reader can see what kind of answer the function promises to produce before reading its name or body.

Fields use the same visible order

struct Pair {
    i32 first;
    i32 second;
}

Inside this struct, each field has its type before its field name. first and second are not mysterious storage slots: their declarations tell us each one is an i32.

This is an introductory example of the syntax. Before treating this exact named struct spelling as compiler-verified, compile it with the current Coral compiler.

What is an initializer?

The part after = is the initializer: the first value assigned by the declaration. In i32 count = 42;, the initializer is 42. The equals sign here belongs to a declaration. Other contexts may use = for assignment; we will keep those ideas distinct when we reach operators.

Quick check

In f64 ratio = 0.5;, identify the type, name, and initial value. Answer: f64, ratio, and 0.5. If you can point to each part, you can read the basic shape of a Coral declaration.
