Literals: values written directly

A literal is a value written directly in the source, instead of reached through a variable name or function call. The lexer sorts literals into categories before the rest of the compiler reasons about them.

Vocabulary-confirmed · detailed parsing rules need tests

Integer spellings

The supplied token list distinguishes decimal, hexadecimal, binary, and octal integer tokens. That means the lexer intends to recognize more than one base for writing whole-number literals.

var decimalValue = 42;
var hexValue = 0x2a;

The exact accepted prefixes and suffixes need compiler examples. The token names alone do not tell us how to write every base.

Floating-point literals

A floating-point literal is a number written with a fractional part, like 3.14. The sample includes exactly that spelling. The lexer also has a separate Float token. The type chosen for the literal is a separate rule from recognizing its spelling.

Strings and C strings

The lexer distinguishes String, CString, and RawString. The current source uses an ordinary quoted string and a C-prefixed string:

var text = "ordinary text";
var cText = C"text for a C-style API";

The token comment says a C string is null-terminated and has no length. That is a useful implementation note, but escape syntax and raw-string delimiters should be demonstrated with tests before becoming a full lesson.

Characters, booleans, and null

The lexer vocabulary includes a character-literal token and the true, false, and null tokens. They represent distinct literal categories. What types they receive in every context is a type-system question, not something we should infer from their spelling.

Why does token category matter?

Think of the lexer as a reader that first sorts each piece of source into a labeled pile: identifier, keyword, integer, string, operator, and so on. Later stages use those labels to understand the program. The labels help us describe the language, but they are only the first step of compilation.
