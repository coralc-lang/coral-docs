Statements, braces, and whitespace

Programs are made of smaller instructions. Punctuation marks help the compiler see where one instruction ends and where a group of instructions begins.

Starter lesson · visible forms in current source

Semicolons mark statement endings

The current Coral examples end declarations and return statements with semicolons:

var answer = 42;
return answer;

A semicolon is not decoration: it is a token the parser can use to separate statements. Exact places where it is optional or required should be checked against the grammar.

Braces group a body

pub void main()
{
    var answer = 42;
    println("{}", answer);
}

The braces make the function body visible. Indentation helps people see the grouping, but the braces are the explicit delimiters in the syntax shown here.

Whitespace helps people read

Spaces and line breaks make code easier to scan. Do not assume that all whitespace is insignificant everywhere: string contents, comments, and token boundaries matter. The parser and lexer define precisely which whitespace may be rearranged safely.

Small exercise

In the example, point to each statement-ending semicolon and the braces that group the body. Then reformat the indentation without changing any tokens. The program’s grouping should still be apparent because the delimiters remain.
