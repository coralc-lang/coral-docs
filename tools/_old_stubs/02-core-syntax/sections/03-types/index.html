Built-in type vocabulary

A type name is a promise about what sort of value a declaration describes. Coral’s lexer has explicit names for several built-in categories.

Vocabulary-confirmed · semantic guarantees vary

Integers: signed and unsigned names

The token list names signed integers from i8 through i128, and unsigned integers from u8 through u128. The number in each name points to a width in bits in the naming scheme; the supplied lexer comment warns that 128-bit support may depend on a platform flag.

“Signed” is the family intended to represent negative as well as non-negative values; “unsigned” is the non-negative family. That is the naming convention, but exact ranges, target support, and overflow behavior must be confirmed against the compiler and target.

i32 signedCount = -1;
u64 byteCount = 12;

These examples illustrate the naming. Test them with the current compiler before using them as guaranteed working examples.

Floating-point names

The lexer names f32 and f64. The workspace sample also initializes a local from 3.14, but does not explicitly state which floating-point type that literal gets. Do not infer the answer from a different language.

Other built-in names

The token vocabulary also lists bool, char, void, usize, isize, rawptr, and str. Their names suggest their roles, but a useful reference must verify the exact representation and operations.

  • bool: a boolean-like type name.
  • char: a character-like type name.
  • void: appears as the return type of main in the sample.
  • usize and isize: size-related integer names.
  • rawptr and str: pointer/string-related names.

Token names are not a complete specification

The lexer recognizes words before later compiler stages decide whether a declaration is valid for the selected target and context. That is why we call this a vocabulary lesson. The type checker and compiler tests are the next evidence needed for widths, ranges, conversions, and supported operations.
