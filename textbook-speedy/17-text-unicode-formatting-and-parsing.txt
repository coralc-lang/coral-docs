Chapter17

Text, Unicode, Formatting, and Parsing

A String Is Not a Pointer With a Zero Somewhere

In C, a string is a pointer to bytes ended by a zero byte, with no length. Every string bug of the last fifty years grows from that decision. Coral does not repeat it.

Coral's text layer centres on two types. `str` is the borrowed view: a pointer and a length, never owning its bytes. `String` is the owned, growable buffer, like a `Vec<u8>` with text-aware methods. Around them sit modules for ASCII, UTF-8, searching, regex, URIs, formatting, and parsing.

17.1 str: The Borrowed View

`str` is built into the language, not a library. Conceptually it is two words:

    // conceptually
    struct str {
        const u8* ptr;
        usize len;
    }

A string literal is a `str`; `slice` returns a `str` pointing into the original buffer; passing a string passes the pointer and length, not a copy. Measuring is therefore O(1):

    str greeting = "hello";
    usize n = greeting.len;               // 5, known, never a strlen walk
    u8 first = greeting.ptr[0];           // 'h'

A `str` is the default parameter type for read-only text: it accepts a literal, a slice of a `String`, or a window into a larger buffer without copying. It never owns its bytes, so its lifetime is bounded by the owner; a stored `str` can dangle. Use it for parameters and short-lived locals, not for struct fields that outlive their source.

A `str` is a window into a book someone else holds; a `String` is a notebook you own. `str` is for reading, `String` for building.

Read methods live in `core::str`; `std::text::strutil` adds free-function forms. The `str` methods are:

    str s = "  Coral Text  ";

    str t     = s.trim();                 // "Coral Text"
    str start = s.trimStart();
    str end   = s.trimEnd();
    str win   = s.slice(2, 7);            // "Coral"

    bool eq   = s.equals("hi");
    i32 ord   = s.compare("other");       // <0, 0, >0

    bool has  = s.containsView("Coral");
    bool hasB = s.containsByte('T');
    usize at  = s.findView("Text");       // byte index, or len if absent
    usize cat = s.findByte('C');
    usize last= s.rfindByte('l');

    bool pre  = s.startsWith("  ");
    bool suf  = s.endsWith("  ");
    bool dig  = s.isAsciiDigit();         // false unless every byte is a digit
    bool alp  = s.isAsciiAlpha();
    bool aln  = s.isAsciiAlnum();
    bool none = s.isEmpty();              // true when len == 0
    u8   b    = s.at(0);                  // bounds-checked byte (asserts idx < len)
    const u8* bytes = s.asU8();           // the raw pointer behind the view

    String alias = s.asString();          // ALIASES these bytes, see the warning below

Two methods handle Unicode: `codepointCount` counts codepoints, and `nextCodepoint` decodes one at a time with a threaded byte cursor:

    usize count = s.codepointCount();     // characters, not bytes

    usize idx = 0;
    char c;
    while (s.nextCodepoint(&idx, &c)) {
        println("{}", c);
    }

`idx` continues where the last call stopped, so UTF-8 decodes forward without a cursor object and `str` stays a zero-cost view.

The view has no mutating or reallocating methods: no `toUpper`, `replace`, or `push`, because it owns nothing and cannot grow. Transforms live on `String` or in `strutil` and return a fresh value. `equals` and `compare` compare content (`compare` returns negative, zero, or positive); `findView`, `findByte`, and `rfindByte` return a byte index, or `len` when absent, so `containsView` and `containsByte` test that result against `len`.

Two constructors interface with C:

    str a = str::fromCstr(cstr);                  // borrow a NUL-terminated C string
    str b = str::fromParts(ptr, len);             // wrap a pointer and a length
    str empty = str::empty();                     // the zero-length view

`fromCstr` pays the `strlen` scan once and returns a length-carrying view thereafter.

`str::asString` does not allocate or copy: it builds a `String` whose pointer and length alias the `str`'s bytes, with capacity zero. It is only safe as a zero-copy bridge in argument position; never `free` it or let `@drop` run, or you deallocate someone else's memory. Use `String::from(s)` for an owned copy, and `asView` to borrow a `String` as a `str`.

17.2 String: The Owned Buffer

Use `String` to build, accumulate, edit, or grow text. Its declaration matches a Vec's three-field shape:

    pub struct String {
        u8*   ptr;
        usize len;
        usize cap;
    }

Construct one empty, with reserved capacity, from a view, or from a C string:

    import(lib) std::text::string { String };

    String a = String::new();            // 17 bytes allocated, cap 16, len 0
    String b = String::withCap(1024);    // room for 1024 bytes up front (clamped to >= 7)
    String c = String::from("hello");    // copy a view, sized exactly
    String d = String::fromCstr(cstr);   // copy a C string
    String e = c.clone();                // an independent copy

`String::new` allocates a seventeen-byte buffer (capacity sixteen plus a trailing NUL) so early appends do not reallocate. `withCap` reserves at least seven bytes. `from` sizes exactly to the view's length. Every `String` keeps a NUL one past `len` for `asCstr`, but `len` is always authoritative.

`String::new` starts with `len` zero but room already reserved, so the first appends are cheap. The trailing NUL is a courtesy for C; Coral trusts `len`.

Appending has a method for each source:

    String sb = String::new();
    sb.pushView("Hello, ");        // append a str, no copy of the middle
    sb.pushStr(&name);             // append another String
    sb.pushCstr(cstr);             // append a C string
    sb.pushChar('!');              // append one raw byte
    sb.pushCodepoint('é');         // append one Unicode scalar as UTF-8
    sb.pushByte(0x0A);             // append one byte
    sb.appendView(" more");        // an alias for pushView

`pushChar` appends one raw byte; `pushCodepoint` appends a `char` as one-to-four UTF-8 bytes, substituting the replacement character for an invalid codepoint. The distinct names make the Unicode intent visible.

Repeating and editing:

    sb.pushRepeat('-', 20);            // "--------------------"
    sb.insertView(0, ">> ");           // insert at a byte offset
    sb.removeRange(0, 3);              // delete [start, end)
    sb.replaceAll("old", "new");       // replace every occurrence
    sb.truncate(10);                   // keep the first 10 bytes
    sb.clear();                        // len = 0, buffer kept
    sb.shrinkToFit();                  // release unused capacity
    sb.free();                         // free now, by hand

Search and inspect while editing:

    usize n    = sb.countChar('a');
    usize i    = sb.findView("needle");
    usize j    = sb.findChar('n');
    usize k    = sb.rfindChar('n');
    bool  pre  = sb.startsWith(">> ");
    bool  suf  = sb.endsWith("!");
    bool  has  = sb.containsView("ell");
    i32   ord  = sb.compare(&other);
    bool  same = sb.equals(&other);
    bool  eqv  = sb.equalsView("hello");

Transform in place or produce a new `String`:

    sb.toUpper();
    sb.toLower();
    sb.reverse();

    String sub   = sb.substr(0, 5);
    String pad   = sb.padLeft(20, ' ');
    String padR  = sb.padRight(20, '.');
    String rep   = sb.repeat(3);
    String trimmed = sb.trim();
    Vec<str> parts = sb.splitByte(',');

`substr` takes `(start, end)`, an exclusive end, unlike `strutil::substr`, which takes a length. `splitByte` returns views into `sb`, valid only until a reallocating mutation; consume or copy them. `toUpper`, `toLower`, and `reverse` are byte-wise and assume ASCII. `replaceAll` mutates in place and handles self-referential arguments with a defensive copy. `clear` keeps the buffer; `shrinkToFit` releases unused capacity.

Two conversions are easy to confuse: `asView` borrows, `clone` allocates an independent copy.

    str borrowed = sb.asView();        // no allocation, tied to sb's lifetime
    String owned  = sb.clone();        // allocates

Use `asView` to pass a `String` where a `str` is wanted; use `clone` when the copy must outlive the original. A `String` is freed by `free` or `@drop`; a `str` is never freed. This is Chapter11 ownership applied to text.

17.3 The strutil Free Functions

`std::text::strutil` exposes the same logic as free functions for functional style and pipelines:

    import(lib) std::text::strutil {
        split, splitVec, trim, trimLeft, trimRight,
        startsWith, endsWith, contains,
        indexOf, indexOfChar, lastIndexOf,
        replace, join, joinVec, substr, equalsIgnoreCase
    };

Signatures and short uses:

    usize split(str sv, u8 delim, str* out, usize maxParts);
    Vec<str> splitVec(str sv, u8 delim);

    str* pieces = alloc<str>(16);
    usize n = split(line, ',', pieces, 16);        // at most 16 fields
    Vec<str> all = splitVec(line, ',');            // as many as there are
    dealloc<str>(pieces);

`split` writes into a caller array and stops after `maxParts`, putting the unsplit remainder in the final element; `splitVec` allocates and returns every field.

    str trimmed  = trim(sv);              // both ends, whitespace bytes
    str left     = trimLeft(sv);
    str right    = trimRight(sv);

    bool pre     = startsWith(sv, "http");
    bool suf     = endsWith(sv, ".crl");
    bool has     = contains(sv, "needle");

    isize i      = indexOf(sv, "needle");      // -1 if absent
    isize j      = indexOfChar(sv, ',');       // -1 if absent
    isize k      = lastIndexOf(sv, ".");

    String out   = replace(sv, "old", "new");  // owned result
    String joined = join(parts, count, ", ");  // const str* array
    String jv     = joinVec(&vecOfStr, ", ");  // a Vec<str>
    str sub       = substr(sv, start, len);    // a view, no copy

    bool ci      = equalsIgnoreCase("Hello", "hELLo");

`indexOf` returns `isize` so `-1` can mean not found without colliding with a real index. `substr` takes `start` and `length` and returns a view, safe only while the source outlives it. Note the mismatch: `strutil::substr(sv, start, len)` takes a length, while `String::substr(start, end)` takes an exclusive end.

At every `substr`, check whether the second number is an end index or a length; off-by-one bugs live here.

17.4 ASCII, UTF-8, and the Layers of Text

Text has layers: a byte is a `u8`; an ASCII character is a byte with ASCII meaning; a codepoint is a Unicode scalar value stored as `char`; an encoded character is one to four UTF-8 bytes. Use the layer that matches your intent.

A byte is an envelope, a codepoint is a letter, and a UTF-8 character is the one-to-four envelopes needed to mail it. Counting envelopes and counting letters differ.

`std::text::ascii` classifies and converts bytes in O(1):

    import(lib) std::text::ascii {
        isAscii, isAsciiDigit, isAsciiAlpha, isAsciiAlnum,
        isAsciiHex, isAsciiSpace, isAsciiUpper, isAsciiLower,
        toAsciiLower, toAsciiUpper, asciiDigitVal, asciiHexVal
    };

    if (isAsciiDigit(c)) { ... }
    u8 lower = toAsciiLower('Q');          // 'q'
    u8 upper = toAsciiUpper('q');          // 'Q'
    u8 value = asciiDigitVal('7');         // 7
    u8 hexv  = asciiHexVal('f');           // 15

For text known to be ASCII, these are all you need and faster than Unicode-aware routines. The module also carries UTF-8 helpers:

    u32 bytes = utf8ByteCount(b0);                  // length of the sequence b0 starts
    u32 cp    = utf8Decode(buf, &bytesOut);         // decode one codepoint
    u32 wrote = utf8Encode(cp, out);                // encode one codepoint
    usize cc  = utf8CountChars(s);                  // codepoints in a str
    bool ok   = utf8IsValid(s);                     // well-formed UTF-8?
    u32 w16   = utf16ToUtf8(0x00E9, out);           // one UTF-16 unit -> UTF-8

`std::text::utf8` works on `(pointer, length)` buffers and returns `String` when it allocates:

    import(lib) std::text::utf8;

    u8 written = utf8::encodeCodepoint(cp, out);            // -> bytes written
    u32 code   = utf8::decodeCodepoint(s, len, &consumed);  // -> codepoint
    usize need = utf8::codepointLen(s, len);                // bytes this char needs
    usize many = utf8::countCodepoints(s, len);
    bool valid = utf8::isValid(s, len);
    String low = utf8::toLower(s, len);                     // -> String
    String up  = utf8::toUpper(s, len);                     // -> String
    Option<char> next = utf8::nextChar(s, len, &consumed);  // -> Some/None
    String one = utf8::encodeChar(c);                       // -> String

Naming the layer makes the classic byte-versus-character bug visible. Beneath both is `core::char_util`, with per-`char` operations `charIsDigit`, `charIsAlpha`, `charIsValid`, `charIsAscii`, `charToUpper`, `charToLower`, `charEncodeUtf8(char, u8*)`, and `charDecodeUtf8(const u8*, usize, usize*)`, plus byte-level classics (`isDigit`, `isAlpha`, `toUpper`, `digitValue`, `encodeUtf8`, `decodeUtf8`) that `ascii` delegates to. `ascii::utf8Decode` and `utf8ByteCount` assume well-formed bytes; `utf8::isValid` and `ascii::utf8IsValid` validate. Validate once at the boundary, then trust the fast routines.

17.5 Formatting: print, println, and the Format Language

Coral's formatting is checked at compile time. The entry points are the print family in `std::io::ios`:

    pub void print<comptime T>(T fmt, ...)
    pub void println<comptime T>(T fmt, ...)
    pub void eprint<comptime T>(T fmt, ...)
    pub void eprintln<comptime T>(T fmt, ...)
    pub void vaprint(... args)

    import(lib) std::io::ios { print, println, eprint, eprintln };

Each takes a format string and a variadic tail. The `comptime` parameter lets the compiler check format and argument types together, so mismatches are build errors. `{}` takes the next argument, `{{` and `}}` are literal braces, and placeholder and argument counts must match exactly.

`{}` dispatches on the argument's type. It handles built-in scalars, `bool`, `cchar`, `char`, both C strings, `str`, `String`, `rawptr`, manipulators, and any type implementing `@toStr`:

    println("x = {}, y = {}", x, y);
    println("name = {}, age = {}", name, age);

A type with neither a built-in printer nor `@toStr` is a compile error, so a struct cannot be printed as raw bytes. Add a `@toStr` conformance to fix it.

Explicit placeholders select a rendering: `{:d}` decimal, `{:x}` hexadecimal, `{:b}` binary, `{:p}` pointer, and `{..}` spreads an iterable with comma-and-space separators:

    println("value = {:d} hex = {:x} bin = {:b}", n, n, n);
    println("at {:p}", ptr);
    println("items: {..}", vec);

The integer formats accept only integers (`char` counts and renders its codepoint), so formatting a float with `{:x}` is a compile error. `{..}` requires a range-for-able argument and is likewise checked.

Format specifiers are few; manipulators handle the rest. They render specially and work through `{}`:

    import(lib) std::io::ios { _spaces, _repeat, _hex, _bin, _fixed };

    println("{}right-aligned", _spaces(10));      // ten spaces, then the text
    println("{}", _repeat('-', 30));              // a rule of thirty dashes
    println("{}", _hex(0xDEADBEEF));              // 0xdeadbeef
    println("{}", _bin(0b1010));                  // 0b1010
    println("{}", _fixed(3.14159, 2));            // 3.14

Signatures are `_spaces(u64 count)`, `_repeat(u8 ch, u64 count)`, `_hex(u64 value)`, `_bin(u64 value)`, and `_fixed(f64 value, u64 precision)`. The manipulator structs are module-internal; the underscore-prefixed constructors are the public API. `ios::_repeat` takes a `u8` and a count, while `fmt::repeat` takes a `str` and a count; import carefully.

A three-line program using the format language:

    import(lib) std::io::ios { println };

    void main() {
        i64 n = 255;
        println("dec {:d} hex {:x} bin {:b}", n, n, n);
    }

Printing a number in several bases is common, and knowing `{}` consumes an argument while `{{` prints a literal brace saves confusion.

For building a `String`, `std::fmt`'s `formatX` family converts one value and returns an owned `String`:

    import(lib) std::fmt::fmt {
        formatInt, formatUint, formatFloat, formatHex,
        formatHexUpper, formatBin, formatChar,
        padLeft, padRight, repeat as repeatStr, join, joinVec
    };

    String dec = formatInt(-42, 10, false);      // radix, upper-case flag
    String hx  = formatInt(255, 16, false);      // "ff"
    String HX  = formatInt(255, 16, true);       // "FF"
    String fl  = formatFloat(3.14159, 3);        // "3.142"
    String px  = formatHex(0xBEEF, true);        // "0xbeef"
    String bny = formatBin(0b1010, true);        // "0b1010"
    String ch  = formatChar('é');                // its UTF-8 bytes
    String pad = padLeft("hi", 5, ' ');          // "   hi"
    String pad2= padRight("hi", 5, '.');         // "hi..."

Signatures are `formatInt(i64 val, u64 radix, bool upper)`, `formatUint(u64 val, u64 radix, bool upper)`, `formatFloat(f64 val, u64 precision)`, `formatHex(u64 val, bool prefix)`, `formatBin(u64 val, bool prefix)`, and `formatChar(char c)`. Also `padLeft(str sv, usize width, u8 pad)`, `padRight(str sv, usize width, u8 pad)`, `repeat(str sv, usize count)`, `join(const str* parts, usize count, str sep)`, and `joinVec(const Vec<String>* parts, str sep)`. `String` has `padLeft`, `padRight`, `repeat`, and a static `join`.

One caveat: `std::fmt` also exposes `String format(str f, ...)`, and it is a stub. It deletes exact `{}` pairs and substitutes nothing, copying every other byte unchanged; `{:x}` is left literally. It does not interpolate. `format("x = {}", 3)` yields `"x = "` with no error. Interpolation lives in `print`, `println`, `eprint`, and `eprintln`; use the `formatX` family to build strings.

17.6 The Parsing Layer

Coral ships parsers for most common formats. They share a design: a type models the document, a parse function returns a `Result`, and a serialise function writes one back. Failure is a value, not an exception.

The JSON parser is the model. Its value type uses a tag rather than a recursive variant:

    pub enum JsonType {
        Null, Bool, I64, F64, String, Array, Object
    }

    pub struct JsonValue {
        JsonType type;
        bool boolVal;
        i64 i64Val;
        f64 f64Val;
        String strVal;
        Vec<JsonValue> arrVal;
        Vec<JsonPair> objVal;
    }

    pub struct JsonPair {
        String key;
        JsonValue value;
    }

Construction uses named constructors, and parsing returns a `Result`:

    import(lib) std::parser::json { parseJson, serialize, JsonValue, JsonType, JsonPair };

    Result<JsonValue, ParseError> result = parseJson(text);
    if (result.isOk()) {
        JsonValue doc = result.unwrap();
        // ... use it ...
        String back = serialize(&doc);
        println("{}", back);
    } else {
        eprintln("bad json");
    }

Read a value by switching on its `type` tag; the compiler checks exhaustiveness:

    f64 numberField(JsonValue* doc, str key) {
        switch (doc->type) {
            JsonType::Object => {
                for (JsonPair p : doc->objVal) {
                    if (p.key.asView().equals(key)) {
                        switch (p.value.type) {
                            JsonType::I64 => return (f64)p.value.i64Val,
                            JsonType::F64 => return p.value.f64Val,
                            else         => return 0.0,
                        }
                    }
                }
                return 0.0;
            },
            else => return 0.0,
        }
    }

CSV has its own streaming reader because of quoting rules. `CsvReader` reads one row at a time:

    import(lib) std::parser::csv { CsvReader };

    CsvReader reader = CsvReader::new(text);
    Vec<String> fields = Vec<String>::new();
    while (true) {
        Result<bool, ParseError> row = reader.readRow(&fields);
        if (row.isErr()) { break; }
        bool got = row.unwrap();
        if (!got) { break; }                 // end of input
        // fields[0], fields[1], ...
    }

Other formats follow the same pattern: TOML returns a `TomlDoc`, INI an `IniFile`, XML an `XmlNode` tree, and UUID provides identifiers. Regex and URI round out the lower-level tools:

    // TOML
    import(lib) std::parser::toml { parseToml, TomlDoc, TomlValue, TomlValueType };
    Result<TomlDoc, ParseError> t = parseToml(text);
    Option<TomlValue*> v = t.unwrap().get("title");
    Option<TomlValue*> nested = t.unwrap().getIn("server", "port");

    // INI
    import(lib) std::parser::ini { IniFile, IniSection };
    IniFile ini = IniFile::new();
    ini.parse(text);
    Option<IniSection*> section = ini.section("database");
    Option<String> host = ini.get("database", "host");

    // XML
    import(lib) std::parser::xml { parseXml, serializeXml, XmlNode, XmlAttribute, XmlNodeType };
    Result<XmlNode, ParseError> x = parseXml(text);
    XmlNode node = XmlNode::element("greeting");
    if (node.hasAttr("lang")) { Option<str> lang = node.getAttr("lang"); }
    Option<XmlNode*> child = node.firstChild("name");

    // UUID
    import(lib) std::parser::uuid { Uuid, uuidV4, parseUuid };
    String fresh = uuidV4();                 // a new random v4 id as text
    Result<Uuid, ParseError> id = parseUuid("...");

Each parser models a typed document and returns a `Result`, so exhaustiveness checking and the failure path apply as in Chapters13 and 15.

17.7 Regular Expressions and URIs

Two more text tools come up constantly.

`std::text::regex` wraps a regular-expression engine with a small API. Compile a `Regex` once and reuse it:

    import(lib) std::text::regex { Regex, regexFlags };

    Regex re;
    if (!re.compile("([0-9]+)-([0-9]+)", false)) {       // false = case-sensitive
        eprintln("bad pattern");
    }

    if (re.matches("12-34")) { ... }                    // true only if the WHOLE input matches

    Vec<str> groups = Vec<str>::new();
    if (re.find("range 12-34 here", &groups)) {
        // groups[0] is the whole match, groups[1] the first capture, ...
        // here groups[0] == "12-34", groups[1] == "12", groups[2] == "34"
        println("first = {}, second = {}", groups.at(1), groups.at(2));
    }
    re.free();

`compile` takes a pattern and a `caseInsensitive` flag and reports validity. `matches` is anchored and whole-string, so it validates strict patterns; use `find` for substring search. `find` fills a `Vec<str>` with the whole match in slot zero and each capture after it; a non-participating group is the empty string, so the vector length matches the group count. The captured `str`s are views into the `Regex`'s scratch buffer and stay valid only until the next `find` or `free`, so copy anything you keep. `free` also releases the scratch buffer.

`std::text::uri` parses a URL into its parts, saving the manual split-on-scheme, authority, and query dance:

    import(lib) std::text::uri { Uri };

    Uri u = Uri::new();
    if (u.parse("https://user@example.com:8443/a/b?x=1#frag")) {
        println("scheme   = {}", u.scheme.asView());
        println("userinfo = {}", u.userInfo.asView());
        println("host     = {}", u.host.asView());
        println("port     = {}", u.port);
        println("path     = {}", u.path.asView());
        println("query    = {}", u.query.asView());
        println("fragment = {}", u.fragment.asView());
    }

`parse` reports whether the input looked like a URI; its fields are `String`s readable through `asView`. A `Uri` frees its fields when it drops.

17.8 A Worked Example: A CSV Reader

A CSV reader must split lines into fields, handle quoted fields containing commas, and convert numbers. The library's `CsvReader` handles the hard part:

    import(lib) std::parser::csv { CsvReader, ParseError };
    import(lib) std::text::string { String };
    import(lib) std::text::strutil { trim };
    import(lib) std::io::ios { parseF64, eprintln };
    import(lib) std::vec { Vec };

    f64 csvNumber(str field) {
        bool ok = false;
        f64 v = parseF64(field, &ok);            // out-param reports success
        if (!ok) {
            eprintln("not a number: {}", field);
            return 0.0;
        }
        return v;
    }

    void readRows(str text) {
        CsvReader reader = CsvReader::new(text);
        Vec<String> fields = Vec<String>::new();

        while (true) {
            Result<bool, ParseError> row = reader.readRow(&fields);
            if (row.isErr()) {
                eprintln("malformed csv");
                break;
            }
            if (!row.unwrap()) break;            // no more rows

            // The first field is a name; the second is a measurement.
            str name = trim(fields.at(0).asView());
            f64 value = csvNumber(fields.at(1).asView());
            println("{} = {}", name, value);
        }

        // `fields` owns the current row's Strings; free them before we leave.
        for (usize i = 0; i < fields.count(); i += 1) {
            fields.atPtr(i)->free();
        }
        fields.dispose();
    }

The reader handles quoting, including embedded commas and doubled quotes inside a quoted field. `parseF64` converts a `str` and reports success through an out-parameter, a lightweight alternative to `Result` for yes-or-no. This is the usual text-processing shape: scan for structure, slice views, trim, convert, and allocate a `String` only when the text must be owned.

Two ownership details make the example correct. `CsvReader::new(text)` stores the text's pointer and length without copying, so the input `str` must outlive the reader. `readRow` frees the previous row's `String`s and reuses the same `Vec`, so `fields` describes only the current row; the explicit cleanup before returning releases the last row. `Result` handles malformed input, while `Ok(false)` means clean end of stream.

17.9 A Worked Example: Human-Readable Sizes

Formatting is part of the text layer. A small size formatter shows the `formatX` family and `String` assembly together:

    import(lib) std::fmt::fmt { formatFloat, padLeft };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    str byteUnit(f64 bytes) {
        if (bytes < 1024.0)               return "B";
        if (bytes < 1024.0 * 1024.0)      return "KiB";
        if (bytes < 1024.0 * 1024.0 * 1024.0) return "MiB";
        return "GiB";
    }

    f64 scaleFor(str unit, f64 bytes) {
        if (unit == "B")   return bytes;
        if (unit == "KiB") return bytes / 1024.0;
        if (unit == "MiB") return bytes / (1024.0 * 1024.0);
        return bytes / (1024.0 * 1024.0 * 1024.0);
    }

    String humanSize(f64 bytes) {
        str unit = byteUnit(bytes);
        String number = formatFloat(scaleFor(unit, bytes), 1);   // one decimal
        String padded = padLeft(number.asView(), 7, ' ');
        number.free();

        String out = String::new();
        out.pushStr(&padded);
        padded.free();
        out.pushChar(' ');
        out.pushView(unit);
        return out;                       // caller owns the result
    }

    println("cache: {}", humanSize(1536.0));     // cache:     1.5 KiB

`formatFloat` renders one decimal place, `padLeft` aligns to seven characters, and `pushView`/`pushChar` assemble the result. Convert with the right format function, assemble with append methods, and print only at the end. It is more verbose than `println`, and correct when the string must outlive the call.

17.10 Exercises

1. Comprehension. What is the difference between `str` and `String`? Give a function signature for which each is the correct parameter type, and explain what would go wrong if you used the other.
