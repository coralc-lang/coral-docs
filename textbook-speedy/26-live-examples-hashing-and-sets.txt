Chapter26

Live Examples: Hashing and Sets

Trading Order for Speed

Hashing turns a nested loop into a single lookup, replacing seconds with microseconds. This chapter shows that from six angles.

A hash map is a theatre coat check: you give a key, it computes a slot number, and it stores the value there. Lookup recomputes the number and goes straight to the slot, with no searching. The catch is that the container needs a hash function to make the ticket and an equality function to tell keys apart; Chapter16 showed the signatures.

Two keys can compute the same slot. That is a collision, and Coral's `HashMap` resolves it by walking forward to the next free slot (open addressing with linear probing). Colliding keys sit near each other, so a lookup checks a short chain. Below half full, that chain is almost always length one, giving constant average lookup. In the pathological worst case everything collides and lookup degrades to a linear scan. "Average" is doing real work.

A set is a map without values. It answers "is this present?" and enforces at most one copy of each element, like a doorman checking a guest list.

`Map` is the other associative container: an ordered tree with O(log n) lookups but deterministic, sorted iteration (Chapter16, 16.3). Use `Map` when keys must stay sorted, `HashMap` when you only look up. A recurring trick is to store a *complement* or a *prefix* rather than the answer: ask "have I seen the value that would complete this pair?" That inversion appears three times below.

Every hashed container needs a hash and an equality function. For integer keys they are almost trivial:

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    usize hashU8(u8 k) { return (usize)k; }
    bool eqU8(u8 a, u8 b) { return a == b; }

    usize hashStr(str k) {
        usize h = 5381;
        for (usize i = 0; i < k.len; i++) {
            h = h * 33 + (usize)k.ptr[i];
        }
        return h;
    }
    bool eqStr(str a, str b) { return a.equals(b); }

`hashStr` is djb2, chosen for speed rather than cryptography, which is all a hash table needs. Equality matters exactly on collision: after hashing to the same slot, the table compares the stored key with yours to tell a true match from a coincidence.

26.1 Two Sum (Unsorted)

The problem

Given an unsorted array and a target, return the positions of the two numbers that sum to the target.

Walk the line once with a notebook mapping each number seen to its position. For each person, ask whether the needed complement is already in the notebook. Never look ahead, never double back.

Try every pair, scanning every later `j` for each `i`: n² / 2 comparisons. It is the baseline hashing must beat by an order of magnitude.

Brute force

One pass with a hash map from value to last-seen position. For each number, compute `target - number` and ask whether the complement has been seen; if so, return the stored position and the current one. Otherwise record the current number. This is the complement trick: store what you have and immediately check whether the past contains its partner.

The better approach

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    Vec<i32> twoSum(const Vec<i32>* v, i32 target) {
        HashMap<i32, i32> seen = HashMap<i32, i32>::new(hashI32, eqI32);
        Vec<i32> out = Vec<i32>::new();
        for (usize i = 0; i < v->count(); i++) {
            i32 x = v->at(i);
            i64 need = (i64)target - (i64)x;
            if (need >= -2147483648 && need <= 2147483647) {
                Option<i32> found = seen.get((i32)need);
                if (found.isSome()) {
                    out.push(found.unwrap());
                    out.push((i32)i);
                    return out;
                }
            }
            seen.insert(x, (i32)i);
        }
        return out;
    }

Two corners are deliberate. The complement is computed in `i64` and range-checked before casting back, because `target - x` can overflow 32-bit subtraction and a wrapped complement could produce a wrong match. And the current number is inserted *after* the lookup, so it never pairs with itself; that ordering distinguishes distinct indices from returning `[i, i]` for `[3]` with target 6.

The cost

Average time is linear: one pass with O(1) average lookups and insertions. Space is linear, since the map may hold every element. The brute force is quadratic; trading memory for time is the signature hash trade.

Edge cases and a variation

Fewer than two elements returns an empty vector. Insert-after-lookup prevents reusing a value. Variation: return all unique pairs by not returning early and skipping consumed complements. The same skeleton solves three-sum after sorting and fixing one element with an outer loop.

26.2 Contains Duplicate

The problem

Given an array, decide whether any value appears at least twice.

Picture this

A doorman checks each arriving name against the guest list. If it is already there, a duplicate has arrived. New guests are compared only with the list.

Brute force

Compare every pair and stop on equality. Quadratic, and it rehashes the same information on every pair.

The better approach

A set. Walk once: if the set contains the value, return true; otherwise insert it. Each value is tested and inserted in constant average time.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::set { Set };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    bool containsDuplicate(const Vec<i32>* v) {
        Set<i32> seen = Set<i32>::new(hashI32, eqI32);
        for (usize i = 0; i < v->count(); i++) {
            i32 x = v->at(i);
            if (seen.contains(x)) {
                return true;
            }
            seen.insert(x);
        }
        return false;
    }

This is the simplest hashing shape, and the membership problems that follow build on it. Insert-if-absent and contains are the set's entire vocabulary here.

The cost

Average time is linear: one membership test and possibly one insertion per element. Space is linear in the worst case. For tight memory and a small value range, a `Bitset` (Chapter16) uses one bit per value with constant-time tests, smaller and faster. "Use a set" is a default, not a law.

Edge cases and a variation

An empty or single-element array returns false. Variation: return the first duplicated value; the moment `contains` is true, the current value is the first repeat. A harder version, a duplicate among `n + 1` values drawn from `1..n` in constant space without modifying the array, abandons hashing for the cycle detection of Chapter27.

26.3 Intersection of Two Arrays

The problem

Given two arrays, return the set of values appearing in both, each once.

Picture this

Read the smaller guest list into memory, walk the larger, and collect names on both. Remember which hits you have already reported so each appears once.

Brute force

For each element of the first array, scan the entire second. Quadratic, with another nested check for deduplication.

The better approach

Load the second array into a "present in B" set. Walk the first; for each value in B and not yet emitted, add it to both the result and an `emitted` set. The second set enforces "each value once."

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::set { Set };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    Vec<i32> intersection(const Vec<i32>* a, const Vec<i32>* b) {
        Set<i32> inB = Set<i32>::new(hashI32, eqI32);
        for (usize i = 0; i < b->count(); i++) {
            inB.insert(b->at(i));
        }

        Set<i32> emitted = Set<i32>::new(hashI32, eqI32);
        Vec<i32> out = Vec<i32>::new();
        for (usize i = 0; i < a->count(); i++) {
            i32 x = a->at(i);
            if (inB.contains(x) && !emitted.contains(x)) {
                emitted.insert(x);
                out.push(x);
            }
        }
        return out;
    }

The `emitted` set is the deduplication guard most first attempts forget; without it, a value appearing three times in `a` is pushed three times. Sorting at the end is an alternative, but the set version keeps first-appearance order from `a`.

The cost

Average time is linear in the combined lengths. Space is linear: two sets, each at most the size of its source. `Set` has this built in as `intersection` (Chapter16, 16.5); prefer it after seeing the machinery.

Edge cases and a variation

Either array empty gives an empty result. For multiplicity, where three copies in `a` and two in `b` mean two in the result, a set cannot represent it; use a `HashMap<i32, i32>` of counts and take the minimum per key. The library's `union`, `difference`, and `isSubset` cover set-theoretic operations.

26.4 Happy Number

The problem

Repeatedly replace a number by the sum of the squares of its digits. If you reach 1 it is "happy"; if you loop forever it is not. Decide which.

Picture this

Follow stepping stones, leaving a chalk mark on each. Reaching a marked stone means a loop, so stop; reaching 1 means happy.

Brute force

The process is infinite, so a naive program loops forever on unhappy numbers. Running it and giving up after some steps is a guess, not a proof.

The better approach

Detect the cycle with a set of seen values. Each step, compute the digit-square sum; if it is 1, the number is happy; if it is already in the set, a loop has closed and the number is unhappy. Otherwise record it. The values are bounded, so only finitely many distinct values can appear before a repeat.

The implementation

    import(lib) std::collections::set { Set };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    i32 digitSquareSum(i32 n) {
        i32 sum = 0;
        while (n > 0) {
            i32 d = n % 10;
            sum = sum + d * d;
            n = n / 10;
        }
        return sum;
    }

    bool isHappy(i32 n) {
        Set<i32> seen = Set<i32>::new(hashI32, eqI32);
        while (n != 1 && !seen.contains(n)) {
            seen.insert(n);
            n = digitSquareSum(n);
        }
        return n == 1;
    }

The loop condition carries the algorithm: continue while `n` is neither 1 nor seen. On exit, `n` is 1 (happy) or a repeat (unhappy). `digitSquareSum` is plain reusable arithmetic.

The cost

Time is bounded by the distinct values reachable before a repeat, a small constant well under a hundred for any 32-bit input, so in practice constant. Space is a small constant. The input is bounded, making this a finite-state machine, with the set finding its cycle.

Edge cases and a variation

Starting at 1 returns true immediately. Starting at 0 maps to itself; the set catches the repeat and returns false, correctly. Variation: Floyd's tortoise-and-hare uses constant space. A slow pointer applies the function once, a fast pointer twice; meeting anywhere other than 1 means a cycle. Same idea, two walkers instead of chalk marks.

26.5 Subarray Sum Equals K

The problem

Given an array of integers, possibly negative, and a target `k`, count the contiguous subarrays summing to `k`.

Picture this

Keep a running total. At each step ask how many earlier running totals equaled `current - k`; each such moment marks a subarray summing to `k`. This is the complement trick applied to prefixes.

Brute force

For every start, extend a running sum right and count hits. n² additions, recomputing totals it could have carried forward.

The better approach

One pass with a hash map counting prefix sums. Seed `0 -> 1` for the empty prefix, or you miss every subarray starting at index zero. At each position, the number of subarrays ending here is the count of past prefixes equal to `prefix - k`; add it, then record the current prefix.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    i32 subarraySum(const Vec<i32>* v, i32 k) {
        HashMap<i32, i32> prefixCount = HashMap<i32, i32>::new(hashI32, eqI32);
        prefixCount.insert(0, 1);
        i32 prefix = 0;
        i32 total = 0;
        for (usize i = 0; i < v->count(); i++) {
            prefix = prefix + v->at(i);
            Option<i32> prior = prefixCount.get(prefix - k);
            if (prior.isSome()) {
                total = total + prior.unwrap();
            }
            Option<i32> here = prefixCount.get(prefix);
            if (here.isSome()) {
                prefixCount.insert(prefix, here.unwrap() + 1);
            } else {
                prefixCount.insert(prefix, 1);
            }
        }
        return total;
    }

Order matters: count completions against past prefixes first, then add the current prefix. Add first, and a zero-length subarray counts itself. This is the insert-after-lookup discipline of 25.1.

The cost

Average time is linear: one pass, two map operations per element. Space is linear, at most one entry per distinct prefix sum. The prefix-sum idea from Chapter24 grows up: there it answered one range query; here a map of all prefixes counts every range in one pass.

Edge cases and a variation

An empty array returns zero. Negative numbers work naturally because the map does not assume sums increase; a sliding window would silently fail, since its sum is non-monotonic. Overflow is the real risk: if sums can exceed 32 bits, promote `prefix` and the map key to `i64` and add `hashI64`. Variation: count subarrays divisible by `k`, keying on prefix sum modulo `k`.

26.6 Longest Substring Without Repeating Characters

The problem

Given a string, find the length of the longest substring with no repeated character.

Picture this

A window slides right. When the new character already appears inside the current window, move the left edge to just after that appearance. The answer is the largest width reached. The engine is a map from character to last position.

Brute force

For every start, extend right while collecting characters in a set, stopping at a repeat. Quadratic, because each start rescans the same runs.

The better approach

One pass with a map from character to last-seen index and a `start` for the left edge. For character `i`, if it was last seen at or after `start`, move `start` past that occurrence. Update the last-seen position and record `i - start + 1`. `start` only moves forward, so each character is processed once.

The implementation

    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::io::ios { println };

    usize hashU8(u8 k) { return (usize)k; }
    bool eqU8(u8 a, u8 b) { return a == b; }

    usize lengthOfLongestSubstring(str s) {
        HashMap<u8, usize> lastSeen = HashMap<u8, usize>::new(hashU8, eqU8);
        usize best = 0;
        usize start = 0;
        for (usize i = 0; i < s.len; i++) {
            u8 c = s.at(i);
            Option<usize> prev = lastSeen.get(c);
            if (prev.isSome() && prev.unwrap() >= start) {
                start = prev.unwrap() + 1;
            }
            lastSeen.insert(c, i);
            usize len = i - start + 1;
            if (len > best) {
                best = len;
            }
        }
        return best;
    }

The guard `prev.unwrap() >= start` is the subtlety. Without it, a character seen long ago and already outside the window would yank `start` backward and shrink the window for no reason. Only positions inside the current window may move the left edge.

The cost

Time is linear: both `start` and `i` only advance, for at most n forward movements. Space is at most the alphabet: 256 entries for byte input, effectively constant. Hashing here is dramatically faster on inputs with long repeated runs.

Edge cases and a variation

The empty string returns zero; all-identical characters return one. This counts bytes, so a multi-byte character could be split; for non-ASCII text iterate codepoints with `nextCodepoint` (Chapter17) and key on `char` with a `hashChar`. Variation: "at most k distinct characters" keeps a distinct count in the map and moves the left edge when it exceeds `k`.

26.7 First Unique Character in a String

The problem

Given a string, return the index of the first character appearing exactly once, or -1 if every character repeats.

Picture this

Count every character first, then read the line again and report the first with count one. Two passes, because "appears exactly once" is only known after seeing the whole string.

Brute force

For each character, scan the entire string for another occurrence. Quadratic, rescanning for every position.

The better approach

One pass builds a frequency map; a second pass finds the first character with frequency one. The second pass follows original order, so the map must be keyed by character.

The implementation

    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::io::ios { println };

    usize hashU8(u8 k) { return (usize)k; }
    bool eqU8(u8 a, u8 b) { return a == b; }

    i32 firstUniqChar(str s) {
        HashMap<u8, i32> count = HashMap<u8, i32>::new(hashU8, eqU8);
        for (usize i = 0; i < s.len; i++) {
            u8 c = s.at(i);
            Option<i32> seen = count.get(c);
            if (seen.isSome()) {
                count.insert(c, seen.unwrap() + 1);
            } else {
                count.insert(c, 1);
            }
        }
        for (usize i = 0; i < s.len; i++) {
            if (count.get(s.at(i)).unwrap() == 1) {
                return (i32)i;
            }
        }
        return -1;
    }

The second-pass lookup is guaranteed to succeed because every character was inserted in the first pass. That is the standard justification for `unwrap` from Chapter15: the code above makes absence impossible.

The cost

Time is linear: two passes with constant-time hash operations. Space is at most the alphabet, 256 entries for bytes, constant regardless of length. For fixed-alphabet input, a 256-counter array would be faster still; the map wins when the alphabet is sparse or large, the same trade as `Bitset` versus `Set`.

Edge cases and a variation

An empty string returns -1; a unique first character returns 0 in the second pass. Variation: return the most frequent character, breaking ties by first occurrence. Another: the first unique character *alphabetically*, which scans the key set in sorted order, exactly why `Map` exists.

26.8 Group Anagrams

The problem

Given a list of words, group together words that are anagrams of each other.

Picture this

Give every word a canonical signature: sort its letters. Anagrams have identical sorted forms. Group by that signature, which discards order while preserving the multiset of letters.

Brute force

Compare every pair, checking whether their letter multisets match, by sorting or counting. Quadratic in the number of words, with an anagram check inside each pair. The better approach never compares words with each other.

The better approach

A hash map from sorted-letter signature to the list of word indices sharing it. For each word, build the signature (copy the bytes, sort, reassemble) and append its index. The map's values are the groups.

The key is a string *built fresh* for each word. A `str` is a borrowed view, so a map keyed by `str` stores the address of the bytes, not the bytes. If those bytes live in a temporary that is freed, the key dangles. Own every signature in a list that outlives the map and hand the map views into it.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::collections::sort { sortBy };
    import(lib) std::io::ios { println };

    usize hashStr(str k) {
        usize h = 5381;
        for (usize i = 0; i < k.len; i++) {
            h = h * 33 + (usize)k.ptr[i];
        }
        return h;
    }
    bool eqStr(str a, str b) { return a.equals(b); }
    bool lessU8(u8 a, u8 b) { return a < b; }

    String canonicalKey(str w) {
        Vec<u8> chars = Vec<u8>::new();
        for (usize i = 0; i < w.len; i++) {
            chars.push(w.at(i));
        }
        sortBy(&chars, lessU8);
        String out = String::withCap(w.len);
        for (usize i = 0; i < chars.count(); i++) {
            out.pushChar(chars.at(i));
        }
        return out;
    }

    Vec<Vec<i32>> groupAnagrams(const Vec<str>* words) {
        Vec<String> keyStore = Vec<String>::new();
        HashMap<str, Vec<i32>> groups = HashMap<str, Vec<i32>>::new(hashStr, eqStr);

        for (usize i = 0; i < words->count(); i++) {
            String key = canonicalKey(words->at(i));
            keyStore.push(key);
            str kv = keyStore.back().asView();

            Option<Vec<i32>*> group = groups.getPtr(kv);
            if (group.isSome()) {
                group.unwrap()->push((i32)i);
            } else {
                Vec<i32> list = Vec<i32>::new();
                list.push((i32)i);
                groups.insert(kv, list);
            }
        }

        Vec<Vec<i32>> out = Vec<Vec<i32>>::new();
        Vec<str> keys = groups.keys();
        for (usize i = 0; i < keys.count(); i++) {
            Option<Vec<i32>> group = groups.get(keys.at(i));
            if (group.isSome()) {
                out.push(group.unwrap());
            }
        }
        return out;
    }

Two ownership details carry this code. `keyStore` owns every signature `String`; the map's `str` keys view its heap buffers, and because `keyStore` is never cleared or freed until return, they stay valid. Even when `keyStore` grows and its array of `String` structs is reallocated, the bytes each `String` points to do not move. Second, values are mutated through `getPtr`, so appending an index edits the list in place rather than a copy that must be written back.

The cost

With n words of average length L, signatures cost O(L log L) to sort, so the total is O(n · L log L). Sorting dominates, not hashing; map operations are O(1) average for O(n) of them. Space is linear in total input. For small bounded L this is effectively linear in n.

Edge cases and a variation

Empty input yields an empty result. Empty strings share the empty signature and group together, correctly. An alternative signature counts letters into a fixed 26-byte array, turning O(L log L) sorting into O(L) counting at the cost of a fixed-length key and an alphabet assumption. That is the same counting-versus-sorting trade as Chapter24 and Chapter25's `sortColors`.

26.9 Isomorphic Strings

The problem

Two strings are *isomorphic* if you can consistently rename characters of the first to get the second. `"egg"` and `"add"` are; `"badc"` and `"baba"` are not.

Picture this

Renaming is a one-to-one translation table: no source maps to two targets, and no target is claimed by two sources. Keep two maps, one per direction, and check both at every position.

Brute force

For each position, scan the rest for the same source letter and verify the target matches. Quadratic, and one-directional checking quietly accepts `"badc"` versus `"baba"`.

The better approach

One pass with `source -> target` and `target -> source`. If the source is mapped, its target must match; if the target is mapped, its source must match; otherwise record both. Lengths must match up front. This doubles the lookup discipline of 25.1 to enforce a bijection.

The implementation

    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::io::ios { println };

    usize hashU8(u8 k) { return (usize)k; }
    bool eqU8(u8 a, u8 b) { return a == b; }

    bool isIsomorphic(str a, str b) {
        if (a.len != b.len) return false;
        HashMap<u8, u8> toB = HashMap<u8, u8>::new(hashU8, eqU8);
        HashMap<u8, u8> toA = HashMap<u8, u8>::new(hashU8, eqU8);
        for (usize i = 0; i < a.len; i++) {
            u8 x = a.at(i);
            u8 y = b.at(i);
            Option<u8> mx = toB.get(x);
            if (mx.isSome()) {
                if (mx.unwrap() != y) return false;
            } else {
                toB.insert(x, y);
            }
            Option<u8> my = toA.get(y);
            if (my.isSome()) {
                if (my.unwrap() != x) return false;
            } else {
                toA.insert(y, x);
            }
        }
        return true;
    }

The second map is what first attempts omit, and it makes the relation a bijection rather than a function. With only `toB`, `"badc"` and `"baba"` would pass `b -> b` and `a -> a`, then record `d -> b` even though `b` already owns target `b`. The return map catches that.

The cost

Average time is linear: one pass with a constant number of hash operations per character. Space is at most the alphabet, one entry per distinct character in each direction, effectively constant for bytes. This is the smallest example needing two hashed structures: a function is not enough when injectivity is also required.

Edge cases and a variation

Different lengths return false before any map is touched. The empty string is isomorphic to itself, and a string compared with itself always is, a decent sanity test. This compares bytes, so the Unicode caveat from 25.6 applies. Variation: *word* isomorphism maps whole tokens, needing `u8 -> str` and `str -> u8`.

26.10 Word Pattern

The problem

Given a pattern such as `"abba"` and a space-separated sentence, decide whether the words follow the pattern. `"dog cat cat dog"` does; `"dog cat cat fish"` does not.

Picture this

This is 25.9 at word granularity: pattern letters are the source alphabet, words the target, and the mapping must be one-to-one. The only new mechanics are splitting the sentence and checking that word count equals pattern length.

Brute force

For each pattern position, scan every other position and check that equal letters have equal words and vice versa. Quadratic, re-deriving the bijection on every pair.

The better approach

Split the sentence, check the lengths, then run the two-map bijection check of 25.9, keyed on the pattern byte one way and the word `str` the other. Word views live for the whole call, so storing them as map values is safe.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::text::strutil { splitVec };
    import(lib) std::io::ios { println };

    usize hashU8(u8 k) { return (usize)k; }
    bool eqU8(u8 a, u8 b) { return a == b; }
    usize hashStr(str k) {
        usize h = 5381;
        for (usize i = 0; i < k.len; i++) {
            h = h * 33 + (usize)k.ptr[i];
        }
        return h;
    }
    bool eqStr(str a, str b) { return a.equals(b); }

    bool wordPattern(str pattern, str sentence) {
        Vec<str> words = splitVec(sentence, ' ');
        if (words.count() != pattern.len) return false;

        HashMap<u8, str> patToWord = HashMap<u8, str>::new(hashU8, eqU8);
        HashMap<str, u8> wordToPat = HashMap<str, u8>::new(hashStr, eqStr);

        for (usize i = 0; i < pattern.len; i++) {
            u8 p = pattern.at(i);
            str w = words.at(i);
            Option<str> mw = patToWord.get(p);
            if (mw.isSome()) {
                if (!mw.unwrap().equals(w)) return false;
            } else {
                patToWord.insert(p, w);
            }
            Option<u8> mp = wordToPat.get(w);
            if (mp.isSome()) {
                if (mp.unwrap() != p) return false;
            } else {
                wordToPat.insert(w, p);
            }
        }
        return true;
    }

`splitVec` returns `str` views into `sentence`, so words are borrowed, not copied; each map holds one view or one byte per token. The `equals` calls are the maps' equality functions in public clothes.

The cost

Time is linear in the combined pattern and sentence length: splitting and the two hash operations per token are constant average work per byte. Space is linear in the number of words, which is unavoidable. The `str`-keyed map borrows the sentence, so no word bytes are duplicated.

Edge cases and a variation

A word-count mismatch returns false before any map is built. An empty sentence with a non-empty pattern fails the count; both empty returns true. Trailing or repeated spaces depend on `splitVec` semantics, so check whether `"a  b"` means the same as `"a b"`. Variation: match a prefix, or return the first violating index by moving the return into the loop.

26.11 Longest Consecutive Sequence

The problem

Given an unsorted array, find the length of the longest run of consecutive integers in O(n) average time. For `[100, 4, 200, 1, 3, 2]` the run `1, 2, 3, 4` gives four.

Picture this

Pour the numbers into a set, then find each run's *start*: a value whose predecessor is absent. Count upward while the next value is present. Each number is visited at most twice, once as a potential start and once in exactly one run.

Brute force

Sort and scan for the longest streak, handling duplicates. O(n log n), correct, and the honest fallback when hashing is unavailable; it costs a full sort to answer an adjacency question.

The better approach

Insert every value into a set. If `value - 1` is present, this value is mid-run and another value will start it, so skip. Otherwise walk upward with `contains` until the chain breaks and record the length. Each value is probed a constant number of times.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::set { Set };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    usize longestConsecutive(const Vec<i32>* v) {
        Set<i32> present = Set<i32>::new(hashI32, eqI32);
        for (usize i = 0; i < v->count(); i++) {
            present.insert(v->at(i));
        }

        usize best = 0;
        for (usize i = 0; i < v->count(); i++) {
            i32 x = v->at(i);
            if (present.contains(x - 1)) continue;
            i32 cur = x;
            usize len = 1;
            while (present.contains(cur + 1)) {
                cur++;
                len++;
            }
            if (len > best) best = len;
        }
        return best;
    }

The set removes duplicates as it loads. The `contains(x - 1)` guard stops the algorithm from re-walking a run from every member; without it the inner loop could total quadratic work.

The cost

Average time is linear: building the set is O(n), and every value starts at most one walk and is extended by at most one, so total inner-loop work is O(n). Space is linear. A set turns an ordering question (O(n log n) by sorting) into an adjacency question (O(n) by hashing).

Edge cases and a variation

An empty array returns zero; one element returns one. Duplicates are absorbed by the set. `x - 1` at the smallest `i32` wraps to a huge positive, which happens to do the right thing, but do not rely on wrap-around; promote to `i64` for extreme input. Variation: return the run itself by threading a start index. A second: longest arithmetic run with difference `d`, replacing `+1`/`-1` with `+d`/`-d`.

26.12 Top K Frequent Elements

The problem

Given an array and an integer `k`, return the `k` most frequent values, in any order.

Picture this

Count occurrences, then bucket values by frequency from 0 to `n`, and read buckets from the highest down until `k` values are collected. Bucket sort needs no comparisons because the bucket index is the sorted order.

Brute force

Sort the distinct values by decreasing count: O(d log d) for d distinct values. Fine but unnecessary, and the version almost everyone writes first.

The better approach

A frequency map, then buckets indexed by frequency. There are `n + 1` buckets because no value can occur more than `n` times. Placing each distinct value costs one lookup and one push; reading the top buckets costs at most `n` steps. O(n) average, with no comparator at all, which sidesteps the fact that a comparator cannot see the frequency map.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::collections::hashmap { HashMap };
    import(lib) std::io::ios { println };

    usize hashI32(i32 k) { return (usize)k; }
    bool eqI32(i32 a, i32 b) { return a == b; }

    Vec<i32> topKFrequent(const Vec<i32>* v, i32 k) {
        HashMap<i32, i32> count = HashMap<i32, i32>::new(hashI32, eqI32);
        for (usize i = 0; i < v->count(); i++) {
            i32 x = v->at(i);
            Option<i32> c = count.get(x);
            if (c.isSome()) {
                count.insert(x, c.unwrap() + 1);
            } else {
                count.insert(x, 1);
            }
        }

        usize n = v->count();
        Vec<Vec<i32>> buckets = Vec<Vec<i32>>::new();
        for (usize i = 0; i <= n; i++) {
            buckets.push(Vec<i32>::new());
        }

        Vec<i32> keys = count.keys();
        for (usize i = 0; i < keys.count(); i++) {
            i32 key = keys.at(i);
            i32 freq = count.get(key).unwrap();
            buckets.atPtr((usize)freq)->push(key);
        }

        Vec<i32> out = Vec<i32>::new();
        isize f = (isize)n;
        while (f >= 0 && out.count() < (usize)k) {
            Vec<i32>* bucket = buckets.atPtr((usize)f);
            for (usize i = 0; i < bucket->count(); i++) {
                out.push(bucket->at(i));
                if (out.count() >= (usize)k) break;
            }
            f--;
        }
        return out;
    }

`buckets.atPtr(freq)` returns a pointer to the inner vector, so `push` edits it in place, the same reasoning 25.8 used for map values. `count.get(key).unwrap()` is safe because every key came from the map, the "code above makes absence impossible" justification from 25.7.

The cost

Average time is O(n): one pass to count, one over distinct keys to fill buckets, one down the buckets. Space is O(n) for the map plus buckets. Bucketing beats the O(d log d) sort and, unlike a `PriorityQueue`, needs no comparator that can see the counts.

Edge cases and a variation

`k` at or above the number of distinct values returns all of them; the loop stops when output is full. Ties break arbitrarily by insertion order within a bucket, which the problem permits. An empty array returns empty. Variation: return the top `k` sorted by sorting the small output; or use a `PriorityQueue` for a streaming O(n log k) version when the array does not fit in memory.

26.13 Valid Sudoku

The problem

Given a 9-by-9 Sudoku board with digits `1` to `9` and `.` for empty cells, decide whether any digit repeats in a row, column, or 3-by-3 box. The board need not be solvable, only free of immediate conflicts.

Picture this

Keep twenty-seven ledgers: nine rows, nine columns, nine boxes. Check each cell against all three, then mark it in all three. The box is `(row / 3) * 3 + (col / 3)`.

Brute force

For each cell, scan its row, column, and box for a duplicate. That is O(81 · 27) work, constant because the board is fixed, but redundant and it hides the box formula.

The better approach

Use bitsets, one machine word per ledger. Bit `d` means digit `d` was seen. Checking is an AND against three masks; marking is an OR. Twenty-seven `i32` masks index rows, columns, then boxes, with no allocation per group.

The implementation

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    bool isValidSudoku(const Vec<u8>* board) {
        Vec<i32> mask = Vec<i32>::withCap(27);
        for (usize i = 0; i < 27; i++) mask.push(0);

        for (usize r = 0; r < 9; r++) {
            for (usize c = 0; c < 9; c++) {
                u8 v = board->at(r * 9 + c);
                if (v == '.') continue;
                i32 bit = 1 << ((i32)v - 48);
                usize box = (r / 3) * 3 + (c / 3);

                if ((mask.at(r) & bit) != 0) return false;
                if ((mask.at(9 + c) & bit) != 0) return false;
                if ((mask.at(18 + box) & bit) != 0) return false;

                mask.set(r, mask.at(r) | bit);
                mask.set(9 + c, mask.at(9 + c) | bit);
                mask.set(18 + box, mask.at(18 + box) | bit);
            }
        }
        return true;
    }

The constant `48` is the byte `'0'`, so `(i32)v - 48` gives the digit value. Bit `d` is `1 << d`, and `d` ranges from 1 to 9, safely inside 32 bits. The 27-slot vector partitions into rows at `0..8`, columns at `9..17`, and boxes at `18..26`, so one `mask.at` call serves all three checks.

The cost

Time and space are constant: 81 cells visited once and 27 ledger integers. There is no `n`; the board size is part of the problem. The bitmask keeps the constant small, the same trick as Chapter16's `Bitset`, scaled to one word per group.

Edge cases and a violation

An all-dots board is valid. A row duplicate fails on its second occurrence, and the box check catches duplicates no row or column sees, the case people forget to test. The input is assumed to be exactly 81 bytes in row-major order; a malformed length would be read past, so validate at the boundary. Variation: use a `Set<u8>` per group, clearer but slower and allocating; or use the same bitmasks to *solve* the board with backtracking, where placing and un-placing is O(1).
