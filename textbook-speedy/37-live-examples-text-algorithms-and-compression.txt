Live Examples: Text Algorithms and Compression

The Algorithms That Shrink and Match Text

Text algorithms are clever ways of walking a byte sequence. Compression finds repetition and names it once; matching finds structure without checking every alignment. RLE, LZ77, and LZW power nearly every compressor, with Huffman as the entropy coder. Levenshtein distance, KMP, the Burrows-Wheeler transform, and suffix arrays answer 'how similar' and 'where does this occur.' Each is a loop, an array, and one non-obvious move.

Cost vocabulary: one pass is O(n), sorting is O(n log n), a table over two strings is O(m x n). Comparing all rotations is O(n^2) or worse, so real Burrows-Wheeler sorts suffixes; this chapter builds the O(n^2) version first and names the fast one as a variation.

Programs treat text as bytes, `str.at(i)` returning a `u8`, correct for ASCII. For Unicode, run the same algorithms over codepoints via `nextCodepoint` (Chapter17). Compression works on arbitrary bytes anyway.

Each block imports what it needs: `Vec`, `String`, `println`, and for Huffman `PriorityQueue`. A `str` is a borrowed view; a `String` is owned and mutable, and a `String*` out-parameter lets a function append to a caller's buffer.

37.1 Run-Length Encoding

The problem. Encode a byte string so runs of the same byte become compact, and decode it back losslessly.

The idea. At each position, count how often the current byte repeats, emit the count and byte, then jump past the run. The decoder reads a count and byte and writes the byte that many times. RLE wins on long runs and loses on data with none: a run of one costs two bytes.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    Vec<u8> rleEncode(str input) {
        // output is a flat stream of (count, byte) records
        Vec<u8> out = Vec<u8>::new();
        usize i = 0;
        // outer loop consumes exactly one run per iteration
        while (i < input.len) {
            u8 b = input.at(i);
            // a run always contains at least the byte we are looking at
            usize run = 1;
            // extend the run while bytes match, capping at 255 so the count fits one byte
            while (i + run < input.len && input.at(i + run) == b && run < 255) {
                run += 1;
            }
            // emit the count first, then the byte it repeats
            out.push((u8)run);
            out.push(b);
            // skip every byte this record described
            i += run;
        }
        return out;
    }

    String rleDecode(const Vec<u8>* encoded) {
        String out = String::new();
        usize i = 0;
        // require both a count and a byte; a trailing lone count is dropped
        while (i + 1 < encoded->count()) {
            u8 run = encoded->at(i);
            u8 b = encoded->at(i + 1);
            // replay the run by writing the byte that many times
            for (u8 k = 0; k < run; k += 1) {
                out.pushByte(b);
            }
            // step over the count and the byte
            i += 2;
        }
        return out;
    }

    void main() {
        str sample = "aaabbbcccccccd";
        Vec<u8> encoded = rleEncode(sample);
        String decoded = rleDecode(&encoded);
        println("input   {} bytes", sample.len);
        println("encoded {} bytes", encoded.count());
        println("decoded {}", decoded.asView());
        println("lossless {}", decoded.asView().equals(sample));
    }

Each run is a count byte followed by a value byte, so the output is a `Vec<u8>`, which keeps the format unambiguous. The `run < 255` guard caps a run at one byte's worth; longer runs split into several records, and the decoder never notices. `i += run` makes the encode one pass.

Cost and notes. Time O(n): each byte is examined once by its run. Space O(r) for r runs. The encoder's best case is all-equal bytes (two output bytes per 255 input); its worst is no repeats, where output doubles. RLE is a pre-filter for an entropy coder, not a general compressor.

Edge cases and variations. Empty input encodes to an empty vector and decodes to an empty `String`. A run of exactly 255 is one record. An odd-length vector drops the trailing count, because the decoder requires `i + 1 < count()`. Variation: emit a literal alone when a run is shorter than three, as PNG does.

37.2 Huffman Coding with a Min-Heap

The problem. Assign variable-length bit codes so frequent bytes get short codes and rare bytes long ones, then compress and decompress. No code may be a prefix of another, or decoding is ambiguous.

The idea. Build a binary tree bottom-up. Start with one leaf per distinct symbol in a min-heap keyed by frequency. Repeatedly join the two lightest nodes under a node weighted by their sum. The final node is the root, and the path to a leaf (zero left, one right) is its code. Joining the two lightest minimizes average length.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };
    import(lib) std::collections::priorityqueue { PriorityQueue };

    struct HNode {
        u32 freq;
        i32 left;
        i32 right;
        i32 parent;
        u8 bit;
        u8 symbol;
        bool leaf;
    }

    struct HeapItem {
        u32 freq;
        i32 node;
    }

    bool heapLess(HeapItem a, HeapItem b) {
        return a.freq < b.freq;
    }

    i32 huffmanBuild(str input, Vec<HNode>* pool, Vec<i32>* leafOf) {
        Vec<u32> freq = Vec<u32>::new();
        // one slot per possible byte value, all counts starting at zero
        for (usize i = 0; i < 256; i += 1) freq.push(0);
        // tally each byte in a single pass
        for (usize i = 0; i < input.len; i += 1) {
            u8 b = input.at(i);
            // freq[byte] counts how many times that byte occurred
            freq.set((usize)b, freq.at((usize)b) + 1);
        }
        // leafOf maps a symbol to its leaf node; -1 means the symbol is unused
        for (usize i = 0; i < 256; i += 1) leafOf->push(-1);

        // min-heap ordered by frequency, so the two rarest nodes pop first
        PriorityQueue<HeapItem> pq = PriorityQueue<HeapItem>::new(heapLess);
        for (usize s = 0; s < 256; s += 1) {
            // only symbols that actually occur become leaves
            if (freq.at(s) > 0) {
                // a new leaf's index is the pool's current size
                i32 idx = (i32)pool->count();
                // a leaf stores its symbol and weight and has no children
                pool->push(HNode {
                    .freq = freq.at(s), .left = -1, .right = -1, .parent = -1,
                    .bit = 0, .symbol = (u8)s, .leaf = true
                });
                // remember where this symbol's leaf lives for encoding
                leafOf->set(s, idx);
                // the leaf enters the merge queue
                pq.push(HeapItem { .freq = freq.at(s), .node = idx });
            }
        }

        // merge the two lightest nodes until a single tree remains
        while (pq.count() > 1) {
            HeapItem a = pq.pop();
            HeapItem b = pq.pop();
            i32 idx = (i32)pool->count();
            // internal node's weight is the sum of its children
            pool->push(HNode {
                .freq = a.freq + b.freq, .left = a.node, .right = b.node,
                .parent = -1, .bit = 0, .symbol = 0, .leaf = false
            });
            // link each child back to the new parent and record its path bit
            pool->atPtr((usize)a.node)->parent = idx;
            pool->atPtr((usize)a.node)->bit = 0;
            pool->atPtr((usize)b.node)->parent = idx;
            pool->atPtr((usize)b.node)->bit = 1;
            // reinsert the merged node with its combined weight
            pq.push(HeapItem { .freq = a.freq + b.freq, .node = idx });
        }
        // empty input: no leaves were ever created
        if (pool->count() == 0) return -1;
        // the single remaining node is the tree root
        return pq.pop().node;
    }

    String huffmanEncode(str input, const Vec<HNode>* pool, const Vec<i32>* leafOf) {
        String out = String::new();
        // scratch buffer reused to collect each symbol's bits
        Vec<u8> path = Vec<u8>::new();
        // a lone symbol has a root that is itself a leaf and needs a special case
        bool single = pool->count() == 1;
        for (usize i = 0; i < input.len; i += 1) {
            // one bit per character is enough when there is only one symbol
            if (single) { out.pushByte((u8)'0'); continue; }
            // start the walk at this symbol's leaf
            i32 cur = leafOf->at((usize)input.at(i));
            path.clear();
            // walk up to the root, gathering bits least-significant first
            while (pool->at((usize)cur).parent != -1) {
                HNode nd = pool->at((usize)cur);
                path.push(nd.bit);
                cur = nd.parent;
            }
            // emit the collected bits in reverse: root direction comes first
            isize k = (isize)path.count() - 1;
            while (k >= 0) {
                out.pushByte((u8)('0' + path.at((usize)k)));
                k -= 1;
            }
        }
        return out;
    }

    String huffmanDecode(str bits, const Vec<HNode>* pool, i32 root) {
        String out = String::new();
        if (pool->count() == 0) return out;
        // single-symbol tree: every bit stands for that one symbol
        if (pool->at((usize)root).leaf) {
            u8 sym = pool->at((usize)root).symbol;
            for (usize i = 0; i < bits.len; i += 1) out.pushByte(sym);
            return out;
        }
        // start each code at the root and walk down
        i32 cur = root;
        for (usize i = 0; i < bits.len; i += 1) {
            HNode nd = pool->at((usize)cur);
            // a '0' turns left, anything else turns right
            if (bits.at(i) == (u8)'0') cur = nd.left;
            else cur = nd.right;
            HNode c = pool->at((usize)cur);
            // landing on a leaf completes a symbol; reset to the root
            if (c.leaf) {
                out.pushByte(c.symbol);
                cur = root;
            }
        }
        return out;
    }

    void main() {
        str text = "this is an example of a huffman tree";
        Vec<HNode> pool = Vec<HNode>::new();
        Vec<i32> leafOf = Vec<i32>::new();
        i32 root = huffmanBuild(text, &pool, &leafOf);
        if (root < 0) return;
        String bits = huffmanEncode(text, &pool, &leafOf);
        String back = huffmanDecode(bits.asView(), &pool, root);
        println("input   {} bytes", text.len);
        println("encoded {} bits", bits.len);
        println("roundtrip {}", back.asView().equals(text));
    }

`parent` and `bit` remove the need to store codes. On each merge, both children learn their parent and bit, so a leaf can walk up on demand. Encoding walks leaf to root, collecting bits, then emits them reversed. Decoding walks down from the root and resets at each leaf. The `single` guard handles one distinct symbol: the code is '0', repeated once per bit.

Cost and notes. Counting is O(n). The heap holds at most 256 entries, so the build is O(k log k) with k effectively constant. Encoding is O(n x depth), decoding O(bits). Skewed frequencies approach entropy, the theoretical floor; a uniform distribution gains almost nothing.

Edge cases and variations. Empty input returns before building, so nothing asserts on an empty heap. The single-symbol case trips naive code because the root is a leaf with no children. `freq` is `u32`, overflowing above four billion bytes; production uses `u64` or rescales. The heap tie-break is arbitrary, so several equally optimal trees exist. Variation: canonical Huffman ships code lengths and rebuilds deterministically, as DEFLATE and zstd do.

37.3 LZ77 Sliding-Window Compression

The problem. Compress by replacing repeated substrings with an (offset, length) backward reference, followed by the next literal byte.

The idea. Keep a window of the last `w` bytes. At the current position, find the longest match and emit a reference plus the literal that broke it. With no match, emit offset zero and the literal alone. The window slides forward. LZ77 is the engine inside DEFLATE, gzip, and zlib; add Huffman coding of tokens and you have the format that compressed the web.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    struct LzToken {
        usize offset;
        usize length;
        u8 literal;
    }

    Vec<LzToken> lz77Encode(str input, usize windowSize) {
        Vec<LzToken> tokens = Vec<LzToken>::new();
        usize n = input.len;
        usize pos = 0;
        // produce one token per position, advancing pos each time
        while (pos < n) {
            // the search window begins windowSize bytes back, or at 0
            usize start = pos > windowSize ? pos - windowSize : 0;
            // track the longest match seen so far and how far back it starts
            usize bestLen = 0;
            usize bestOff = 0;
            // try every earlier position inside the window
            for (usize s = start; s < pos; s += 1) {
                // measure how far the candidate and current position agree
                usize l = 0;
                // the guard keeps the read inside the input
                while (pos + l < n && input.at(s + l) == input.at(pos + l)) {
                    l += 1;
                }
                // a longer match replaces the previous best
                if (l > bestLen) {
                    bestLen = l;
                    bestOff = pos - s;
                }
                // cannot beat matching to the end of input; stop early
                if (bestLen == n - pos) break;
            }
            // the literal that follows the match, or 0 if the match reached the end
            u8 lit = pos + bestLen < n ? input.at(pos + bestLen) : 0;
            tokens.push(LzToken {
                .offset = bestOff, .length = bestLen, .literal = lit
            });
            // consume the match plus its terminating literal
            pos += bestLen + 1;
        }
        return tokens;
    }

    String lz77Decode(const Vec<LzToken>* tokens) {
        String out = String::new();
        for (usize i = 0; i < tokens->count(); i += 1) {
            LzToken t = tokens->at(i);
            // a zero-length token means the literal stands alone
            if (t.length > 0) {
                // offset is measured back from the current output end
                usize from = out.len - t.offset;
                // copy byte by byte so an overlap can read bytes just written
                for (usize k = 0; k < t.length; k += 1) {
                    out.pushByte(out.at(from + k));
                }
            }
            out.pushByte(t.literal);
        }
        return out;
    }

    void main() {
        str text = "abracadabra abracadabra abracadabra";
        Vec<LzToken> toks = lz77Encode(text, 16);
        String back = lz77Decode(&toks);
        println("input  {} bytes", text.len);
        println("tokens {}", toks.count());
        println("roundtrip {}", back.asView().equals(text));
    }

The inner `while` walks from candidate `s` and `pos` together, never reading past the end thanks to `pos + l < n`. Overlapping matches let a reference reach into bytes not yet written: the decoder copies byte by byte, each copy a source for the next, which is how 'aaaa' becomes one token. Each token advances `pos` by `bestLen + 1`, the literal that ended the match.

Cost and notes. The straightforward search is O(n x window) comparisons, or O(n x window x maxlength) with long matches. Production encoders reach O(n) with hash chains or suffix structures, which is why DEFLATE is fast. A repeated 12-byte phrase becomes one token; longer repetitions and smaller windows improve the ratio. The decoder is strictly linear and must be fast.

Edge cases and variations. `windowSize` zero makes `start == pos`, so every token is a lone literal, a useful check. At end of input `bestLen` may reach the final byte; the unused literal is written as `0`. A token whose `offset` exceeds `out.len` underflows, so a decoder reading untrusted data must validate. Variation: DEFLATE's lazy match emits a literal when the next position has a longer match, buying several percent.

37.4 LZW Dictionary Compression

The problem. Build the dictionary as you go. Each output code refers to a dictionary entry, and new entries come from combinations the decoder has just seen, so the dictionary is never transmitted.

The idea. Both sides start with 256 single-byte entries, and the next free code is 256. The encoder keeps a current string, initially the first byte. For each next byte, if the concatenation is in the dictionary, extend; otherwise emit the current code, add the concatenation, and restart at the new byte. Emit the last code at the end. The decoder reconstructs entries in lock-step. LZW is what `compress` and GIF use.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    Vec<i32> lzwEncode(str input) {
        Vec<i32> out = Vec<i32>::new();
        // no input, no codes
        if (input.len == 0) return out;
        Vec<Vec<i32>> dict = Vec<Vec<i32>>::new();
        // seed the dictionary with the 256 single-byte codes
        for (usize s = 0; s < 256; s += 1) {
            Vec<i32> row = Vec<i32>::new();
            for (usize c = 0; c < 256; c += 1) row.push(-1);
            dict.push(row);
        }
        // next free code; new entries grow past the base alphabet
        i32 next = 256;
        // w is the longest prefix seen so far, tracked as a dictionary code
        i32 w = (i32)input.at(0);
        // i starts at 1 because the first byte already seeded w
        for (usize i = 1; i < input.len; i += 1) {
            u8 c = input.at(i);
            // does w followed by c already have a code?
            i32 found = dict.atPtr((usize)w)->at((usize)c);
            if (found != -1) {
                // extend the current string without emitting anything yet
                w = found;
            } else {
                // no extension: emit w and register w+c as a new code
                out.push(w);
                dict.atPtr((usize)w)->set((usize)c, next);
                // grow the flat table by one all-(-1) row
                Vec<i32> row = Vec<i32>::new();
                for (usize k = 0; k < 256; k += 1) row.push(-1);
                dict.push(row);
                next += 1;
                w = (i32)c;
            }
        }
        // flush the final pending string
        out.push(w);
        return out;
    }

    void lzwEmit(String* out, i32 code, const Vec<i32>* dprev, const Vec<u8>* dsuf) {
        Vec<i32> stack = Vec<i32>::new();
        i32 c = code;
        // climb the prefix chain down to a base single-byte code
        while (c >= 256) {
            stack.push(c);
            c = dprev->at((usize)c);
        }
        // the base byte begins the expansion
        out->pushByte((u8)c);
        // replay the suffixes from the deepest prefix outward
        isize k = (isize)stack.count() - 1;
        while (k >= 0) {
            out->pushByte(dsuf->at((usize)stack.at((usize)k)));
            k -= 1;
        }
    }

    u8 lzwFirst(i32 code, const Vec<i32>* dprev) {
        i32 c = code;
        // walk to the base entry; that single byte is the string's first
        while (c >= 256) c = dprev->at((usize)c);
        return (u8)c;
    }

    String lzwDecode(const Vec<i32>* codes) {
        String out = String::new();
        if (codes->count() == 0) return out;
        Vec<i32> dprev = Vec<i32>::new();
        Vec<u8> dsuf = Vec<u8>::new();
        // base entries: codes below 256 are single bytes with no prefix
        for (usize i = 0; i < 256; i += 1) {
            dprev.push(-1);
            dsuf.push(0);
        }
        i32 next = 256;
        i32 prev = codes->at(0);
        // the first code has no predecessor, so emit it directly
        lzwEmit(&out, prev, &dprev, &dsuf);
        // each later code may refer to an entry not built yet (the KwKwK case)
        for (usize i = 1; i < codes->count(); i += 1) {
            i32 code = codes->at(i);
            if (code < next) {
                // known code: emit it, then add the entry the encoder made
                lzwEmit(&out, code, &dprev, &dsuf);
                // the new entry's prefix is the previous string
                dprev.push(prev);
                // and its trailing byte is the first byte of the code just emitted
                dsuf.push(lzwFirst(code, &dprev));
                next += 1;
            } else {
                // code == next: it is prev plus prev's own first byte
                u8 fb = lzwFirst(prev, &dprev);
                lzwEmit(&out, prev, &dprev, &dsuf);
                // append that first byte to finish the new entry
                out.pushByte(fb);
                dprev.push(prev);
                dsuf.push(fb);
                next += 1;
            }
            // the current code becomes the prefix source for the next iteration
            prev = code;
        }
        return out;
    }

    void main() {
        str text = "TOBEORNOTTOBEORTOBEORNOT";
        Vec<i32> codes = lzwEncode(text);
        String back = lzwDecode(&codes);
        println("input  {} bytes", text.len);
        println("codes  {}", codes.count());
        println("roundtrip {}", back.asView().equals(text));
    }

The encoder's dictionary is a flat `Vec<Vec<i32>>`: one 256-wide row per code, `dict[w][c]` holding the code for `w` followed by `c`, or -1. `atPtr` gives a pointer to the row without copying an owning `Vec`. The decoder stores `dprev` and `dsuf`, so each extended code remembers its prefix and trailing byte; `lzwEmit` walks the chain and replays suffixes, keeping decoding linear.

Cost and notes. Encoding is O(n) lookups, each O(1) because the table is flat; real implementations use a hash map of (prefix, byte) pairs to avoid wide rows. Decoding is O(n x entryLength) worst case for `lzwEmit`, but bounded overall because the dictionary grows and short paths dominate. Repeated phrases cost a handful of codes. LZW's weakness is an unbounded dictionary and growing code width, so GIF freezes at 4096 entries and resets.

Edge cases and variations. The decoder's `else` branch is the KwKwK case: a code equal to `next`, emitted before the decoder creates it, because the just-added entry is the previous string plus its own first byte. Emit `prev`, append its first byte, then add the same entry. Getting this wrong is the classic LZW bug, visible on 'aaaaa'. Empty input and a single code are handled by the early return and initial `lzwEmit`.

37.5 Levenshtein Edit Distance

The problem. Compute the minimum insertions, deletions, and substitutions that turn one string into another, then recover an alignment that achieves it.

The idea. Fill a table where `dp[i][j]` is the distance between the first `i` characters of `a` and first `j` of `b`. The first row and column are the index, since turning 'abc' into '' costs three deletions. Each interior cell is the cheapest of delete (above plus one), insert (left plus one), or substitute (diagonal, plus zero on a match, one otherwise). The bottom-right is the answer; walking backward retraces the alignment.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    i32 editDistance(str a, str b, Vec<i32>* table) {
        usize m = a.len;
        usize n = b.len;
        // flat (m+1) x (n+1) table, stored row-major
        table->clear();
        // allocate the whole table up front
        for (usize i = 0; i <= m; i += 1) {
            for (usize j = 0; j <= n; j += 1) {
                table->push(0);
            }
        }
        // first column: i deletions reduce a's prefix to empty
        for (usize i = 0; i <= m; i += 1) table->set(i * (n + 1), (i32)i);
        // first row: j insertions build b's prefix from empty
        for (usize j = 0; j <= n; j += 1) table->set(j, (i32)j);
        for (usize i = 1; i <= m; i += 1) {
            for (usize j = 1; j <= n; j += 1) {
                // matching characters align for free
                i32 subCost = a.at(i - 1) == b.at(j - 1) ? 0 : 1;
                // candidate 1: delete a[i-1], taking the cell above
                i32 best = table->at((i - 1) * (n + 1) + j) + 1;
                // candidate 2: insert b[j-1], taking the cell to the left
                i32 insert = table->at(i * (n + 1) + (j - 1)) + 1;
                if (insert < best) best = insert;
                // candidate 3: align or substitute, taking the diagonal
                i32 substitute = table->at((i - 1) * (n + 1) + (j - 1)) + subCost;
                if (substitute < best) best = substitute;
                // keep the cheapest of the three moves
                table->set(i * (n + 1) + j, best);
            }
        }
        // the bottom-right corner is the full distance
        return table->at(m * (n + 1) + n);
    }

    void printAlignment(const Vec<i32>* table, str a, str b) {
        usize n = b.len;
        String top = String::new();
        String bot = String::new();
        String op = String::new();
        // start from the bottom-right cell, where the full distance lives
        isize i = (isize)a.len;
        isize j = (isize)n;
        // walk back toward the origin, one cell at a time
        while (i > 0 || j > 0) {
            i32 here = table->at((usize)i * (n + 1) + (usize)j);
            // matching characters sit on the optimal diagonal
            if (i > 0 && j > 0 && a.at((usize)(i - 1)) == b.at((usize)(j - 1)) &&
                here == table->at((usize)(i - 1) * (n + 1) + (usize)(j - 1))) {
                op.pushByte((u8)'=');
                top.pushByte(a.at((usize)(i - 1)));
                bot.pushByte(b.at((usize)(j - 1)));
                i -= 1;
                j -= 1;
            } else if (i > 0 &&
                here == table->at((usize)(i - 1) * (n + 1) + (usize)j) + 1) {
                // the value came from above: a deletion from a
                op.pushByte((u8)'-');
                top.pushByte(a.at((usize)(i - 1)));
                bot.pushByte((u8)'_');
                i -= 1;
            } else if (j > 0 &&
                here == table->at((usize)i * (n + 1) + (usize)(j - 1)) + 1) {
                // the value came from the left: an insertion from b
                op.pushByte((u8)'+');
                top.pushByte((u8)'_');
                bot.pushByte(b.at((usize)(j - 1)));
                j -= 1;
            } else {
                // otherwise the optimal path took a substitution
                op.pushByte((u8)'*');
                top.pushByte(a.at((usize)(i - 1)));
                bot.pushByte(b.at((usize)(j - 1)));
                i -= 1;
                j -= 1;
            }
        }
        // built backward; reverse all three rows for display
        top.reverse();
        bot.reverse();
        op.reverse();
        println("{}", top.asView());
        println("{}", bot.asView());
        println("{}", op.asView());
    }

    void main() {
        str a = "kitten";
        str b = "sitting";
        Vec<i32> table = Vec<i32>::new();
        i32 d = editDistance(a, b, &table);
        println("edit distance {}", d);
        printAlignment(&table, a, b);
    }

The table is a flat `Vec<i32>` indexed by `i * (n + 1) + j`, faster and smaller than a vector of vectors. `editDistance` fills it and returns the last entry; `printAlignment` walks backward and uses the values to choose each move. The `op` legend is `=` match, `*` substitution, `-` deletion from `a`, `+` insertion from `b`. Rows are built backward and reversed.

Cost and notes. Time and space are O(m x n). The table is the price of the alignment: the distance alone needs two rolling rows and O(n) space, but the backtrack needs the whole table. A spell-checker can use O(n) space; a diff tool needs the alignment. This underpins `diff`, fuzzy matching, and speech and OCR error models.

Edge cases and variations. An empty string against a non-empty one gives the other's length, with no special case. The backtrack prefers a match on equal characters, safe because the diagonal is then a minimizer. Delete and insert ties break in a fixed order, so the alignment is deterministic but not unique. Variation: rolling rows for O(n) space; Myers diff runs in O((m + n) x d) and is what `git diff` uses.

37.6 Knuth–Morris–Pratt Substring Search

The problem. Find every occurrence of a pattern without re-examining text characters, so the search stays linear even for patterns like 'aaaaab' that make the naive method quadratic.

The idea. Precompute a failure function: for each pattern position, the length of the longest proper prefix that is also a suffix. On a mismatch it says how far to fall back without moving the text pointer. Each text character is inspected once, so the search is O(n + m).

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    Vec<usize> buildFailure(str pat) {
        usize m = pat.len;
        Vec<usize> fail = Vec<usize>::new();
        for (usize i = 0; i < m; i += 1) fail.push(0);
        // k is the length of the longest prefix matching a suffix seen so far
        usize k = 0;
        // fill fail[i] for each prefix ending at i
        for (usize i = 1; i < m; i += 1) {
            // on mismatch, fall back through the earlier failure links
            while (k > 0 && pat.at(i) != pat.at(k)) k = fail.at(k - 1);
            // characters agree, so the matched border grew by one
            if (pat.at(i) == pat.at(k)) k += 1;
            // record the border length for position i
            fail.set(i, k);
        }
        return fail;
    }

    Vec<usize> kmpSearch(str text, str pat) {
        Vec<usize> matches = Vec<usize>::new();
        // an empty pattern has no meaningful position
        if (pat.len == 0) return matches;
        Vec<usize> fail = buildFailure(pat);
        // k counts how many pattern characters match at the current text position
        usize k = 0;
        for (usize i = 0; i < text.len; i += 1) {
            // on mismatch, fall back without moving the text pointer
            while (k > 0 && text.at(i) != pat.at(k)) k = fail.at(k - 1);
            if (text.at(i) == pat.at(k)) k += 1;
            // the whole pattern matched
            if (k == pat.len) {
                // start index of this occurrence
                matches.push(i + 1 - pat.len);
                // fall back so overlapping matches are still found
                k = fail.at(k - 1);
            }
        }
        return matches;
    }

    void main() {
        str text = "abababcabababcabababc";
        str pat = "ababc";
        Vec<usize> hits = kmpSearch(text, pat);
        for (usize i = 0; i < hits.count(); i += 1) {
            println("match at {}", hits.at(i));
        }
        println("total {}", hits.count());
    }

`buildFailure` runs the same scan on the pattern against itself. `k` is the current matched prefix length; on a mismatch it falls back to `fail[k - 1]`, and only a match advances `k`. The search never decrements `i`, which is why it is linear. After a full match, `k = fail[k - 1]` finds overlapping occurrences, so 'aa' in 'aaa' is reported at 0 and 1.

Cost and notes. Both phases are O(n + m): each iteration advances `i` or decreases `k`, and `k` cannot decrease more times than it increased. That amortised argument is why KMP exists, the same shared-budget reasoning as the two-pointer palindrome scan in Chapter25. Space is O(m).

Edge cases and variations. An empty pattern is rejected up front, since matching everywhere is rarely intended and `pat.at(0)` would assert. A pattern longer than the text never reaches `k == pat.len`. The first failure entry is always zero, and each value is at most its position, so fallback makes progress. Beyond KMP, Boyer-Moore skips more but needs a KMP-style table to bound its worst case.

37.7 The Burrows–Wheeler Transform

The problem. Reversibly rearrange a string so characters cluster into runs, then feed it to a run-aware compressor. This is the front end of `bzip2`, and why BWT plus Huffman beats Huffman alone on real text.

The idea. Write down every rotation, sort them lexicographically, and take the last column, which tends to have long runs because equal characters end up adjacent. Reversal also needs the row index of the original string; the inverse uses the last-to-first mapping, a stable count of each character's occurrences. Nothing is lost and no marker is needed.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    bool rotationLess(str s, usize i, usize j) {
        usize n = s.len;
        // compare the two rotations character by character
        for (usize k = 0; k < n; k += 1) {
            u8 a = s.at((i + k) % n);
            u8 b = s.at((j + k) % n);
            // the first differing character decides the order
            if (a != b) return a < b;
        }
        // identical rotations compare as equal
        return false;
    }

    void sortRotations(str s, Vec<usize>* idx) {
        // insertion sort; it is stable, which matters for equal rotations
        for (usize i = 1; i < idx->count(); i += 1) {
            usize key = idx->at(i);
            isize j = (isize)i - 1;
            // shift larger rotations right to open a slot for key
            while (j >= 0 && rotationLess(s, key, idx->at((usize)j))) {
                idx->set((usize)(j + 1), idx->at((usize)j));
                j -= 1;
            }
            // drop key into its sorted place
            idx->set((usize)(j + 1), key);
        }
    }

    String bwtEncode(str s, usize* primaryIndex) {
        usize n = s.len;
        String last = String::new();
        *primaryIndex = 0;
        if (n == 0) return last;
        Vec<usize> idx = Vec<usize>::new();
        // each rotation is identified by the index it starts at
        for (usize i = 0; i < n; i += 1) idx.push(i);
        // sort the start indices by their rotation
        sortRotations(s, &idx);
        // the last column holds the character just before each rotation's start
        for (usize i = 0; i < n; i += 1) {
            usize start = idx.at(i);
            last.pushByte(s.at((start + n - 1) % n));
        }
        // find the row that is the unrotated string; the inverse needs it
        for (usize i = 0; i < n; i += 1) {
            if (idx.at(i) == 0) {
                *primaryIndex = i;
                break;
            }
        }
        return last;
    }

    String bwtDecode(str last, usize primary) {
        usize n = last.len;
        String out = String::new();
        if (n == 0) return out;
        Vec<usize> count = Vec<usize>::new();
        for (usize i = 0; i < 256; i += 1) count.push(0);
        // count how often each byte appears in the last column
        for (usize i = 0; i < n; i += 1) {
            u8 b = last.at(i);
            count.set((usize)b, count.at((usize)b) + 1);
        }
        Vec<usize> C = Vec<usize>::new();
        usize total = 0;
        // C[b] is where byte b's block begins in the first column
        for (usize i = 0; i < 256; i += 1) {
            C.push(total);
            total += count.at(i);
        }
        // occ tracks how many times each byte has been seen so far
        Vec<usize> occ = Vec<usize>::new();
        for (usize i = 0; i < 256; i += 1) occ.push(0);
        Vec<usize> lf = Vec<usize>::new();
        // lf maps a last-column row to its row in the first column
        for (usize i = 0; i < n; i += 1) {
            u8 b = last.at(i);
            // rank within the byte's block, plus the block's start
            lf.push(C.at((usize)b) + occ.at((usize)b));
            occ.set((usize)b, occ.at((usize)b) + 1);
        }
        // start at the row holding the original string
        usize row = primary;
        // follow the last-to-first links, emitting one byte per step
        for (usize k = 0; k < n; k += 1) {
            out.pushByte(last.at(row));
            row = lf.at(row);
        }
        // the walk yields the string backward, so flip it
        out.reverse();
        return out;
    }

    void main() {
        str text = "banana";
        usize primary = 0;
        String last = bwtEncode(text, &primary);
        String back = bwtDecode(last.asView(), primary);
        println("input     {}", text);
        println("bwt       {}", last.asView());
        println("primary   {}", primary);
        println("roundtrip {}", back.asView().equals(text));
    }

`rotationLess` compares rotations without materialising them, reading `s` at `(i + k) % n` and `(j + k) % n`. `sortRotations` is an inline insertion sort because a function pointer cannot capture `s`; `Vec::sortBy` would need a global. `bwtEncode` outputs the last column and records the original row. The inverse computes `C`, each byte's cumulative starting rank, and `lf`, mapping a row to the row beginning with its last character, then walks from the primary row and reverses.

Cost and notes. The honest version materialises nothing but pays for sorting: insertion sort is O(n^2) comparisons of O(n), so O(n^3), fine only for small strings. Real BWT builds a suffix array in O(n log n) by prefix doubling. The inverse is linear once `C` and `lf` exist. The payoff is the `bzip2` pipeline: run-length encode the last column, then Huffman code the runs.

Edge cases and variations. An empty string transforms to empty with primary index zero. A periodic string like 'abab' has equal rotations, and the stable sort preserves original order, so it round-trips. The primary index is the row whose rotation starts at zero; getting it wrong yields a rotation of the original, a subtle bug because the output still looks like text.

37.8 Suffix-Array Substring Search

The problem. Index a text once, then answer many substring queries quickly, returning an occurrence without rescanning.

The idea. Sort every suffix and store the start indices. A pattern occurs exactly when it is a prefix of some suffix, and sorted suffixes beginning with the pattern form a contiguous block. Binary search finds that block in O(log n) comparisons, each costing at most the pattern length. Build once, query many times.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    bool suffixLess(str text, usize i, usize j) {
        usize n = text.len;
        // compare two suffixes without materialising either of them
        while (i < n && j < n) {
            u8 a = text.at(i);
            u8 b = text.at(j);
            // the first difference decides the order
            if (a != b) return a < b;
            i += 1;
            j += 1;
        }
        // the suffix that ended first is the smaller one
        return i == n;
    }

    void buildSuffixArray(str text, Vec<usize>* sa) {
        usize n = text.len;
        // start with every suffix index in ascending order
        for (usize i = 0; i < n; i += 1) sa->push(i);
        // insertion sort by suffix order
        for (usize i = 1; i < n; i += 1) {
            usize key = sa->at(i);
            isize j = (isize)i - 1;
            // shift larger suffixes right to open a slot for key
            while (j >= 0 && suffixLess(text, key, sa->at((usize)j))) {
                sa->set((usize)(j + 1), sa->at((usize)j));
                j -= 1;
            }
            // insert key at its sorted position
            sa->set((usize)(j + 1), key);
        }
    }

    i32 compareSuffixPattern(str text, usize start, str pat) {
        usize n = text.len;
        usize k = 0;
        // compare the suffix to the pattern until one of them runs out
        while (start + k < n && k < pat.len) {
            u8 a = text.at(start + k);
            u8 b = pat.at(k);
            // first difference gives a three-way result: -1, 0, or 1
            if (a != b) return a < b ? -1 : 1;
            k += 1;
        }
        // pattern consumed first means it is a prefix, hence a match
        if (k == pat.len) return 0;
        // the suffix ended first, so the pattern is larger
        return -1;
    }

    Option<usize> suffixSearch(str text, str pat, const Vec<usize>* sa) {
        // an empty pattern is a prefix of every suffix
        if (pat.len == 0) return Option<usize>::Some { .value = 0 };
        isize lo = 0;
        isize hi = (isize)sa->count() - 1;
        // ordinary binary search over the sorted suffix array
        while (lo <= hi) {
            isize mid = lo + (hi - lo) / 2;
            i32 c = compareSuffixPattern(text, sa->at((usize)mid), pat);
            // found: return the suffix's start position in the text
            if (c == 0) return Option<usize>::Some { .value = sa->at((usize)mid) };
            // suffix is smaller; drop the left half
            if (c < 0) lo = mid + 1;
            else hi = mid - 1;
        }
        // range exhausted without a match
        return Option<usize>::None;
    }

    void main() {
        str text = "mississippi";
        str pat = "issi";
        Vec<usize> sa = Vec<usize>::new();
        buildSuffixArray(text, &sa);
        println("suffixes {}", sa.count());
        switch (suffixSearch(text, pat, &sa)) {
            Option::Some { value } => { println("found '{}' at {}", pat, value); },
            Option::None => { println("'{}' not found", pat); }
        }
    }

The suffix array is a `Vec<usize>` of start positions sorted by suffix. `suffixLess` compares byte by byte, treating the suffix that ends first as smaller, without allocating. `compareSuffixPattern` returns three-way, with a pattern that is a prefix counting as a match. `suffixSearch` is ordinary binary search, and `Option` carries not-found without a sentinel, as Chapter36 argues.

Cost and notes. Building here is insertion sort with an O(n) comparator, so O(n^2) comparisons and O(n^3) time: correct and clear, but only for modest texts. Prefix doubling builds in O(n log n) and is what real suffix arrays use. Queries are O(pat.len x log n), so the point is amortisation. The array stores 8 bytes per suffix plus the text, which is why suffix arrays displaced suffix trees.

Edge cases and variations. An empty pattern matches at position zero and returns before the search. A pattern longer than any suffix is handled by `compareSuffixPattern` returning -1 when the suffix ends first. The search returns one occurrence; scan left and right while the comparison returns zero to find all. Variation: a longest-common-prefix array reduces per-comparison cost to O(1).

37.9 A Substitution Cipher

The problem. Encrypt a message with a repeating key so each letter gets a different shift, then decrypt it. This is the Vigenere cipher, the step from Caesar's single shift to a polyalphabetic one.

The idea. Shift each letter by the corresponding key letter's alphabet position. Advance the key only on letters, so spaces and punctuation pass through unchanged. Decryption subtracts. Both directions reduce the letter to a 0-through-25 index, operate there, and add the case's base back.

The implementation.

    import(lib) std::text::string { String };
    import(lib) std::io::ios { println };

    String vigenere(str text, str key, bool encrypt) {
        String out = String::new();
        // a missing key means no shift; return the input untouched
        if (key.len == 0) return String::from(text);
        // the key index advances only when a letter is consumed
        usize ki = 0;
        for (usize i = 0; i < text.len; i += 1) {
            u8 c = text.at(i);
            u8 base = 0;
            if (c >= (u8)'A' && c <= (u8)'Z') {
                base = (u8)'A';
            } else if (c >= (u8)'a' && c <= (u8)'z') {
                base = (u8)'a';
            } else {
                // non-letters are copied verbatim and do not consume key
                out.pushByte(c);
                continue;
            }

            // cycle through the key
            u8 k = key.at(ki % key.len);
            u8 kbase = 0;
            if (k >= (u8)'A' && k <= (u8)'Z') {
                kbase = (u8)'A';
            } else if (k >= (u8)'a' && k <= (u8)'z') {
                kbase = (u8)'a';
            } else {
                // a non-letter key byte is a deliberate refusal
                return String::from(text);
            }

            // shift the key letter to a 0..25 index
            u8 shift = (u8)(k - kbase);
            u8 letter = (u8)(c - base);
            if (encrypt) {
                // encrypt adds the shift, wrapping modulo 26
                letter = (u8)((letter + shift) % 26);
            } else {
                // decrypt subtracts; the +26 keeps the result non-negative
                letter = (u8)((letter + 26 - shift) % 26);
            }
            // restore the original letter's case base
            out.pushByte((u8)(letter + base));
            // a letter was consumed, so advance the key
            ki += 1;
        }
        return out;
    }

    void main() {
        str message = "Attack at dawn!";
        str key = "lemon";
        String cipher = vigenere(message, key, true);
        String plain = vigenere(cipher.asView(), key, false);
        println("plain     {}", message);
        println("cipher    {}", cipher.asView());
        println("decoded   {}", plain.asView());
        println("roundtrip {}", plain.asView().equals(message));
    }

The two case checks could be a `letterBase(u8)` helper returning the base or -1, the DRY refactor of Chapter36. The `continue` on a non-letter keeps the key aligned: punctuation is copied and `ki` is not advanced. Decryption adds 26 before subtracting so the result never goes negative.

Cost and notes. One pass, O(n) time and O(n) space for the owned output. Vigenere was believed unbreakable for three centuries and is trivially broken today by frequency analysis: a repeating key leaks its period, then each shift is a Caesar cipher. This is text manipulation, not cryptography; use the standard library's AES or Appendix I, never a hand-rolled cipher.

Edge cases and variations. An empty key returns the input unchanged, and a key with non-letter bytes does the same, a deliberate refusal. Empty text returns an empty string, and case is preserved. Variation: the one-time pad uses a key as long as the message, never reused, and is information-theoretically unbreakable. Explain why a repeating key can never be a pad, in terms of frequency counts.
