Chapter0

A Gentle Start

Programming for the Very First Time

This chapter assumes no programming experience.

By the end you will know what a program and a compiler are, and how to make decisions, repeat work, and package it into functions.

0.1 What a Program Is

A program is an ordered list of instructions a machine carries out.

Instructions decide and repeat. The machine understands only its own simple operations, so the program must be translated first.

0.2 What a Compiler Does

A compiler translates source into the machine code the machine runs.

It also checks your work. On a misspelling, missing punctuation, or wrong type it stops and reports what it could not understand and roughly where.

Writing, compiling, reading errors, fixing, and running is the daily loop.

0.3 A Mental Model: Values, Memory, and Control Flow

One working model, refined later.

A value is what a memory location holds, such as 42 or "hello". A variable is a name for a value.

Control flow is the order instructions run: usually top to bottom, but it can branch on a condition or repeat.

0.4 What Coral Is, and Why This Book Teaches It

Coral is a programming language: you write it, a compiler translates it, the machine runs it.

Coral is small: a short list of built-in ideas, with almost everything else built from them.

Coral is explicit: type changes and memory use are written down.

Coral is C-shaped.

It has no magic, so the program you read is the program that runs.

0.5 How to Read This Book

Chapters build: Chapter0 is the friendliest, Chapter1 the design, Chapter2 the raw material. Later chapters assume earlier ones.

Every example is valid Coral. Type them in.

Do the exercises. You learn to program by writing.

When stuck, read the compiler message, compare your code character by character with the nearest example, and ask for help.

0.6 Your First Program

The smallest complete program, in a file named hello.crl:

    pub void main()
    {
        println("Hello, world.");
    }

It prints:

    Hello, world.

Each piece in turn.

    pub

pub means public: the function is visible outside this file.

    void

void is the return type meaning nothing; a void main returns no value. Coral also allows i32 main with return 0. The type comes before the name.

    main

main is where the program begins.

    ()

The parentheses hold inputs. Empty means main takes none.

    {

The brace opens the body, grouping instructions. Indentation is only for readers.

        println("Hello, world.");

println is a ready-made action that prints its argument and a newline. "Hello, world." is a string. The semicolon ends the instruction.

println and print are available without an import. Other tools live in the standard library and need an import line.

    }

This closes the body and ends the program.

Here is a value printed rather than fixed text:

    pub void main()
    {
        i32 answer = 40 + 2;
        println("The answer is {}.", answer);
    }

This declares answer and stores 40 + 2. The {} in the text is a placeholder filled with answer, here 42. Output:

    The answer is 42.

0.7 Variables, Types, and Values: A First Look

A variable is a name for a value in memory. Declare it with a type, a name, an equals sign, and a value:

    i32 score = 0;
    f64 temperature = 98.6;
    bool is_ready = true;
    str greeting = "hello";

f64 is a floating-point number with a fractional part; bool is true or false; str is text.

Assign a new value after creation:

    score = 10;
    score = score + 5;

The right side is computed first.

The kind of a value is its type. Coral will not mix types carelessly; storing 98.6 in an i32 is a compile error.

When the type is obvious, var lets the compiler infer it:

    var count = 100;
    var pi = 3.14159;

count is an integer and pi a float. Use explicit types when the type is the interesting fact.

Types get a full treatment in Chapter2.

0.8 Making a Decision

The if statement checks a condition and runs a block when it is true.

    if (age >= 18)
    {
        println("You may vote.");
    }

The condition is in parentheses and the body in braces.

else supplies the alternative:

    if (age >= 18)
    {
        println("You may vote.");
    }
    else
    {
        println("Not yet.");
    }

Exactly one of the two blocks runs.

Chain checks with else if; each is tried only if the earlier ones were false:

    char grade = 'F';
    if (score >= 90)
    {
        grade = 'A';
    }
    else if (score >= 80)
    {
        grade = 'B';
    }
    else if (score >= 70)
    {
        grade = 'C';
    }
    else if (score >= 60)
    {
        grade = 'D';
    }
    else
    {
        grade = 'F';
    }

The first true condition wins, and the final else catches the rest.

The condition must be a real bool. A number is not true or false, so a forgotten comparison is a compile error.

A decision can also produce a value:

    i32 magnitude = if (x < 0) -x else x;

Control flow gets full treatment in Chapter4.

0.9 Repeating Work

The while loop repeats a block while a condition stays true.

    i32 sum = 0;
    i32 i = 1;
    while (i <= 5)
    {
        sum = sum + i;
        i = i + 1;
    }
    println("The sum is {}.", sum);

sum starts at 0 and i at 1. Each pass adds i and increments it; when i reaches 6 the condition fails, printing 15.

The counter is set up before the loop, changed inside, and tested in the condition. Without a change toward stopping, the loop runs forever.

The ranged for walks a collection:

    var numbers = Vec<i32>::withCap(4);
    numbers.push(3);
    numbers.push(5);
    numbers.push(8);

    i32 total = 0;
    for (var n : numbers)
    {
        total = total + n;
    }
    println("The total is {}.", total);

A Vec is a growable list (Chapter16). The loop is the point:

    for (var n : numbers)

Each trip binds n to the next element; no counter, bounds check, or increment is written. Chapter4 covers both loops.

0.10 Functions: Named, Reusable Steps

A named, reusable step is a function.

    i32 add(i32 a, i32 b)
    {
        return a + b;
    }

This produces an i32 named add, needing two i32 inputs a and b. return hands back the answer and ends the function.

    i32 total = add(2, 3);
    i32 other = add(total, 10);

The first call returns 5; the second returns 15.

Chapter5 covers functions fully. The shape is type, name, inputs, body, return.

0.11 A Short Glossary

The rest of the book assumes these words.

    value
        A single piece of information: the number 42, the text "hi", the answer true. Values are what programs compute with.

    variable
        A name for a value stored in memory. You create one by giving it a type, a name, and a value. You can change what it holds by assigning a new value.

    type
        The kind of a value, such as i32 (an integer), f64 (a number with a fractional part), bool (yes or no), or str (text). The type says how much room the value needs and what you may do with it. Coral's types are written before names.

    function
        A named, reusable set of instructions. It may take inputs (in parentheses) and may hand back a result (its return type). Calling its name runs it. main is the function where a program starts.

    statement
        A single instruction, usually ending with a semicolon. "Add these two numbers and store the result" is a statement.

    expression
        A piece of code that produces a value, such as 40 + 2 or age >= 18. Expressions are the raw material statements are made of, and they can appear inside other expressions.

    compile
        To translate a program you wrote into the language the machine runs, checking it for mistakes along the way. The tool that does this is the compiler.

    run
        To have the machine carry out a compiled program, following its instructions in order.

    bug
        A mistake in a program: a wrong instruction, a missing one, or an instruction that does not mean what you thought. Bugs are normal. Every program has some, and finding them is a large part of the work.

    memory
        The machine's storage, a long row of numbered places holding values. Variables name particular places so you can find them again. The book refines this picture as it goes, but it is a true place to start.

0.12 How Not to Panic

Sooner or later the compiler will refuse your program with a message you do not understand. That is normal.

When the compiler complains:

Read the whole message. It usually names the problem and points to the line and exact spot.

Start at the first error. One mistake can trigger many complaints that vanish when it is fixed.

Compare with a working example, character by character. Most beginner errors are small: a missing semicolon, an unclosed brace, a misspelled name, a wrong type, a non-bool condition.

Change one thing at a time, then compile.

Keep your working programs; comparing against the last one that worked is often the fastest fix.

0.13 Exercises

Type each exercise yourself rather than copying and pasting.

    1. Hello, by name. Write a program that prints "Hello, I am learning Coral." Then change the text to greet a different name, compile, and run it again.

    2. Print a number. Make a variable holding your age, and print a sentence that includes it using a {} placeholder. Then change the age and run it again to confirm the output follows.

    3. Add two numbers. Write a program with two integer variables and print their sum. Then change one value and predict the new output before you run it.

    4. Decide something. Write a program that sets a variable to a number and prints "positive" if it is greater than zero, "zero" if it is exactly zero, and "negative" otherwise. Test it with all three kinds of value.

    5. Count to ten. Use a while loop to print the numbers from 1 to 10, one per line. Then modify it to print only the even numbers.

    6. Sum a range. Use a while loop to compute the sum of the numbers from 1 to 100 and print the result. If your answer is 5050, you have it right.

    7. Write a function. Write a function named double that takes one integer and returns twice that value. Call it from main on a few different numbers and print the results.

    8. Combine ideas. Write a function named max that takes two integers and returns the larger one, using an if/else to decide. Call it with several pairs of numbers, including a pair where both are equal, and print each result. (Decide for yourself what max should return when the two are equal, and make the code say so.)

If you can do all eight, you are ready for Chapter1.
