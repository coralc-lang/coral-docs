Live Examples: Graphics (from Scratch)

Pixels, Lines, and Light Without a Library

An image is a rectangle of numbers: an array of colored squares, meaningful only because of the order in which the numbers were chosen. A renderer needs a width, a height, a byte buffer, and rules for each byte.

This chapter builds those rules: a PPM framebuffer, a gradient, Bresenham lines, midpoint circles, barycentric triangles, affine transforms, a 5x7 bitmap font, ray-traced spheres, and the Mandelbrot set, all arithmetic on a `Vec<u8>`.

Two conventions matter. A pixel is a unit square centered at `(x + 0.5, y + 0.5)`, starting at byte `(y * width + x) * 3`, with y pointing down. Colors are floats in `[0, 1]`, blended there and converted to bytes only at the end, in one clamping, rounding place. Arithmetic in `u8` wraps: `200 + 100` becomes `44`, and the gradient tears.

Imports: `Vec` from `import(lib) std::vec { Vec };`, file functions from `import(lib) std::io::fs`, `formatInt` from `import(lib) std::fmt::fmt`, `String` from `import(lib) std::text::string`, and math helpers from `import(lib) std::math::math`. `println` is from `std::io::ios`; `Vec` and `str` are prelude names.

Section 43.1 defines the shared scaffolding once: `Image`, `Color`, `toByte`, and `writePPM`. Later sections reuse it, like the `Graph` of Chapter 31.

43.1 The Framebuffer and the PPM File

The problem. Represent a rectangular image in memory, set individual pixels, and write it to a file an ordinary viewer can open.

Picture this. The framebuffer is graph paper read in reading order: left to right, then top to bottom. "Put a red pixel at (3, 2)" means "replace the three bytes starting at index `(2 * width + 3) * 3`." Every drawing operation in this chapter is that sentence with different numbers.

PPM in binary `P6` form: magic `P6`, whitespace, decimal width, whitespace, height, whitespace, maximum channel value (`255`), exactly one whitespace byte, then raw RGB bytes. No compression, no header length, no library. The ASCII cousin `P3` writes the same header but spells every channel in decimal text, easier to read and far larger.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };
    import(lib) std::io::fs { fileOpen, fileClose, fileWrite, File, IoError };
    import(lib) std::fmt::fmt { formatInt };
    import(lib) std::text::string { String };

    struct Image {
        usize w;             // width in pixels
        usize h;             // height in pixels
        Vec<u8> px;          // w * h * 3 bytes, RGB, row-major, row 0 on top

        // Allocate a black w-by-h image: reserve up front, then zero-fill.
        static Image new(usize w, usize h) {
            Image img = Image {
                .w = w,
                .h = h,
                .px = Vec<u8>::withCap(w * h * 3)
            };
            for (usize i = 0; i < w * h * 3; i += 1) img.px.push(0);  // zero-fill
            return img;
        }

        // Store one RGB triple; out-of-bounds writes are dropped.
        void setPixel(usize x, usize y, u8 r, u8 g, u8 b) {
            if (x >= self.w || y >= self.h) return;   // drop out-of-bounds writes
            usize i = (y * self.w + x) * 3;           // first byte of pixel (x, y)
            self.px.set(i, r);
            self.px.set(i + 1, g);
            self.px.set(i + 2, b);
        }
    }

    // formatInt returns an owned String; copy its bytes into the output buffer.
    void appendInt(Vec<u8>* out, i64 value) {
        String s = formatInt(value, 10u, false);      // base 10, lowercase digits
        for (usize i = 0; i < s.len; i += 1) out->push(s.ptr[i]);
    }

    // Serialize the framebuffer to a binary P6 PPM file.
    void writePPM(str path, const Image* img) {
        // Assemble the P6 header and the raw bytes in a single output buffer.
        // Reserve the header slack plus every pixel byte.
        Vec<u8> out = Vec<u8>::withCap(img->px.count() + 32);
        out.push((u8)'P');                          // "P6": binary PPM magic
        out.push((u8)'6');
        out.push((u8)'\n');
        appendInt(&out, (i64)img->w);               // width in ASCII decimal
        out.push((u8)' ');
        appendInt(&out, (i64)img->h);               // height in ASCII decimal
        out.push((u8)'\n');
        appendInt(&out, 255);                       // max value: one byte per channel
        out.push((u8)'\n');                         // exactly one whitespace before the data

        // Pixel bytes: red, green, blue per pixel, left-to-right then top-to-bottom.
        for (usize i = 0; i < img->px.count(); i += 1) out.push(img->px.at(i));

        Result<File, IoError> fo = fileOpen(path, "w");  // "w" = create and truncate
        // Error path: report and return if the file cannot be opened.
        if (fo.isErr()) { println("could not open {}", path); return; }
        File f = fo.unwrap();

        usize off = 0;                              // fileWrite may write short; loop
        while (off < out.count()) {
            // Loop until every byte of the buffer has been written.
            Result<isize, IoError> wr = fileWrite(f, out.ptr() + off, out.count() - off);
            if (wr.isErr()) { println("write failed"); break; }
            // Guard against a stall: stop if the write makes no progress.
            isize put = wr.unwrap();
            if (put <= 0) break;                    // nothing moved: stop
            off += (usize)put;                      // advance past what got written
        }
        fileClose(f);
    }

    void main() {
        // A 160-by-100 image.
        Image img = Image::new(160, 100);
        // Two-axis ramp: red grows across, green grows down, blue is fixed.
        for (usize y = 0; y < img.h; y += 1) {
            for (usize x = 0; x < img.w; x += 1) {
                // Scale each channel to [0, 255], guarding a one-pixel axis.
                u8 r = img.w > 1 ? (u8)(x * 255 / (img.w - 1)) : 128;
                u8 g = img.h > 1 ? (u8)(y * 255 / (img.h - 1)) : 128;
                img.setPixel(x, y, r, g, 96);
            }
        }
        writePPM("/tmp/coral-framebuffer.ppm", &img);
        println("wrote /tmp/coral-framebuffer.ppm ({}x{})", img.w, img.h);
    }

`Image::new` allocates `w * h * 3` zero bytes. `setPixel` computes the flat index and silently drops writes outside the image, letting algorithms wander a pixel past the edge without crashing. `appendInt` copies `formatInt`'s `String` bytes out. `writePPM` writes the header then pixels in a loop, because one `write` may write fewer bytes than requested.

Cost and notes. Building the image is O(w × h) time and space. `writePPM` is another O(w × h) pass plus one linear write. Uncompressed, 1920×1080 is about six megabytes. `appendInt` allocates a `String` per integer, fine for four and wasteful in a loop.

Edge cases and variations. A reader consumes exactly one whitespace character after `255`; write `255\n\n` and the second newline becomes the first pixel's red byte, shifting every channel. The `w > 1` and `h > 1` guards avoid division by zero for a one-pixel axis. `setPixel` drops out-of-bounds writes rather than clipping, right for drawing but lossy for a naive blit. For `P3`, write each channel with `appendInt` separated by spaces and change the magic; the file becomes inspectable text, roughly five times larger. A `getPixel` method is left as an exercise. A 16-bit variant needs two-byte writes and `65535` in the header.

43.2 Gradients and Color Math

The problem. Fill an image with a smooth blend between two colors. The gradient establishes the color representation the rest of the chapter uses.

Picture this. A color is three numbers saying how much red, green, and blue to emit. Blend two colors by walking `t` from zero to one and mixing a little more of the second at each step. At `t = 0` you get the first color, at `t = 1` the second, and in between the weighted average `(1 - t) * a + t * b` per channel. That formula is linear interpolation, or `lerp`, the atom of shading.

The approach. Work in floating point on `[0, 1]` and convert to bytes only when writing a pixel. The conversion multiplies by 255, adds one half to round, and clamps to `[0, 255]`, so an overshooting value lands on black or white instead of wrapping. `Image` and `writePPM` are reused unchanged.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    // A color in linear [0, 1] per channel; bytes only at the very end.
    struct Color {
        f64 r;
        f64 g;
        f64 b;
    }

    // The single place floats become bytes: clamp, scale by 255, round.
    u8 toByte(f64 v) {
        // Below zero clamps to black.
        if (v <= 0.0) return 0;
        // One or above clamps to white.
        if (v >= 1.0) return 255;
        return (u8)(v * 255.0 + 0.5);           // +0.5 rounds to nearest
    }

    // Weighted blend per channel: t=0 gives a exactly, t=1 gives b.
    Color lerpColor(Color a, Color b, f64 t) {
        return Color {
            .r = a.r + (b.r - a.r) * t,
            .g = a.g + (b.g - a.g) * t,
            .b = a.b + (b.b - a.b) * t
        };
    }

    // One color per row, interpolated from top to bottom.
    void fillVerticalGradient(Image* img, Color top, Color bottom) {
        usize denom = img->h > 1 ? img->h - 1 : 1;  // guard a one-row image
        // Walk each row of the image.
        for (usize y = 0; y < img->h; y += 1) {
            f64 t = (f64)y / (f64)denom;            // 0 at the top row, 1 at the bottom
            Color c = lerpColor(top, bottom, t);
            u8 r = toByte(c.r);                     // convert once per row
            u8 g = toByte(c.g);
            u8 b = toByte(c.b);
            // Every pixel in this row shares the one color.
            for (usize x = 0; x < img->w; x += 1) img->setPixel(x, y, r, g, b);
        }
    }

    void main() {
        // A 160x100 canvas.
        Image img = Image::new(160, 100);
        // Blend from deep blue at the top to warm orange at the bottom.
        fillVerticalGradient(&img,
            Color { .r = 0.10, .g = 0.20, .b = 0.70 },
            Color { .r = 0.95, .g = 0.60, .b = 0.20 });
        writePPM("/tmp/coral-gradient.ppm", &img);
        println("wrote /tmp/coral-gradient.ppm");
    }

The inner `x` loop is the optimization that matters, and it is a property of the image: every pixel in a row gets the same color, so compute it once per row instead of once per pixel. `toByte` is the single point where a float color becomes a byte, and it clamps before casting, so a briefly negative or above-one `Color` cannot wrap. The formula `a + (b - a) * t` is algebraically `(1 - t) * a + t * b` but does one fewer multiply and behaves slightly better at the endpoints.

Cost and notes. The image is one pass, O(w × h), and per-row color work is constant. Floats are read and converted once per row, keeping expensive work out of the per-pixel path. The gradient is exact to floating-point rounding; the only quantization is the final byte conversion, which is why a gradient can show faint banding when the color changes by less than one byte across many pixels. That banding is inherent to eight-bit output, not the algorithm.

Edge cases and variations. A one-pixel-tall image divides by the sentinel `1`, maps its row to `t = 0`, and takes the top color. Components outside `[0, 1]` are clamped by `toByte`, so a deliberately bright color above one is safe. A red-to-blue `lerp` passes through muddy purple rather than bright magenta; blending through an intermediate color or in another space is an artistic choice. A 2D or radial gradient is a one-line change to how `t` is computed. Replacing `lerp` with smoothstep, `t * t * (3 - 2 * t)`, eases the ends and removes the seam where a gradient meets a flat region.

43.3 Lines: Bresenham's Algorithm

The problem. Draw a line between two integer pixel coordinates. A line is continuous and the grid is not, so choose the best discrete pixel for each step of the ideal line.

Picture this. Walk from one endpoint to the other one column at a time. The ideal line's y drifts by a fraction each step, and you must decide whether to stay on the row or step up. Bresenham's insight: you never need the fraction, only the sign of the accumulated error. When it crosses a threshold, take the diagonal step and subtract the threshold. Integer arithmetic, one decision per pixel, no floating point, no division.

The approach. The algorithm handles all eight octants using absolute deltas, tracking error and stepping x and y independently according to direction. `plotSafe` drops negative coordinates before casting to `usize`.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    // Guard the cast: negative coordinates are off-image.
    void plotSafe(Image* img, isize x, isize y, u8 r, u8 g, u8 b) {
        if (x < 0 || y < 0) return;                 // drop off-image coordinates
        img->setPixel((usize)x, (usize)y, r, g, b);
    }

    // Draw a line between two integer endpoints.
    void plotLine(Image* img, isize x0, isize y0, isize x1, isize y1, u8 r, u8 g, u8 b) {
        // Integer-only; the same loop covers all eight octants.
        isize dx = x1 > x0 ? x1 - x0 : x0 - x1;     // |x1 - x0|
        isize sx = x0 < x1 ? 1 : -1;                // x step direction
        isize dy = y1 > y0 ? y0 - y1 : y1 - y0;     // -|y1 - y0|
        isize sy = y0 < y1 ? 1 : -1;                // y step direction
        isize err = dx + dy;                        // err starts at dx - |dy|

        // Plot the current pixel, then step toward the endpoint.
        while (true) {
            plotSafe(img, x0, y0, r, g, b);
            if (x0 == x1 && y0 == y1) break;        // reached the far endpoint
            isize e2 = 2 * err;                     // double for the sign tests
            if (e2 >= dy) { err += dy; x0 += sx; }  // the x decision
            if (e2 <= dx) { err += dx; y0 += sy; }  // the y decision
        }
    }

    void main() {
        Image img = Image::new(200, 200);
        // Fan twelve lines out from a common origin, sweeping slope and color.
        // Twelve lines whose color tracks the loop index.
        for (usize i = 0; i <= 11; i += 1) {
            isize t = (isize)(i * 255 / 11);        // 0 .. 255 across the fan
            plotLine(&img, 10, 100, 190, t, (u8)(255 - (usize)t), (u8)t, 128);
        }
        writePPM("/tmp/coral-lines.ppm", &img);
        println("wrote /tmp/coral-lines.ppm");
    }

The two `if` statements are the entire algorithm. `dx` is the positive horizontal extent and `dy` the negative vertical extent, so `err` measures how far the line has strayed from the diagonal. Doubling it and comparing against `dy` and `dx` decides independently whether to advance x and y. A step can advance both, one, or (at an endpoint) neither, which lets one loop draw shallow, steep, or exactly diagonal lines without a special case per octant. The loop terminates because each iteration advances toward the endpoint or breaks at the final pixel.

Cost and notes. One iteration per pixel, a constant number of additions and comparisons, no floating point, division, or square root. A line spanning `n` pixels costs O(n), optimal since every pixel must be written. Integer arithmetic is exact as long as coordinates and deltas fit `isize`, so the line is identical on every machine, which is why the algorithm has survived since 1962.

Edge cases and variations. A zero-length line plots one pixel and breaks. Steep and shallow lines both work because the decisions are independent. Coordinates are `isize` and `plotSafe` guards the cast, so off-image pixels are dropped; a fully off-screen line draws nothing but still costs work proportional to its length, so a robust renderer would clip first. A thick line plots a small square or disk at each step, though that double-draws overlaps; the clean version offsets several parallel passes. Xiaolin Wu's algorithm antialiases by plotting two pixels per column with intensities proportional to distance from the ideal line, removing the staircase.

43.4 Circles: The Midpoint Algorithm

The problem. Draw the outline of a circle of integer center and radius with integer arithmetic and no trigonometry. A naive angular step leaves gaps or overdraws; exploit the circle's symmetry instead.

Picture this. A circle is eight identical arcs, one per octant, reflected and rotated into place. Plot only the arc from the top toward the forty-five-degree point, mirroring each pixel into seven other positions. Along that arc, as x increases by one, y decreases by zero or one; the midpoint algorithm decides by testing whether a point halfway between two candidate pixels lies inside or outside the true circle. That test is the sign of a small integer expression, so again only additions and comparisons.

The approach. Start at `(x, y) = (radius, 0)` with an error term that is exactly the midpoint test. Each step plots the eight symmetric points, advances y, and either keeps x or steps it in by one, updating the error. `plotPixel` guards the unsigned cast, and the eight-fold symmetry in `plot8` turns one arc into a circle.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    // Plot only if in-image; negative coordinates are dropped.
    void plotPixel(Image* img, isize x, isize y, u8 r, u8 g, u8 b) {
        if (x < 0 || y < 0) return;                 // guard the unsigned cast
        img->setPixel((usize)x, (usize)y, r, g, b);
    }

    // One arc point becomes eight: the four axis mirrors plus the diagonals.
    void plot8(Image* img, isize cx, isize cy, isize x, isize y, u8 r, u8 g, u8 b) {
        plotPixel(img, cx + x, cy + y, r, g, b);
        plotPixel(img, cx - x, cy + y, r, g, b);
        plotPixel(img, cx + x, cy - y, r, g, b);
        plotPixel(img, cx - x, cy - y, r, g, b);
        plotPixel(img, cx + y, cy + x, r, g, b);    // swap x and y for the reflections
        plotPixel(img, cx - y, cy + x, r, g, b);
        plotPixel(img, cx + y, cy - x, r, g, b);
        plotPixel(img, cx - y, cy - x, r, g, b);
    }

    // Walk the first octant; symmetry fills the rest.
    void drawCircle(Image* img, isize cx, isize cy, isize radius, u8 r, u8 g, u8 b) {
        if (radius < 0) return;
        isize x = radius;                           // start at (radius, 0)
        isize y = 0;
        isize err = 0;                              // midpoint decision variable
        // Stop at the 45-degree point where x drops below y.
        while (x >= y) {                            // walk the first octant
            plot8(img, cx, cy, x, y, r, g, b);
            // Advance y every step.
            y += 1;
            if (err <= 0) err += 2 * y + 1;         // midpoint is still inside
            if (err > 0) { x -= 1; err -= 2 * x + 1; }  // step x inward
        }
    }

    void main() {
        Image img = Image::new(200, 200);
        // Six concentric circles of growing radius and shifting color.
        for (usize i = 1; i <= 6; i += 1) {
            isize rad = (isize)(i * 15);
            drawCircle(&img, 100, 100, rad, (u8)(i * 40), (u8)(255 - i * 30), 160);
        }
        writePPM("/tmp/coral-circles.ppm", &img);
        println("wrote /tmp/coral-circles.ppm");
    }

`err` is the midpoint decision variable, kept as an integer because the tests need only its sign. Starting at `(radius, 0)`, the loop walks the first octant while `x >= y` and stops at forty-five degrees. The two `if`s can both fire: when `err` is exactly zero the first makes it positive and the second consumes that, the intended transition. `plot8` writes the point and seven mirrors; the three lines swapping `x` and `y` reflect across the diagonal, filling the other four arcs. The `radius < 0` guard cheaply refuses a meaningless request.

Cost and notes. The loop runs about `radius / √2` times, so O(radius), with a handful of integer operations per iteration and no large multiplications, `sqrt`, `sin`, or `cos`. The full circle costs eight pixel writes per iteration, free work compared to evaluating the circle equation per pixel. That is why the midpoint method is standard for outlined and filled circles where a math library is unavailable or too slow.

Edge cases and variations. Radius zero plots the center pixel eight times, harmlessly. With an even radius the arc endpoints can plot a pixel twice, once in this octant and once as a mirror; visually irrelevant. `plotPixel` clips circles running off the image. A filled version changes `plot8` to draw a horizontal span from `cx - x` to `cx + x` (or `y`, whichever is wider) per scanline, turning the outline into a disk with the same loop. An antialiased circle keeps the fractional midpoint test as intensity and blends the two candidates. The same skeleton with a different midpoint test draws ellipses, though both axes must then be tracked separately.

43.5 Triangles: Barycentric Rasterization

The problem. Fill a triangle whose three vertices are floating-point coordinates, interpolating color across the surface. Triangles are the primitive of every real renderer: any shape breaks into them, and three points are always coplanar.

Picture this. Every point inside a triangle is a weighted average of its corners: `P = w0 * A + w1 * B + w2 * C`, with non-negative weights summing to one. Near a corner its weight is near one and the others near zero. Compute the weight triplet for a pixel to test whether it is inside (all weights in range) and blend the corner colors with the same weights. These are barycentric coordinates, and they fall out of the areas of the three sub-triangles the point forms with the edges.

The approach. The weight of A is the area of triangle PBC divided by the area of ABC, likewise for the others. Signed area is an edge function, a cross product, so only one normalization division is needed. Scan integer pixels in the triangle's bounding box; evaluate the three weights at each pixel center and keep the pixel when all are non-negative. Dividing every edge function by the signed area makes the test winding-independent.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };
    import(lib) std::math::math { minF64, maxF64, floor, ceil };

    // Twice the signed area of triangle (a, b, p): the barycentric edge test.
    // Half the cross product of (b - a) and (p - a).
    f64 edgeFn(f64 ax, f64 ay, f64 bx, f64 by, f64 px, f64 py) {
        return (px - ax) * (by - ay) - (py - ay) * (bx - ax);
    }

    void rasterTriangle(Image* img,
                        f64 x0, f64 y0, f64 x1, f64 y1, f64 x2, f64 y2,
                        Color c0, Color c1, Color c2) {
        // Signed area of the whole triangle.
        f64 area = edgeFn(x0, y0, x1, y1, x2, y2);
        if (area == 0.0) return;                    // degenerate triangle

        // Bounding box of the three vertices, in floating point.
        f64 minX = minF64(x0, minF64(x1, x2));
        f64 maxX = maxF64(x0, maxF64(x1, x2));
        f64 minY = minF64(y0, minF64(y1, y2));
        f64 maxY = maxF64(y0, maxF64(y1, y2));

        // Clip the box out to whole pixel rows and columns.
        // Round the box outward to integer pixel bounds.
        isize px0 = (isize)floor(minX);
        isize px1 = (isize)ceil(maxX);
        isize py0 = (isize)floor(minY);
        isize py1 = (isize)ceil(maxY);

        // Scan every candidate pixel inside the bounding box.
        for (isize py = py0; py <= py1; py += 1) {
            for (isize px = px0; px <= px1; px += 1) {
                f64 cx = (f64)px + 0.5;             // test the pixel center
                f64 cy = (f64)py + 0.5;
                // Barycentric weight of each corner; divided by area they sum to one.
                // Weights for each corner at the pixel center.
                f64 w0 = edgeFn(x1, y1, x2, y2, cx, cy) / area;
                f64 w1 = edgeFn(x2, y2, x0, y0, cx, cy) / area;
                f64 w2 = edgeFn(x0, y0, x1, y1, cx, cy) / area;
                // Inside when all three weights are non-negative.
                if (w0 >= 0.0 && w1 >= 0.0 && w2 >= 0.0) {
                    // Blend the corner colors with the same weights.
                    Color c = Color {
                        .r = w0 * c0.r + w1 * c1.r + w2 * c2.r,
                        .g = w0 * c0.g + w1 * c1.g + w2 * c2.g,
                        .b = w0 * c0.b + w1 * c1.b + w2 * c2.b
                    };
                    // Drop pixels that fall outside the image before writing.
                    if (px >= 0 && py >= 0)
                        img->setPixel((usize)px, (usize)py, toByte(c.r), toByte(c.g), toByte(c.b));
                }
            }
        }
    }

    void main() {
        Image img = Image::new(200, 200);
        // One RGB triangle: each corner carries its own color.
        rasterTriangle(&img, 100.0, 20.0, 180.0, 170.0, 20.0, 170.0,
            Color { .r = 1.0, .g = 0.1, .b = 0.1 },
            Color { .r = 0.1, .g = 1.0, .b = 0.2 },
            Color { .r = 0.1, .g = 0.2, .b = 1.0 });
        writePPM("/tmp/coral-triangle.ppm", &img);
        println("wrote /tmp/coral-triangle.ppm");
    }

`edgeFn(a, b, p)` returns twice the signed area of triangle `a, b, p`, positive on one side of the directed edge and negative on the other. `area` is the same function on the triangle's own vertices, twice the whole signed area. Dividing each sub-area by the whole normalizes the weights to sum to one and flips every sign to match, so winding order does not matter. The bounding box limits the scan to the rectangle the triangle can touch, and testing the pixel center `(px + 0.5, py + 0.5)` keeps coverage consistent with the pixel-as-unit-square convention.

Cost and notes. The scan visits every pixel in the bounding box, so O(bounding-box area), with three edge evaluations, three divisions, and, inside, three `lerp`s and a `toByte` triple per pixel. The three divisions are wasteful; a production rasterizer computes edge functions incrementally, adding a constant per step, and defers the single division by `area`, or avoids it by comparing unnormalized weights. The bounding box wastes work on long, thin triangles, where a scanline approach tracking each edge's x-range visits far fewer pixels. For a textbook the brute-force scan is clearer and completely correct.

Edge cases and variations. A degenerate triangle has zero area and returns before dividing by zero, catching collinear points or coincident vertices. Pixels exactly on an edge can go to either neighbor because `>= 0.0` is inclusive on all three edges; two triangles sharing an edge may both claim them, or with a strict test neither, the classic cracks-and-overdraw problem. Production pipelines use consistent tie-breaking, such as `w >= 0` on two edges and `w > 0` on the third. Signed-area normalization hides winding order, but a culling rasterizer must preserve the sign. Perspective-correct texture mapping divides each weight by a per-vertex depth. A scanline fill computes two edge crossings per row and fills between them, avoiding bounding-box waste.

43.6 2D Transforms: A Point Type and an Affine Matrix

The problem. Move, rotate, and scale a shape by combining those operations into one object, so transforming a point is one matrix multiply rather than a chain of calls.

Picture this. Translation is a shift, rotation a spin about the origin, scaling a stretch along the axes. Each is a two-by-three table of numbers turning an input point into an output point. Compose transforms by multiplying their tables, and the result does the work of both. The order is fixed the moment you multiply. This chapter fixes the convention: a point is a column, and the matrix multiplies it on the left.

The approach. Represent an affine transform as `a b c / d e f`, meaning `x' = a*x + b*y + c` and `y' = d*x + e*y + f`. The last row of the full three-by-three matrix is always `0 0 1`, which lets translation fit inside. `mul` returns `self` times `other`, so `self` is applied last and `other` first; `translate.mul(rotate).mul(scale)` therefore scales, rotates, then translates, the order almost every layout wants. Points are `P2`; the polygon outline reuses `plotLine` from 42.3.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };
    import(lib) std::math::math { sin, cos };

    // A point in the plane.
    struct P2 {
        f64 x;
        f64 y;
    }

    struct Affine {
        f64 a; f64 b; f64 c;      // x' = a*x + b*y + c
        f64 d; f64 e; f64 f;      // y' = d*x + e*y + f

        // The do-nothing transform.
        static Affine identity() {
            return Affine { .a = 1.0, .b = 0.0, .c = 0.0,
                            .d = 0.0, .e = 1.0, .f = 0.0 };
        }
        // Shift x by tx and y by ty.
        static Affine translate(f64 tx, f64 ty) {
            return Affine { .a = 1.0, .b = 0.0, .c = tx,
                            .d = 0.0, .e = 1.0, .f = ty };
        }
        // Stretch the axes independently.
        static Affine scale(f64 sx, f64 sy) {
            return Affine { .a = sx,  .b = 0.0, .c = 0.0,
                            .d = 0.0, .e = sy,  .f = 0.0 };
        }
        // Rotation about the origin, in radians.
        static Affine rotate(f64 angle) {
            return Affine { .a = cos(angle), .b = -sin(angle), .c = 0.0,
                            .d = sin(angle), .e =  cos(angle), .f = 0.0 };
        }
        // Return self composed after other.
        Affine mul(Affine other) {                  // self composed after other
            // The 3x3 matrix product with the constant last row folded away.
            return Affine {
                .a = self.a * other.a + self.b * other.d,
                .b = self.a * other.b + self.b * other.e,
                .c = self.a * other.c + self.b * other.f + self.c,
                .d = self.d * other.a + self.e * other.d,
                .e = self.d * other.b + self.e * other.e,
                .f = self.d * other.c + self.e * other.f + self.f
            };
        }
        // Apply the transform to a point.
        P2 apply(P2 p) {                            // point through the transform
            return P2 {
                .x = self.a * p.x + self.b * p.y + self.c,
                .y = self.d * p.x + self.e * p.y + self.f
            };
        }
    }

    // Outline a closed polygon by connecting consecutive vertices.
    void drawPolygon(Image* img, const Vec<P2>* pts, u8 r, u8 g, u8 b) {
        usize n = pts->count();
        // Need at least two points to draw an edge.
        if (n < 2) return;                          // nothing to connect
        for (usize i = 0; i < n; i += 1) {
            P2 p = pts->at(i);
            P2 q = pts->at((i + 1) % n);            // wrap the last vertex to the first
            plotLine(img, (isize)p.x, (isize)p.y, (isize)q.x, (isize)q.y, r, g, b);
        }
    }

    void main() {
        Image img = Image::new(200, 200);

        Vec<P2> square = Vec<P2>::new();            // a unit square centered on the origin
        square.push(P2 { .x = -1.0, .y = -1.0 });
        square.push(P2 { .x =  1.0, .y = -1.0 });
        square.push(P2 { .x =  1.0, .y =  1.0 });
        square.push(P2 { .x = -1.0, .y =  1.0 });

        // Compose scale, then rotate, then translate (read right to left).
        Affine m = Affine::translate(100.0, 100.0)
                            .mul(Affine::rotate(0.5))
                            .mul(Affine::scale(60.0, 40.0));

        // Map each corner through the composed matrix, then outline it.
        Vec<P2> out = Vec<P2>::new();
        // Push each transformed corner into a new list.
        for (usize i = 0; i < square.count(); i += 1) out.push(m.apply(square.at(i)));
        drawPolygon(&img, &out, 255, 200, 40);
        writePPM("/tmp/coral-transform.ppm", &img);
        println("wrote /tmp/coral-transform.ppm");
    }

`mul` is just the three-by-three product with the constant last row folded away: the extra `+ self.c` and `+ self.f` are the left matrix's translation terms. Read `m` right to left: the unit square is stretched by `scale`, spun by `rotate`, then shifted by `translate`. In `drawPolygon`, `(i + 1) % n` closes the outline and the `n < 2` guard refuses a polygon with nothing to connect.

Cost and notes. Composing two transforms is a constant number of multiplies and adds, and a chain collapses to one matrix before any point is touched. Transforming `n` points is O(n), one matrix-vector multiply each. This is why graphics systems insist on matrices: a million vertices under fifty transforms pays for fifty compositions once, then one multiply per vertex. `sin` and `cos` are evaluated once when the rotation matrix is built.

Edge cases and variations. A zero scale collapses the shape to a line or point and makes the transform non-invertible; drawing shows the collapse, but texture mapping or hit-testing must detect it. Rotation is about the origin, so rotating an off-center shape also swings it; "rotate about a point" is `translate(center).mul(rotate).mul(translate(-center))`. `drawPolygon` always closes, drawing an outline rather than an open path. A full three-by-three matrix can also apply shear, the same six numbers plus two. A 2D camera stores the inverse transform to turn screen coordinates back into world coordinates for picking. Keeping translation separate from the linear part, as `std::math::matrix`'s `Mat2` and `Mat4` do, is preferable when one rotation applies to many objects at different positions.

43.7 Text: A 5x7 Bitmap Font

The problem. Draw readable text into the image. With no font engine, letters must come from a table of pixels built by hand.

Picture this. Before scalable outlines, every computer had a bitmap font: each character was a small grid of dots, and "draw the letter A" meant "copy that grid into the framebuffer." A five-wide, seven-tall grid makes every capital and digit legible, and seven bytes per glyph, one per row using the low five bits, hold the alphabet in a couple hundred bytes. Scaled text replaces each lit dot with a `scale`-by-`scale` block.

The approach. Build the font once as a `Vec<u8>`, seven bytes per glyph, in a fixed order: space, A through Z, then digits. Each row is a five-bit binary literal, so the table reads like the letters. A lookup maps a character to a glyph index; `drawText` walks the string and, for each lit bit, fills a small square, advancing the pen by six times the scale (five columns plus a one-column gap).

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    // Append one glyph as seven row bytes, top row first, low five bits used.
    void glyph(Vec<u8>* font, u8 r0, u8 r1, u8 r2, u8 r3, u8 r4, u8 r5, u8 r6) {
        font->push(r0); font->push(r1); font->push(r2); font->push(r3);
        font->push(r4); font->push(r5); font->push(r6);
    }

    // Build the bitmap font table.
    Vec<u8> buildFont() {
        Vec<u8> f = Vec<u8>::new();
        // Order: space, then A..Z, then 0..9; the space glyph is seven zero rows.
        glyph(&f, 0b00000, 0b00000, 0b00000, 0b00000, 0b00000, 0b00000, 0b00000); // space
        glyph(&f, 0b01110, 0b10001, 0b10001, 0b11111, 0b10001, 0b10001, 0b10001); // A
        glyph(&f, 0b11110, 0b10001, 0b10001, 0b11110, 0b10001, 0b10001, 0b11110); // B
        glyph(&f, 0b01110, 0b10001, 0b10000, 0b10000, 0b10000, 0b10001, 0b01110); // C
        glyph(&f, 0b11110, 0b10001, 0b10001, 0b10001, 0b10001, 0b10001, 0b11110); // D
        glyph(&f, 0b11111, 0b10000, 0b10000, 0b11110, 0b10000, 0b10000, 0b11111); // E
        glyph(&f, 0b11111, 0b10000, 0b10000, 0b11110, 0b10000, 0b10000, 0b10000); // F
        glyph(&f, 0b01110, 0b10001, 0b10000, 0b10111, 0b10001, 0b10001, 0b01111); // G
        glyph(&f, 0b10001, 0b10001, 0b10001, 0b11111, 0b10001, 0b10001, 0b10001); // H
        glyph(&f, 0b11111, 0b00100, 0b00100, 0b00100, 0b00100, 0b00100, 0b11111); // I
        glyph(&f, 0b00111, 0b00010, 0b00010, 0b00010, 0b00010, 0b10010, 0b01100); // J
        glyph(&f, 0b10001, 0b10010, 0b10100, 0b11000, 0b10100, 0b10010, 0b10001); // K
        glyph(&f, 0b10000, 0b10000, 0b10000, 0b10000, 0b10000, 0b10000, 0b11111); // L
        glyph(&f, 0b10001, 0b11011, 0b10101, 0b10101, 0b10001, 0b10001, 0b10001); // M
        glyph(&f, 0b10001, 0b11001, 0b10101, 0b10011, 0b10001, 0b10001, 0b10001); // N
        glyph(&f, 0b01110, 0b10001, 0b10001, 0b10001, 0b10001, 0b10001, 0b01110); // O
        glyph(&f, 0b11110, 0b10001, 0b10001, 0b11110, 0b10000, 0b10000, 0b10000); // P
        glyph(&f, 0b01110, 0b10001, 0b10001, 0b10001, 0b10101, 0b10010, 0b01101); // Q
        glyph(&f, 0b11110, 0b10001, 0b10001, 0b11110, 0b10100, 0b10010, 0b10001); // R
        glyph(&f, 0b01111, 0b10000, 0b10000, 0b01110, 0b00001, 0b00001, 0b11110); // S
        glyph(&f, 0b11111, 0b00100, 0b00100, 0b00100, 0b00100, 0b00100, 0b00100); // T
        glyph(&f, 0b10001, 0b10001, 0b10001, 0b10001, 0b10001, 0b10001, 0b01110); // U
        glyph(&f, 0b10001, 0b10001, 0b10001, 0b10001, 0b10001, 0b01010, 0b00100); // V
        glyph(&f, 0b10001, 0b10001, 0b10001, 0b10101, 0b10101, 0b11011, 0b10001); // W
        glyph(&f, 0b10001, 0b10001, 0b01010, 0b00100, 0b01010, 0b10001, 0b10001); // X
        glyph(&f, 0b10001, 0b10001, 0b01010, 0b00100, 0b00100, 0b00100, 0b00100); // Y
        glyph(&f, 0b11111, 0b00001, 0b00010, 0b00100, 0b01000, 0b10000, 0b11111); // Z
        glyph(&f, 0b01110, 0b10001, 0b10011, 0b10101, 0b11001, 0b10001, 0b01110); // 0
        glyph(&f, 0b00100, 0b01100, 0b00100, 0b00100, 0b00100, 0b00100, 0b01110); // 1
        glyph(&f, 0b01110, 0b10001, 0b00001, 0b00010, 0b00100, 0b01000, 0b11111); // 2
        glyph(&f, 0b11111, 0b00010, 0b00100, 0b00010, 0b00001, 0b10001, 0b01110); // 3
        glyph(&f, 0b00010, 0b00110, 0b01010, 0b10010, 0b11111, 0b00010, 0b00010); // 4
        glyph(&f, 0b11111, 0b10000, 0b11110, 0b00001, 0b00001, 0b10001, 0b01110); // 5
        glyph(&f, 0b00110, 0b01000, 0b10000, 0b11110, 0b10001, 0b10001, 0b01110); // 6
        glyph(&f, 0b11111, 0b00001, 0b00010, 0b00100, 0b01000, 0b01000, 0b01000); // 7
        glyph(&f, 0b01110, 0b10001, 0b10001, 0b01110, 0b10001, 0b10001, 0b01110); // 8
        glyph(&f, 0b01110, 0b10001, 0b10001, 0b01111, 0b00001, 0b00010, 0b01100); // 9
        return f;

    // Map an ASCII byte to its slot in the font table.
    isize glyphIndex(u8 c) {
        if (c == (u8)' ') return 0;
        // Capital letters follow the space glyph.
        if (c >= (u8)'A' && c <= (u8)'Z') return 1 + (isize)(c - (u8)'A');
        // Digits follow the capitals.
        if (c >= (u8)'0' && c <= (u8)'9') return 27 + (isize)(c - (u8)'0');
        return -1;                                          // unknown: skipped
    }

    // Render a string at (x0, y0) with the given scale.
    void drawText(Image* img, const Vec<u8>* font, isize x0, isize y0,
                  str text, isize scale, u8 r, u8 g, u8 b) {
        // Walk the string one character at a time.
        for (usize i = 0; i < text.len; i += 1) {
            isize gi = glyphIndex(text.at(i));      // table slot for this character
            if (gi < 0) continue;                   // skip anything not in the table
            // Seven rows per glyph, top to bottom.
            for (usize row = 0; row < 7; row += 1) {
                u8 bits = font->at((usize)gi * 7 + row);  // this row's five bits
                // Five columns per glyph, left to right.
                for (usize col = 0; col < 5; col += 1) {
                    u8 on = (u8)((bits >> (u32)(4 - col)) & 1u);  // leftmost is the high bit
                    if (on == 0) continue;
                    // A lit bit becomes a scale-by-scale block of pixels.
                    for (isize dy = 0; dy < scale; dy += 1) {
                        for (isize dx = 0; dx < scale; dx += 1) {
                            // Pen advances six columns (five plus a gap) per character.
                            isize px = x0 + (isize)col * scale + dx + (isize)i * (6 * scale);
                            isize py = y0 + (isize)row * scale + dy;
                            if (px >= 0 && py >= 0)
                                img->setPixel((usize)px, (usize)py, r, g, b);
                        }
                    }
                }
            }
        }
    }

    void main() {
        Image img = Image::new(200, 90);
        Vec<u8> font = buildFont();

        // Draw the title large and the subtitle small.
        drawText(&img, &font,  6,  6, "CORAL", 4, 255, 220, 80);
        drawText(&img, &font,  6, 48, "GRAPHICS 42", 2, 120, 220, 255);
        writePPM("/tmp/coral-text.ppm", &img);
        println("wrote /tmp/coral-text.ppm");
    }

The font table is the whole idea. Each glyph is seven rows, top to bottom, each row five bits, left to right, so `0b01110` for the top of an `A` is its cap. `glyphIndex` converts ASCII to the fixed glyph order with two range checks. `drawText` extracts each bit with a shift and mask, testing the high bit first for the leftmost column because `4 - col` counts down from four. The pen advances by `6 * scale` per character: five columns plus one of spacing. Unknown characters are skipped, leaving a blank rather than throwing.

Cost and notes. Building the font costs a few hundred pushes once, so it is hoisted into `main`. Drawing `m` characters at scale `s` writes up to `m * 35 * s²` pixels, so cost grows with the square of the scale. Bit extraction is a shift and an AND per pixel, cheaper than any lookup. The whole font is a little over 250 bytes, why bitmap fonts were the only ones that fit in early machines.

Edge cases and variations. Lowercase, punctuation, and accented characters are absent; `glyphIndex` returns `-1`, so they vanish rather than drawing garbage. Adding a glyph is one more `glyph` call and one `glyphIndex` line. Text is not wrapped or clipped at the right edge: characters past the image are dropped by `setPixel`, so a long string is silently truncated. Scale zero draws nothing; a robust version clamps negative scale to one. A taller or wider font, or one with a descent for g and p, means more rows and a per-glyph vertical offset. Packing each glyph as five columns of seven bits makes vertical scrolling cheaper. A vector font, with glyphs as line and curve segments, stays sharp at any size at the cost of much more code.

43.8 A Ray Tracer for Spheres

The problem. Produce a shaded image of three-dimensional objects by simulating light. A ray tracer answers one question per pixel: shooting a ray from the camera through this pixel, what does it hit, and how is that surface lit? For spheres the answer is closed-form.

Picture this. The camera is a point and the image a window in front of it; each pixel corresponds to one direction through that window, so one ray leaves the eye per pixel. To find where a ray meets a sphere, substitute the ray's parametric equation into the sphere's implicit equation and solve the quadratic; the smallest positive root is the nearest hit. The outward normal is the direction from the sphere's center to the hit point, and one light makes brightness proportional to how directly the surface faces it. A flat ambient term keeps nothing pure black, and the picture already reads as solid 3D forms.

The approach. Build a ray direction per pixel from a pinhole camera looking down the negative z-axis. Test every sphere and keep the nearest positive hit. If there is one, shade it with a Lambert term against one directional light; otherwise fill the pixel with a vertical sky gradient. Colors are clamped and written by `toByte` from 42.2. `Vec3` carries directions and points.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };
    import(lib) std::math::math { sqrt };

    struct Vec3 {
        f64 x; f64 y; f64 z;

        static Vec3 new(f64 x, f64 y, f64 z) {
            return Vec3 { .x = x, .y = y, .z = z };
        }
        Vec3 add(Vec3 o) { return Vec3 { .x = self.x + o.x, .y = self.y + o.y, .z = self.z + o.z }; }
        Vec3 sub(Vec3 o) { return Vec3 { .x = self.x - o.x, .y = self.y - o.y, .z = self.z - o.z }; }
        Vec3 scale(f64 s) { return Vec3 { .x = self.x * s, .y = self.y * s, .z = self.z * s }; }
        f64  dot(Vec3 o) { return self.x * o.x + self.y * o.y + self.z * o.z; }
        // Return a unit-length copy, or the zero vector if this one is zero.
        Vec3 normalize() {
            // Length is the dot of the vector with itself.
            f64 len = sqrt(self.dot(*self));
            // Avoid dividing by zero for the zero vector.
            if (len == 0.0) return Vec3 { .x = 0.0, .y = 0.0, .z = 0.0 };
            return self.scale(1.0 / len);
        }
    }

    struct Sphere {
        Vec3 center;
        f64 radius;
        Color color;
    }

    // Nearest positive hit of ray `dir` (unit length) from origin, or -1.
    f64 hitSphere(Sphere s, Vec3 origin, Vec3 dir) {
        Vec3 oc = origin.sub(s.center);             // origin relative to the center
        f64 b = oc.dot(dir);                        // half the linear coefficient
        // Constant term: offset length squared minus radius squared.
        f64 c = oc.dot(oc) - s.radius * s.radius;
        f64 disc = b * b - c;                       // reduced discriminant, a = 1
        if (disc < 0.0) return -1.0;                // ray misses the sphere
        f64 root = sqrt(disc);
        f64 t = -b - root;                          // near intersection
        if (t > 0.001) return t;
        t = -b + root;                              // far root: eye inside the sphere
        if (t > 0.001) return t;
        return -1.0;                                // both hits behind the eye
    }

    // One ray per pixel from a pinhole camera.
    void render(Image* img, const Vec<Sphere>* spheres) {
        // Aspect ratio keeps pixels square in view space.
        f64 aspect = (f64)img->w / (f64)img->h;
        Vec3 eye = Vec3::new(0.0, 0.0, 0.0);        // pinhole at the origin
        Vec3 light = Vec3::new(0.5, 0.8, 0.3).normalize();  // one directional light

        for (usize y = 0; y < img->h; y += 1) {
            for (usize x = 0; x < img->w; x += 1) {
                // Map the pixel center to the view plane in [-aspect, aspect] x [-1, 1].
                // Horizontal and vertical view-plane coordinates.
                f64 u = (2.0 * ((f64)x + 0.5) / (f64)img->w - 1.0) * aspect;
                f64 v = 1.0 - 2.0 * ((f64)y + 0.5) / (f64)img->h;
                // The ray points into the scene along -z.
                Vec3 ray = Vec3::new(u, v, -1.0).normalize();

                // Nearest-hit search across all spheres.
                f64 bestT = 1e30;
                isize hit = -1;
                for (usize i = 0; i < spheres->count(); i += 1) {
                    f64 t = hitSphere(spheres->at(i), eye, ray);
                    if (t > 0.0 && t < bestT) { bestT = t; hit = (isize)i; }  // nearest so far
                }

                Color c;
                // If a sphere was hit, shade it; otherwise draw sky.
                if (hit >= 0) {
                    // Shade the nearest surface: Lambert against the light plus ambient.
                    Sphere s = spheres->at((usize)hit);
                    // Hit point along the ray.
                    Vec3 p = ray.scale(bestT);
                    // Outward normal is the hit point minus the center.
                    Vec3 n = p.sub(s.center).normalize();
                    // Lambert: how squarely the surface faces the light.
                    f64 diff = n.dot(light);
                    if (diff < 0.0) diff = 0.0;                 // clamp the Lambert term
                    f64 k = 0.1 + 0.9 * diff;        // ambient plus Lambert
                    c = Color {
                        .r = s.color.r * k,
                        .g = s.color.g * k,
                        .b = s.color.b * k
                    };
                } else {
                    f64 t = 0.5 * (ray.y + 1.0);     // sky gradient by height
                    c = Color { .r = 1.0 - 0.5 * t, .g = 1.0 - 0.3 * t, .b = 1.0 };
                }
                img->setPixel(x, y, toByte(c.r), toByte(c.g), toByte(c.b));
            }
        }
    }

    void main() {
        Image img = Image::new(200, 150);
        Vec<Sphere> spheres = Vec<Sphere>::new();
        spheres.push(Sphere {
            .center = Vec3::new(-0.8, 0.0, -3.0), .radius = 0.7,
            .color = Color { .r = 1.0, .g = 0.2, .b = 0.2 }
        });
        spheres.push(Sphere {
            .center = Vec3::new(0.7, 0.2, -3.5), .radius = 0.9,
            .color = Color { .r = 0.2, .g = 1.0, .b = 0.3 }
        });
        render(&img, &spheres);
        writePPM("/tmp/coral-spheres.ppm", &img);
        println("wrote /tmp/coral-spheres.ppm");
    }

`hitSphere` is the quadratic in disguise. With a normalized direction the leading coefficient is one, so `b² - 4ac` shrinks to `b² - c`, where `b` is the dot of offset and direction and `c` is offset length squared minus radius squared. A negative discriminant means a miss, returning `-1.0`. Otherwise the roots are `-b ± √disc`; the code takes the near root, and only if it is behind the eye considers the far root, handling a camera inside a sphere. The `0.001` bias stops a ray starting on a surface from re-hitting it. `render` finds the nearest sphere and shades it: normal is hit point minus center, the Lambert term is the clamped dot with light, and a miss uses the sky gradient.

Cost and notes. O(width × height × spheres): one quadratic solve per sphere per pixel, a few dots, one `sqrt`, no allocation. The per-hit `sqrt` dominates and can be avoided by comparing squared distances when only the nearest matters. Shadows, reflections, and multiple lights are small additions to the same per-pixel loop.

Edge cases and variations. A miss, or a hit behind the camera, falls through to the sky. Shading is flat Lambert with no shadows, the most visible simplification. `normalize` returns zero for a zero input, preventing division by zero but giving no shading; these directions are never zero. Add a second light and sum the terms. A shadow ray toward the light, one more `hitSphere` call, darkens blocked pixels. Reflection traces a reflected ray and mixes its color, the recursive step that makes it a tracer. Environment maps and distance-function surfaces extend the same loop. `std::math::vector` provides a `Vec3`.

43.9 The Mandelbrot Set

The problem. Render the Mandelbrot set, defined by a rule simple enough to fit in five lines and rich enough that no one has finished describing it.

Picture this. Feed each point of the complex plane to `z ← z² + c`, starting from `z = 0`. The point belongs to the set if `z` stays bounded forever and escapes if it grows past any limit. A complex number with magnitude greater than two can never be pulled back, so the escape test is `|z| > 2`, and squaring avoids the square root: test `zr² + zi² > 4`. Escaping points are colored by how many iterations they survived; points that never escape stay black. Zooming reveals an infinitely detailed boundary.

The approach. Map pixel coordinates onto a rectangle of the complex plane, run the iteration with a fixed cap, and choose a color from the escape count. The cap turns "forever" into "up to `maxIter`"; points reaching the cap are treated as inside. A simple palette maps the escape fraction through a curve to a color; the curve is art, but any monotone map produces a recognizable image.

The implementation.

    import(lib) std::vec { Vec };
    import(lib) std::io::ios { println };

    // Color by escape count; points that never escape stay black.
    Color mandelbrotColor(i32 n, i32 maxIter) {
        if (n >= maxIter) return Color { .r = 0.0, .g = 0.0, .b = 0.0 };  // never escaped
        f64 t = (f64)n / (f64)maxIter;              // 0 = fastest escape, 1 = last ring
        return Color {
            .r = t,
            .g = t * t,
            .b = 0.5 + 0.5 * (1.0 - t)
        };
    }

    // Map pixels to a rectangle of the complex plane.
    void renderMandelbrot(Image* img, i32 maxIter) {
        // Rectangular window of the complex plane to render.
        // Real-axis extent of the window.
        f64 reMin = -2.5;
        f64 reMax = 1.0;
        // Imaginary-axis extent of the window.
        f64 imMin = -1.2;
        f64 imMax = 1.2;
        f64 reSpan = reMax - reMin;
        f64 imSpan = imMax - imMin;
        usize wd = img->w > 1 ? img->w - 1 : 1;     // guard the one-pixel case
        usize hd = img->h > 1 ? img->h - 1 : 1;

        // Walk every pixel in the image.
        for (usize y = 0; y < img->h; y += 1) {
            // im is the imaginary part of c for this row.
            f64 im = imMin + imSpan * (f64)y / (f64)hd;
            for (usize x = 0; x < img->w; x += 1) {
                f64 re = reMin + reSpan * (f64)x / (f64)wd;  // map the pixel to c = re + im*i
                f64 zr = 0.0;                       // z starts at zero
                f64 zi = 0.0;
                i32 n = 0;
                // Iterate z <- z*z + c until |z|^2 > 4 or the cap is reached.
                // Loop until the point escapes or maxIter is reached.
                while (n < maxIter && zr * zr + zi * zi <= 4.0) {
                    f64 next = zr * zr - zi * zi + re;   // real part of z^2 + c
                    zi = 2.0 * zr * zi + im;             // imaginary part
                    zr = next;
                    n += 1;                              // count survived iterations
                }
                // Turn the escape count into a color.
                Color c = mandelbrotColor(n, maxIter);
                img->setPixel(x, y, toByte(c.r), toByte(c.g), toByte(c.b));
            }
        }
    }

    void main() {
        Image img = Image::new(200, 150);
        // 80 iterations is enough to show the shape.
        renderMandelbrot(&img, 80);
        writePPM("/tmp/coral-mandelbrot.ppm", &img);
        println("wrote /tmp/coral-mandelbrot.ppm");
    }

The iteration is complex multiplication by hand: `(zr + zi i)² = (zr² - zi²) + (2 zr zi) i`, and `+ c` adds the current point's parts. The new real part is computed into `next` before `zr` is overwritten, because the imaginary part still needs the old `zr`; swapping those lines is the classic bug and produces a wrong image rather than a crash. The escape test `zr*zr + zi*zi <= 4.0` runs every iteration, and `n` records how many the point survived. `mandelbrotColor` turns `n` into a color and paints capped points black. The mapping divides by `width - 1` and `height - 1` so the first and last pixels land on the rectangle's edges, guarded for the one-pixel case.

Cost and notes. Cost is image size times average iteration count, O(width × height × maxIter) worst case, though most exterior points escape much sooner and the boundary concentrates the work. A few hundred iterations at a few hundred pixels square takes a fraction of a second; deep zooms need arbitrary precision because `f64` runs out of mantissa long before the picture runs out of detail. Each pixel is independent, the textbook embarrassingly parallel workload, though this chapter stays single-threaded.

Edge cases and variations. Boundary points are neither strictly inside nor outside because iteration must stop; the cap decides, and raising it moves the boundary only slightly, so the black region is stable. Interior points never escape, so their color is constant and all interest is the escape-time rings just outside. A single monotone ramp shows the shape but not the bands; a cyclical palette using `n % period` produces stripes. A zoom is six different numbers for the rectangle. Smooth iteration uses `n - log(log|z|) / log 2` to remove banding. Julia sets fix `c` and iterate each point as the starting `z`, so the same loop with `c` and `z₀` exchanged draws a different universe.
