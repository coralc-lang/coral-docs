Appendix D, Prelude, Core, and Platform

This appendix is one volume of the Coral Standard Library API reference; for a guided tour of how these modules fit together, see Appendix A, A Tour of the Standard Library. Its companion volumes are Appendices D through K, each covering a group of the library.

This document catalogues every pub export of the Coral standard library and the core/platform support modules it builds on. It is generated from the actual source tree under lib/ and reflects the current dialect.

  • Sources of truth: lib/core/**, lib/platform/**, and the per-target lib/std/x86_64/<target>/** trees. The primary target documented here is x86_64/linux; lib/std/x86_64/windows/** mirrors it with platform differences (noted where relevant).
  • Top-level manifest: lib/std/lib.crl re-exports the submodules; the per-target manifest is lib/std/x86_64/linux/lib.crl.
  • Signature syntax: RetType name(params). Tuple types are spelled struct(T, T) (never (T, T)). Generics are <T>, <T, U>, <T, usize N>, or <comptime N>; there are no generic bounds and no trait composition.
  • Visibility: the dialect has no per-method pub; every member declared in a pub struct/pub variant/pub enum/pub extend is public. Members named with a leading _ are internal helpers, listed here for completeness but not intended for direct use.
  • @drop: @drop is an inbuilt trait. Types that own heap memory provide an extend <T> : @drop { void drop() } block wiring their dispose() into the language's automatic cleanup.

core

1. core::cchar, C character type

coral
pub distinct cchar = flag (arch)
{
    x86_64 => { i8 },
    else   => { u8 }
}

A cchar is a char-like C character whose signedness depends on the target architecture (signed i8 on x86_64, unsigned u8 elsewhere).
